## 二、修复方案

### Phase 1：框架层 — 撮合/估值口径对齐 PTrade

#### P1-1：`_ADJ_OHLC_SQL` 改为原始 OHLC

**文件**：`quantstudio/backtest/providers/duckdb_data_access.py` 行 61-65

**当前**（方案A，前复权撮合）：
```python
_ADJ_OHLC_SQL = """
               COALESCE(open_front, open)   AS open,
               COALESCE(high_front, high)   AS high,
               COALESCE(low_front, low)     AS low,
               COALESCE(close_front, close) AS close,"""
```

**改为**（raw 撮合，对齐 PTrade）：
```python
_ADJ_OHLC_SQL = """
               open, high, low, close,"""
```

**证据**：PTrade 撮合/估值用 raw_close（11 笔成交 + last_price 实证）。
**影响链**：`query_daily_snapshot` → `curr_data['close']` 变为 raw → 下游全部自动切换：
- `prices`（行 534，估值）→ raw close ✅
- `_build_match_prices`（行 953，撮合）→ raw close ✅
- `t1_open_prices`（行 560，next_open 撮合）→ raw open ✅
- `BarData.close/price`（ptrade_api.py 行 173-174）→ raw close ✅

**不变项**：`get_bars(fq='pre')`（信号路径，行 389-392 独立查 `*_front` 列）完全不受影响。

#### P1-2：`_ADJ_PRECLOSE_SQL` 改为原始 preClose

**文件**：同上，行 66-69

**当前**（方案A，preClose 缩放）：
```python
_ADJ_PRECLOSE_SQL = """
               CASE WHEN close > 0 AND close_front IS NOT NULL AND close_front > 0
                    THEN preClose * (close_front / close)
                    ELSE preClose END AS preClose,"""
```

**改为**：
```python
_ADJ_PRECLOSE_SQL = """
               preClose,"""
```

**理由**：撮合/估值改 raw 后，preClose 也应用原始值，保持口径一致。

#### P1-3：`_get_pct_chg` 改用 pctChg 列

**文件**：`quantstudio/backtest/backtest_engine.py` 行 882-905

**问题**：当前 `_get_pct_chg` 用 `(close - preClose) / preClose` 计算。改为 raw 后，除权日 raw close/preClose 会产生虚假 -50% 涨跌幅（如 159995 07-07），导致涨跌停误判。

**改为**：优先使用快照中已有的 `pctChg` 列（数据管线预计算的真实涨跌幅，已复权校正）：
```python
# 优先用预计算的 pctChg（除权日正确），回退才用 close/preClose
pct_chg = row.get('pctChg')
if pct_chg is None or pd.isna(pct_chg):
    pre = row.get('preClose', 0)
    pct_chg = (close - pre) / pre * 100 if pre else 0.0
```

**证据**：etf_daily/stock_daily 表的 pctChg 列是数据管线按复权因子校正后的真实涨跌幅。快照 SQL（行 310）已返回此列。

#### ~~P1-4：已删除~~

> 原方案提议将本地 get_history 默认 fq 改为 None（对齐 PTrade 默认不复权）。
> **用户决策（2026-08-14）：删除此项。** 理由：不复权会导致除权日信号失真（均线/动量被扭曲），
> 前复权是量化回测的标准默认口径。保持本地默认 fq='pre'（前复权信号正确），
> 通过 P3-1 source_import 注入 fq='pre' 确保 PTrade 端信号一致。
> **PTrade 平台默认全链路不复权（实证确认），但策略通过 source_import 转换时
> 注入 fq='pre' 获得前复权信号——这是"我们替策略确保信号正确"，而非 PTrade 原生行为。**

### Phase 3：转换层（source_import → PTrade）

#### P3-1：对无 fq 的 get_history 注入 fq='pre'

**文件**：`quantstudio/strategy_compiler/source_import.py`

**问题**：PTrade get_history 默认 fq = 不复权（实证确认）。策略源码不指定 fq 时：
- 本地引擎默认 fq='pre' → 前复权（信号正确）
- PTrade 默认不复权 → raw（信号除权失真）
- **两端不一致**

**改为**：source_import 在 AST 重写时，对没有 fq 参数的 get_history/get_price 调用，自动注入 `fq='pre'`：

```python
# 仅对没有 fq 关键字的调用注入（不覆盖策略显式指定的 fq=None）
has_fq = any(kw.arg == 'fq' for kw in node.keywords)
if not has_fq:
    node.keywords.append(ast.keyword(arg='fq', value=ast.Constant(value='pre')))
```

**覆盖**：get_history + get_price 所有调用点（签名 A 和 B 均覆盖）。

**效果**：
- 策略不指定 fq → 两端都前复权（信号正确 + 一致）✅
- 策略写 fq='pre' → 两端都前复权 ✅
- 策略写 fq=None → 两端都 raw（策略故意要 raw，不覆盖）✅

**用户决策依据（2026-08-14）**：不复权信号在除权日失真是明摆的问题，前复权是必须的。
既然信号计算必须前复权，不如在 skill 生成本地策略时默认 fq='pre'，转换到 PTrade 时
也注入 fq='pre'，确保两端信号一致 + 不给用户埋雷。

#### P3-2：fq='pre' 归一化保持不变

当前 `dypre→pre` 归一化逻辑不变。新增的 P3-1 注入与其协同。
