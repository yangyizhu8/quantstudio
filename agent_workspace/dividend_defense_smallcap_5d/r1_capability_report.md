### 2.2 PIT 语义实测（乙①）

- `div_proc` 全表 54,023 行**全部为"实施"**，无"预案/股东大会通过"等中间状态 → **div_proc 无区分力，只能兜底**。
- `ex_date` 无空值（0 行）；`ann_date` 空 89 行；`ann_date > ex_date` 仅 2 行（异常，可忽略）。

- **结论：以 ex_date <= 决策日 作为"已实施"判据成立且必要**，与客户 ① 的要求一致。
- 决策日 2026-07-30 的 12 个月窗口（ex_date 属于 (2025-07-30, 2026-07-30]）内有税前现金分红的股票 **3,441 只 / 4,556 条记录**；无分红者按 0 处理，被"股息率 > 0"天然剔除（客户 ④）。

## 三、BLOCK 项（MISSING_REUSABLE_API，2 项）

### B1 股息率聚合 —— 无可用 API
- `get_stock_exrights(security, date)` 是**单日查询**（内部 SQL：WHERE code = ? AND ex_date = ?，duckdb_data_access.py:1262-1266），无法聚合近 12 个月。
- 全市场 x 约 250 交易日逐日调用不可行。
- 归入已获批准的 A1 框架工作流（乙项）。

### B2 换手率历史序列 —— 无可用 API（本轮新发现，需裁定）
两条路都被实测封死：

1. **`get_history` 不支持换手率**：`field='turnover_rate'` / `'turnover_ratio'` 返回默认 OHLCV 帧且 `turn` 列全 NaN；`field='turn'` 返回单列全 NaN。根因：底层源列 `stock_daily.turn` 非空率仅 9,997 / 9,714,918 = **0.1%**；换手率唯一完整来源是 `stock_daily_valuation.turnover_rate`（9,652,068 / 9,652,068 = **100%**），不在 `stock_daily` 中。
2. **`get_fundamentals(table='valuation', date=D)` 的 date 在回测运行期失效**：`DuckDBMarketDataProvider.get_valuation`（duckdb_provider.py:183-189）第一句即 `self._data.get_fundamentals_from_preload(codes, fields)`，命中预加载快照即直接返回**决策日估值**，`date` 被短路。实测：对 2026-07-23 / 24 / 27 / 28 / 29 五个不同日期分别查询，turnover_ratio 返回完全相同值（600519 = 0.4986，000060 = 2.2147），证实 date 无效。

**影响**：二次筛选「近 20 日换手率波动率升序取最小 5 只」在现有可复用 API 下**无法计算**，属 R1 BLOCK，不可用近似口径替代（skill 绝对规则 15）。

**建议处置**：并入同一条 A1 框架工作流，作为第二个可复用能力交付；契约草案：
```
换手率序列 = 最近 N 个交易日 stock_daily_valuation.turnover_rate（PIT：time <= 决策日，逐日取值，不做前向填充）
N 默认 20；数据缺失日按缺失处理，缺失数 > 阈值 则该标的不参与二次筛选排序（由设计层钉死阈值）
```
同时须修复 `get_fundamentals(table='valuation', date=...)` 的 date 短路行为（或明确其"忽略 date"语义并另立 API）——注意该行为属**框架行为变更**，不得混入性能优化，须独立立项审计。
