# Quickstart: 常驻采集与回测共存 — 端到端验证指南

**Date**: 2026-10-27 | **Spec**: [./spec.md](./spec.md) | **Plan**: [./plan.md](./plan.md)

本指南用于**验收**，不是使用手册。每条场景给出前置、操作、预期与证据落点。全部通过才满足 spec 的 SC-001～SC-010。

## 前置

1. 项目根：`D:\miniQMT策略实盘\QuantStudio`
2. 主库存在且可读：`data/quantstudio.db`（DuckDB 1.4.x）
3. 测试环境：`python -m pytest tests/ -q` 可跑
4. 一个可跑通的回测策略（用于哈希对比），建议固定参数：单策略、固定区间（≥1 年）、固定初始资金
5. 证据目录：`docs/evidence/backtest-coexistence-<日期>/`

## 场景 A · 基线不变（回归，对应纯增益审计）

- **前置**：采集未开启。
- **操作**：发起一次回测（GUI 与 CLI 各一次）。
- **预期**：行为、耗时量级、产物与改动前一致；无额外等待提示。
- **证据**：改动前后产物哈希对比（应一致）。

## 场景 B · 采集空闲时直接回测（SC-001 主体）

- **前置**：常驻采集开启，且当前不在采集轮内（轮间间隙）。
- **操作**：直接发起回测。
- **预期**：
  - 无需任何手动停采集动作；回测正常完成；
  - `data/backtest_window.request` 在回测期间存在、结束后消失；
  - 采集状态显示"因回测让路暂停"，回测结束后自动恢复推进（≤1 个采集周期，SC-009）。
- **证据**：请求件生命周期时间戳、run_state 留痕（`skip_reason=backtest_window`）、采集恢复时间。

## 场景 C · 撞上在跑的采集轮（SC-006 / SC-010）

- **前置**：构造一个耗时明显 > 30s 的采集任务（或临时调小阈值到 5s 以便复现）。
- **操作**：在采集轮运行中发起回测。
- **预期**：
  - 1 秒内出现等待读数「已等待 X 秒 · 等待采集轮收尾」，读数持续递增；
  - 超过阈值后阶段变为「已请求中断当前任务」；
  - 该轮在任务/单元边界中断，`run_state` 写 `interrupted=true, yield_reason=backtest_yield`，**水位未推进**；
  - 回测在「阈值 + 单单元耗时」内开始（记录实测值）。
- **证据**：等待时间线截图/日志、run_state 快照、水位前后对比。

## 场景 D · 等待中取消（SC-007）

- **前置**：同场景 C（确保处于等待态）。
- **操作**：在等待态点击取消。
- **预期**：回测不开始、无结果目录产出；采集继续正常推进；界面明确显示"已取消"。
- **证据**：界面状态、采集下一轮正常执行的 run_state。

## 场景 E · 失败/崩溃后自动恢复（SC-002 核心）

分四个子场景，每个至少 3 次：

| 子场景 | 操作 | 预期 |
|---|---|---|
| E1 回测成功 | 正常跑完 | 采集自动恢复 |
| E2 回测失败 | 构造异常策略（如取数必失败） | 采集自动恢复 |
| E3 用户取消 | 运行中取消 | 采集自动恢复 |
| E4 强杀回测进程 | 任务管理器 / `taskkill` 杀 GUI 或 CLI 进程 | 心跳停止 → TTL（120s）后 daemon 自行恢复采集，并写 `yield_reason=stale_window_cleared` |

- **证据**：每次的 run_state 时间线 + 采集恢复时间；E4 需记录 TTL 到期到恢复的实际秒数。

## 场景 F · 空数据防线（SC-003）

| 子场景 | 操作 | 预期 |
|---|---|---|
| F1 启动前不可用 | 用外部进程锁住主库后发起回测 | 显式拒绝 + 原因 + 建议动作；**不产出结果目录** |
| F2 运行中失去访问 | 回测中途外部抢占库 | 回测显式失败；不产出"成功但空"的结果 |
| F3 合法零交易对照 | 选一个区间内不满足交易条件的策略 | 回测**成功**，结果含取数成功证据，不被判为空数据失败 |

- **证据**：错误文本原文、结果目录是否存在、F3 的取数证据字段。

## 场景 G · 结果逐位一致（SC-004）

- **操作**：同一策略 + 同一参数，分别执行：
  1. 手动停采集 → 回测 → 启采集；
  2. 采集开启 → 直接回测（共存窗）。
- **基线有效性的三项确认**（缺一即基线无效）：①界面显示采集已停止且 `get_daemon_status()` 为 stopped；②`collector_run.lock` 可被立即获取；③无 daemon 进程存活（`is_daemon_running()` 为假）。
- **预期**：两次产物（净值、交易记录、指标）**哈希一致，零容差**。
- **证据**：两目录逐文件哈希对比表 + 基线三项确认的截图/日志。

## 场景 H · 双端对等（SC-008）

- **操作**：同一参数分别从 CLI 与 GUI 发起（均无采集占用）。
- **预期**：产物哈希一致；等待读数阶段枚举一致。
- **证据**：哈希对比 + 两端输出片段。

## 场景 I · 队列上限（FR-014）

- **操作**：快速连点发起 4 次回测。
- **预期**：前 3 个排队/执行；第 4 个被拒绝并提示当前队列状态；无静默丢弃。
- **证据**：界面提示与 run_state 记录。

## 场景 J · 采集数据完整性（SC-011 / FR-018）

- **前置**：记录一份「无回测干扰」的采集产物基线（同一交易日、同一任务集合跑完后的表快照哈希）。
- **操作**：分别构造两种让路各至少 1 次——①任务边界让路；②任务内单元边界让路（超阈值）。
- **预期**：让路轮次水位未推进；重跑完成后，采集产出的数据与基线**哈希一致（零容差）**；`run_state` 如实标记让路轮次。
- **证据**：基线哈希、让路轮次 run_state、重跑后哈希对比表。

## 场景 K · 合窗集成验证（T018 / T023 / T028 / T033 一次跑完）

> 口径（2026-10-27）：**回测前停采集 → 回测 → 采集保持停止 → 用户手动启动**。

### 一条龙命令

```powershell
# 0) 前置：记录采集未运行时的基线（哈希），供 SC-004 对比
#    （可选，若已有基线可跳过）

# 1) 启动常驻采集（GUI 点「开启」，或命令行按项目既有方式启动），确认在跑
#    然后立刻发起回测——**不要手动停采集**：
python -m quantstudio.backtest.run_ptrade_strategy <策略.py> 2026-01-01 2026-06-30 2> coexist.log

# 2) 观察 stderr（等待读数）：
Get-Content coexist.log -Wait

# 3) 回测结束后核对：
Get-ChildItem data\daemon_stop.request -ErrorAction SilentlyContinue   # 应为空（已被 daemon 消费）
Get-Content data\backtest_stop.flag                                    # 应存在：reason=backtest
Get-Process | Where-Object { $_.ProcessName -like '*python*' }          # 确认 daemon 进程已退出

# 4) 等 ≥1 个采集周期（5 分钟），确认采集**没有**自行启动（SC-002）

# 5) 手动启动采集（GUI 点「开启」），确认恢复推进；flag 在下次回测启动时清除
```

### 记录模板（填完即证据）

| 项 | 读数 | 证据 |
|---|---|---|
| 回测启动时刻 | | 日志 |
| 采集停止耗时（从发起回测到进程退出） | 秒 | `coexist.log` 里 `[coexist]` 最后一行 + 进程退出时刻 |
| 等待阶段是否升级（任务边界 → 单元边界） | 是/否 | `coexist.log` 阶段文案 |
| 回测结束时刻 | | 日志 |
| 采集停止时长 ÷ 回测时长（SC-005） | 比值 | 上两行相除 |
| 回测后是否自动启动采集（SC-002） | 必须为「否」 | 5 分钟后进程列表 |
| `backtest_stop.flag` | 存在 / reason | 文件内容 |
| GUI 按钮状态（若用 GUI） | 未开启 / 文案 | 截图 |
| 重启 GUI 后状态仍为「已停止」 | 是/否 | 截图（SC-009） |
| 与「手动停采集后同参回测」产物哈希（SC-004） | 一致 / 不一致 | 逐文件哈希表 |

### 判定

- 任一「否」→ 该 SC 未通过，回 fix.md 记录并修；
- 全部符合 → T018/T023/T033 可勾，T028 另需 F1/F2/F3 三态（见场景 F）。

## 汇总判定

| 指标 | 目标 | 对应场景 |
|---|---|---|
| 免手动停采集成功率 | 100%（20 次） | B |
| 自动恢复率 | 100%（≥12 次：E1–E4 各 3） | E |
| 空数据静默跑完 | 0 次（≥10 次验证） | F |
| 与手动停采集同参回测 | 哈希一致 | G |
| 采集中断 ÷ 回测时长 | 0.9–1.1 | B/C |
| 等待读数 1s 内出现 | 100% | C |
| 取消成功率 | 100% | D |
| 双端产物一致 | 哈希一致 | H |
| 采集数据重跑后一致 | 哈希一致（零容差） | J |
| 队列超限被拒绝 | 100% 显式拒绝 | I |

全部达标方可判定"Converged → 终态"。
