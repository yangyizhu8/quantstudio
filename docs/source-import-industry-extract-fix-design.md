## 一、背景与动机

### 1.1 缺陷

`quantstudio/strategy_compiler/source_import.py:3262-3279` 的
`_extract_industry_codes` 用于**从策略源码提取「行业剔除码集」**，再经
`_QS_INDUSTRY_EXT` 模板的 `__QS_INDUSTRY_CODES__` 占位符**烘焙进 PTrade 转换产物**
（渲染见 `:3003-3011`，调用点 `:4786`）。

其实现为 **`ast.walk` 遍历全文件全部 `ast.Constant`，凡「纯 6 位数字字符串」即收**：

```python
for node in ast.walk(tree):
    if isinstance(node, ast.Constant) and isinstance(node.value, str):
        v = node.value.strip()
        if len(v) == 6 and v.isdigit() and v not in codes:
            codes.append(v)
```

**该判据无法区分「行业码」与「业务哨兵 / 无关代码表」** ⇒ 误提取。

### 1.2 实测证据（四策略直测，本机执行）

| 策略源码 | 实测提取结果 | 判定 |
|---|---|---|
| `F-Score选股RSRS择时.py` | `('801780','801790','480000','490000')` | ✅ **恰好正确——但有运气成分**（该源码内恰好只有这 4 个 6 位数字） |
| `断板反包策略.py` | **≈200 个北交所代码** | ✗✗ **`_QS_BSE_LEGACY`（n=248 的 BSE 映射快照，另一语义）被整表收走** |
| `连板梯队龙头打板套利策略.py` | `('999999',)` | ✗ **业务哨兵被收走**（源码 L889 的 fallback 值） |
| `双均线策略.py` | `()` | ✓ 源码无 6 位数字 |

**推论**：**该缺陷对「源码内含其他 6 位数字集合」的策略必然发作**，且**静默**（下游有
fail-open 兜底，不报错、不崩溃）。

### 1.3 与此前初判的差异（自证伪记录）

初判为「docstring 的 `'801780'` 被误提取」——**实测证伪**：docstring 作为**整体**
`ast.Constant`，其 `len(value) != 6` ⇒ **不命中**。真实机理是**更朴素也更严重**的
「全文件 6 位数字扫描」，其后果不止哨兵，还包括**整表收走无关集合**。

### 1.4 影响面（要求③，随方案披露）

| 产物 | 现况 | 判定 |
|---|---|---|
| `F-Score选股RSRS择时` × **12 个版本产物** | `('801780','801790','480000','490000')` | **正确**（侥幸）；修复后应**保持不变** ⇒ 可作**等价性基准** |
| `连板梯队龙头打板套利策略_ptrade.py` | `()` | 与实测 `('999999',)` **不一致** ⇒ **该产物生成于 2026-09-04 18:06**，早于当前提取器行为，**属旧版产物**（路径差异并入本方案 §2 影响面核查） |
| `断板反包策略.py` | 尚未转换 | **若按其现状重转，将烘焙 200 个码** ⇒ PTrade 端逐个查行业 ⇒ **池查询灾难** |

## 二、范围与边界

### 2.1 改动范围（框架层，单函数）

| 项 | 内容 |
|---|---|
| **主改** | `quantstudio/strategy_compiler/source_import.py` 的 **`_extract_industry_codes`** 函数体 |
| **不改** | `_QS_INDUSTRY_EXT` / `_QS_FUNDAMENTALS_EXT` **模板字符串内容**（**不得触碰**，见 §2.2） |
| **不改** | 渲染逻辑 `:3003-3011`、告警分支、`_QS_INDUSTRY_CODES = __QS_INDUSTRY_CODES__` 占位机制 |
| **零改动** | **任何策略源码**（铁律：策略源码零改动）——含 `连板梯队...` 的 `_QS_INDUSTRY_CODES = ()` |

### 2.2 矩阵哈希纪律（要求②）

`scripts/check_fund_matrix.py:31-38` 的 `wrapper_hash()` 比对范围**明确包含
`_QS_INDUSTRY_EXT`**：

```python
for name in ("_QS_FUNDAMENTALS_EXT", "_QS_INDUSTRY_EXT"):
    m = re.search(name + r" = '''.*?'''", src, re.S)
```

⇒ **本方案只在函数体内改逻辑、不触碰模板字符串，预期哈希不变**。
**但按纪律执行**：实施后先跑 `python scripts/check_fund_matrix.py --check`；
**若哈希变** ⇒ 同 commit 内附 `--check --reverify` 产出的 yaml/md 哈希更新
（禁止后置单拆）。

### 2.3 兼容边界

- 函数签名与返回类型不变（`(source: str) -> tuple[str, ...]`）；
- **空集语义不变**：仍返回 `()`，仍触发转换器告警 + 下游 fail-open（RD-3）；
- **渲染产物格式不变**：仍为 tuple 字面量（模板内 `[0]` 下标、`','.join` 保序依赖此形态）。

## 三、任务拆解

### T1 · 提取判据重写（锚定专用声明位，要求①）

**新判据——两路锚定 + 三类排除**：

| 路 | 锚定对象 | 说明 |
|---|---|---|
| **A. 结构化判定位** | `Compare` 节点中 `op=In`、右侧为**字面量元组/集合**的 `ast.Constant` 元素 | 覆盖 `F-Score` 的 `ic in ('801780', ...)` 形态 |
| **B. 显式命名常量** | `Assign` 目标名匹配 `INDUSTRY_EXCLUDE*` / `_QS_INDUSTRY_CODES` 的**字面量元组/集合** | 覆盖显式声明的行业清单 |

| 排除 | 对象 | 手段 |
|---|---|---|
| **E1** | 函数/模块 docstring 与注释 | **不再遍历全量 Constant** ⇒ 结构上天然排除；仅从上述两路取 |
| **E2** | 哨兵与魔法值 | 白名单常量名排除（`'999999'` 类哨兵）+ 可配置黑名单 |
| **E3** | 已知无关集合 | 常量名黑名单：`_QS_BSE_LEGACY` / `BSE_LEGACY_TO_920` / `*_BSE_*` 等（**注释说明理由**） |

**若两路均无命中** ⇒ 返回 `()`（**保持既有告警 + fail-open 语义**），
**不回落旧行为**（回落即等于保留缺陷）。
