# 一、问题定义

`match_price_mode=close` 下引擎涨停拦截基准 = **T 日收盘价**（B2′ 定谳 `7435430`，6 笔实测：T日 close=high=涨停 ⇒ 提交即拒）。首板高开接力策略天然要买可能涨停的票 ⇒ 该拦截口径直接决定可成交性，且与聚宽侧存在平台撮合语义差异（聚宽 16 笔仅聚宽买入的相当部分可由此解释）。当前口径硬编码、不可配置、无文档 ⇒ 属隐含语义。

# 二、候选形态

| 项 | 内容 |
| --- | --- |
| 能力 | 涨停拦截基准可配置：`limit_up_basis ∈ {t_close(默认，现状), bar(当日执行bar)}` |
| 入口 | 策略侧显式 opt-in；**默认 t_close 不变** |
| 可观测 | 拦截时审计行输出基准与取值（`QS_ORDER_RESULT` 通道可直接带出） |

# 三、判型主张（候呈批轮裁）

- **新增能力型**（单列）：默认行为零改变；开启后属「数据修正型效果」（结果按所选口径变化，须显式声明影响面）。
- 不与 RC-001a 合批：RC-001a 是 CLI 防护（面小），本案在引擎撮合层。
