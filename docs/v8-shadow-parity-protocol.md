# V8 专项协议：影子库等价 · 四步游标续传 · 双判据（一页合订）

- **版本**：v1（2026-09-13，dev 会话起草；待对拍会签 → 总调度入册）
- **适用**：9/16 起执行的 V8 影子库真拉专项；与 A1-A4 等价性验收共用本判据
- **一句话**：本协议不定义"做什么优化"，只定义**什么样的证据才算数**；判据的适用边界写在判据旁边

## 一、影子库协议

1. **落点**：`data/staging_shadow_<YYYYMMDD>/quantstudio.db`（由 `.gitignore` 的 `data/staging_*/` 覆盖，禁止落在未忽略路径——35GB 级文件误入库不可逆）。
2. **复制**：字节级读，**不必等写窗**（读者并存无害）；`robocopy /J`（无缓冲 I/O）。基准：35.3GB / 45.4s。
3. **写窗门禁 E-3**：判据 = **RW-open 试开成功 → 立即关闭**。
   - **只读探测通过 ≠ 写窗可用**（DuckDB 允许多读者共存，但任一读者即挡写者；实测：14:33 只读过、14:34 写被拒）；
   - **"GUI 已关"亦不构成判据**（回测/探针等任何读者同权）。
4. **完整性抽验（双层，缺一不可）**：
   - 第一层：字节数一致 + 表集合一致 + 代表表**行数**一致；
   - 第二层：关键列**确定性切片**哈希——对 `ORDER BY <时间列> LIMIT N` 的子查询求 `SUM(hash(...))`；**禁用随机采样**（采样不可复现，无法作为等价证据）。
5. **列名实测**：时间列以 `DESCRIBE` 实测为准，**禁止假设列名**（实测同库内 `time`/`trade_date`/`timestamp`/`scan_date` 各不相同；写死 `time` 会以 BinderException 静默丢失整张表的校验）。
6. **镜像保真**：补建水位等变更需同步进影子时，须复制主库**实际落库行**（含 `source_generation`/`cutover_id` 审计列），**禁止**用 dry-run 候选值重算——否则影子审计列与生产态不一致。

## 二、四步游标续传演练协议

**四步（顺序不可交换）**：①影子内定水位 → ②停止跑（写游标）→ ③**中间零水位动作** → ④续跑（全程窗口起点不变）。

- **判废分支 = 独立对照用例**：在第 ③ 步**故意插入一次水位推进**，验证游标按设计判废 → 全窗执行。此用例与"续传成功"用例**分离**，两条判据**不得互相吃掉**（生产实证：正是"停止后、续跑前插入水位补建"把游标判废了；若两判据混跑，"续传成功"会假阴性）。
- **空水位场景单独构造**：复制品已含水印行，**不会自然出现**"无水印 → 全窗"路径，须显式造场景。
- **判据**：续传运行的起点 = 游标 `last_completed` 的次日（口径与 `ResidentCollector._bump_date` 一致：毫秒时间戳 / `YYYY-MM-DD` / `YYYYMMDD` 三形态；**毫秒形态不得被静默忽略**），且日志中可见"确已跳过"的行证据。

## 三、双判据：一致性 / 真值性

**两判据分立成文，各附证据来源；合并解读即失效。**

### 3.1 一致性判据（"等同云端"）

- **命题**：影子与云端（修复前后各跑）结果一致。
- **证据来源**：对比脚本输出 **+ 双方各自的行数/哈希指纹**（不得只记"相等"这一结论——没有双方指纹，"相等"不可复核）。
- **已知污染项**：**云端重复偏置**。

### 3.2 真值性判据（不依赖云端）

- **命题**：表内容满足自身应有约束。
- **证据来源**：表内自洽约束校验输出——PK 唯一性（`COUNT(*)` vs `COUNT(DISTINCT pk)`）、时间列覆盖/单调性、必要时与**独立源**交叉核对。

### 3.3 反向归因防护（随判据并列，不得移入正文）

> 一致性差异中的一部分**来自云端重复偏置**；**不得**据此反推为"修复引入的偏差"。

**理由**：一致性判据只能证明"未引入**新**偏差"，不能证明"修复前云表为真值"。缺此句，两判据会在报告阶段被合并解读——即回到"用一致性给旧云表背书真值"的原错误。
