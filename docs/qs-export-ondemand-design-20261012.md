## §1 问题定义

周期收尾才导出（`run_fm_export` 挂在轮次 finally）⇒ **周期不结束就不出件**。实测：`data/fm_export/` 末次产出 **10-08 07:43**（as_of 09-29），连日周期未收尾 ⇒ 工件陈旧 4 天，而**陈旧对消费方静默**。本方案提供**按需**导出：不依赖周期收尾、不依赖空闲窗、不需停 daemon。

## §2 改动范围（纯新增，既有文件零改动）

| 项 | 规格 |
|---|---|
| 新模块 | `quantstudio/pipeline/qs_export.py`——复用 fm_export 的命名/轮转/状态件原语（**不 import 其业务逻辑**，只对齐规约） |
| 请求件 | `data/qs_export_request.json`：`{request_id, tables:[...], window:{col,start,end}, columns:"*"|[...], format:"csv\|parquet", limit, token}` |
| 响应件 | `data/qs_export_status.json`：`{request_id, state:accepted\|running\|done\|failed, artifacts:[...], rows, error, at}` |
| 触发 | **周期内消费**：请求件在 daemon 侧**已有 writer/shared_conn 时**被消费（**不新增连接、不触锁**）；每轮询周期检查一次 |
| 窗口谓词 | `WHERE <col> BETWEEN <start> AND <end>`（`time` 为 BIGINT ms，按 ms 归一；`trade_date` 走 ISO 转换——P0 教训） |
| 格式 | **CSV**（新增）+ parquet（复用 pyarrow） |
| 轮转清理 | **复用同一命名函数生成清理清单**（KB 采纳点）；保留 N（默认 10） |
| 失败 | 不覆盖旧件 + status=failed + ERROR（禁静默） |

## §3 影响面

| 面 | 评估 |
|---|---|
| 写路径 | **零改动**（只读查询） |
| 周期行为 | **零变化**——导出发生在既有 writer 可用时，不加锁、不改水位、不改任务序；不新增连接 |
| 性能 | 与 applying 争 CPU ⇒ **限幅**：`limit` 上限 + 单次导出超时（默认 120s）+ 串行（同刻仅一件在跑） |
| 依赖 | 零新增（csv/pyarrow 均在） |
| 判型 | **纯增益·新增导出能力**（非行为漂移） |

## §4 验收标准

1. **导出件等价复算**：同请求下（表/窗口/列/格式）用独立只读连接复核行数与列值 —— **逐值一致**；
2. **周期行为零变化**：导出前后 `run_state`（success/failed/committed 等）与 applying 心跳**逐项不变**；daemon 日志无新增 WARNING/ERROR 类别；
3. 请求→状态→工件三段可追溯（`request_id` 贯穿）；`token` 不匹配则拒绝并留痕（照 stop.request 语义）；
4. 失败路径：构造非法窗口/超限 ⇒ status=failed + 旧件保留 + ERROR。

## §5 回退条件

单文件新模块 + 请求件；回退＝**不再投请求件**（零影响）或移除模块（既有路径未引用）。回退点：实施前按四步配方建快照（`git add -A` → `create -m` → `store` → `reset`）。

## §6 待审选项（请裁）

1. **触发位置**：仅「周期内（有 writer 时）」消费（**推荐**：不新增连接、零锁扰动）vs 允许轻量循环用**短命连接**服务（覆盖"周期外"的空档，但会短暂持锁、破坏"轻量循环无 conn"不变量）；
2. **输出落点**：`data/fm_export/`（与既有件同目录，便于消费方一处取件）vs 独立 `data/qs_export/`（避免与 FM 名义混淆）——**推荐独立目录**；
3. **是否要求双端对等**：请求件是否需 PyQt 侧入口（新增能力型铁律的"双端对等"）——若消费方为其他会话/脚本（非 GUI 用户），**建议豁免并登记依据**。
