# 方案：get_index_stocks 日期归一 —— 契约文档与实现一致性（F3）

> 六步流水线**第 1 步（方案）** ｜ 提出方：策略线会话 ｜ 日期：2026-10-03 ｜ 归属：**框架层**（与「换算价错配」分立两件，各走各的六步）
> 来源：ZCode 独立复核第 2 片 F3（low）｜ 总调度裁定：**立项框架层六步**

## 1. 问题定义

`quantstudio/backtest/ptrade_api.py:767-773` 的 `get_index_stocks` docstring 声明：

```python
def get_index_stocks(self, index_code: str, date=None) -> list:
    """获取指数成分股（对应 Ptrade get_index_stocks），严格 PIT（F3）。

    - 显式 ``date``：**标准化为 YYYY-MM-DD** 后严格 as-of 查询；
    ...
    """
    ...
    if date is not None:
        effective_date = str(date)[:10]        # ← 仅截断，未做任何归一
```

**实测**：`str('20260115')[:10]` = `'20260115'` —— **8 位 ISO 基本格式串原样透传，并未「标准化为 YYYY-MM-DD」**。

### 1.1 但它**当前并不造成错误结果**（这一点必须写清，避免夸大）

本线已实测闭环（ZCode 沙箱拦截、由本线代跑）：

```text
pd.Timestamp('20260115', tz='Asia/Shanghai') = 2026-01-15 00:00:00+08:00
  日期部分 == 2026-01-15 : True
  与横线格式 '2026-01-15' 等值 : True
```

即：8 位串经下游 `time_axis.py:33` 的 pandas 解析**容错兜住**，as-of 语义正确 —— **PIT 有效**。

**因此本件不是「PIT 缺陷」，而是「契约文档与实现不一致」**：

| 项 | 现状 |
| --- | --- |
| docstring 承诺 | 标准化为 `YYYY-MM-DD` |
| 实现实际 | `str(date)[:10]` 截断，形态完全透传 |
| 正确性来源 | **依赖下游解析器的容错**，而非本层的显式契约 |
| 风险性质 | 契约与实现脱节 → 调用方无法据文档判断可传什么形态；换解析器/换存储层即可能静默改变语义 |

## 2. 改动范围 → **已裁定：候选甲**

> **三小裁定原文（verbatim）**：
> 「F3=候选甲（实现补齐归一+不可识别 fail-closed）——docstring 的承诺是正确契约，应修实现而非降级承诺
> （修订 docstring 等于把契约拉低到现状，违反契约精神）」

| 候选 | 做法 | 取舍 | 裁定 |
| --- | --- | --- | --- |
| **甲** | **实现补齐归一**：显式把 `YYYYMMDD` / `YYYY-MM-DD` / `datetime` 等归一为 `YYYY-MM-DD`；无法识别则 raise 或 fail-closed 返空池 + 明确日志 | 让实现兑现文档；调用方获得确定契约；**代价**：新增归一逻辑，需覆盖既有全部调用形态（回归面在 `get_index_stocks` 的全部调用点与测试） | **采纳** |
| 乙 | **修订 docstring**：如实写「按 `str(date)[:10]` 截断，形态透传；解析由下游 time_axis 承担」 | 零行为风险、改动最小；**代价**：把「靠容错」固化为契约，调用方仍需自行保证形态 | **不采纳**（修订 docstring 等于把契约拉低到现状，违反契约精神） |

**裁定采纳甲**：契约应当可依赖，且当前「靠 pandas 容错」的隐式依赖在跨存储层/跨解析器时不稳。
乙案不再作为候选（其把契约拉低到现状，违反契约精神）。**本件据此进入六步排程**（审计序列：换算价② → **F3②** → R33-R37 → 美德② → R1 → P1）。

## 4. 验收标准

| # | 判据 |
| --- | --- |
| V1 | **形态矩阵**：`YYYYMMDD` / `YYYY-MM-DD` / `datetime` / `date` 四种入参，返**同一成分列表**（逐位一致） |
