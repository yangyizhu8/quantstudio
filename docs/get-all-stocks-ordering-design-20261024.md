## 一、问题定义（已实证，非推断）

### 1.1 探针实录（2026-10-24）

同参数（`date=2026-01-05`，`len` 恒为 5,456）连续 5 次 × 2 进程：

| 进程 | 5 次序列哈希 | 唯一数 | 首 10 码 |
| --- | --- | --- | --- |
| A | `c5eca93d` / `263d6db7` / `a244aad7` / `3d177855` / `9d9d989f` | **5** | `001286, 300288, 000795, 300006, 300236 …` |
| B | `2a066f71` / `26f2368c` / `593559b8` / `6a833a4b` / `a72e2dcd` | **5** | `003042, 600793, 000651, 000678, 000901 …` |

⇒ **同一进程内连续 5 次，返回顺序全部不同**（比跨进程不确定更严重）。

### 1.2 根因（代码定位）

```python
# quantstudio/backtest/providers/duckdb_data_access.py:2106  query_all_stocks
SELECT DISTINCT code FROM stock_daily WHERE time = (SELECT MAX(time) ...)
#              ↑ 无 ORDER BY ⇒ DuckDB 并行 hash-distinct，行序不确定
```

调用链：`get_Ashares` → `reference.get_all_stocks`（`duckdb_provider.py:339`）→ `query_all_stocks`（无序）。

### 1.3 下游后果（因果链闭合）

池顺序随机 ⇒ `_board_filtered` 保序 ⇒ `filtered` 随机 ⇒ `first_board` 随机 ⇒ 当日**同日多笔买入的提交顺序**随机 ⇒ `trades.csv` / `round_trips.csv` 行序随机。

**实证**：两次 OFF（均关 P1′ 缓存）+ 同窗口 01-05~02-02 回测，`trades.csv` 仅 2026-01-06 两笔（`600556`/`600587`）顺序互换，其余 6 文件字节级一致 ⇒ **顺序非确定性根因即此处**。

### 3.2 关键结论

1. **无任何消费方依赖「随机顺序」** —— 随机序不可被依赖，故无「既有行为」被破坏 ✓
2. 排序变更后**收益方向**：可复现性提升 ✓（同日多笔顺序确定 ⇒ `trades.csv` 逐位对拍成为可能 ✓）
3. **风险点**：① 依赖顺序的策略其**选股结果可能改变**（因顺序变了 ⇒ 取前 N 的集合变了）⇒ 这正是**确定性带来的首次固定**，须在验收中**如实申报「这些策略的结果将发生一次性变化」**；② tests 断言需复核 ✓

## 四、三型判定

| 审计项 | 判定 | 论证 |
| --- | --- | --- |
| ① 是否影响其他功能 | **影响（受控且收敛）** | 仅影响「依赖 `get_Ashares` 顺序」的消费方；已扫全部 86 处，逐一归类；转换管线零依赖 ✓ |
| ② 是否影响回测性能 | **否** ✓（可能轻微正向） | 追加 `ORDER BY code` 增加一次排序（5,456 行，毫秒级）；且 DuckDB 单次 DISTINCT+ORDER 仍远快于多次调用 |
| ③ 是否影响回测精度 | **影响 → 按「确定性恢复」口径** | 结果从「每次不同」变为「每次相同」⇒ **首次固定**；**不是数值口径变更**（集合完全相同 ✓ 仅序不同） |

**定判：纯恢复型（确定性恢复）** —— 理由：缺陷是「无确定序」，恢复为「确定序」；集合恒等（`set()` 前后一致，可逐位断言 ✓）；**可观察顺序变化属修复目的本身，非副作用**。

⚠ **请②审特别裁定**：此定性是否成立 ✗（严格按铁律，可观察结果变化即非纯性能型 ✓；本项归「纯恢复型」，但「首次固定」会改变依赖顺序的策略结果 ✗ —— 是否接受该一次性变化 ✓）
