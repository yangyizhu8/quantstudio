## §1 问题定义

applying 相位**边际失效率 99.5%**（Δ处理 840 / Δ失败 836），`committed` 冻结于 **6**，
而**逐单元失败原因无任何可读留痕**：`qfq_orch` 在当前日志 WARNING/ERROR 为 **0 行**，
唯一明细在 `quantstudio.db` 的 `qfq_trigger_queue`，而该库被 daemon **独占**（实测只读打开失败）。
⇒ 取证被"无库窗即不可读"卡死；本案**本可用可读辅助库承载**却未落任何逐单元记录。

## §2 改动范围（纯增量）

| 项 | 规格 |
|---|---|
| 落点①（结构化） | 逐单元一行写 **`qfq_aux.db:qfq_deep_audit_item`**（既有表；列：`asset_type/code/status/round_no/attempt_count/last_error/updated_at`） |
| 落点②（可读日志） | 逐单元一行 **INFO/WARNING** 日志（现仅每 ~10min 聚合心跳）——形态照 `code_contract` 的「审计行」约定 |
| 记录字段 | `code / asset_type / trigger_id / 结果状态（committed\|retryable_failed\|dead_letter\|blocked\|skipped）/ last_error 原文（截断）/ attempt_count / cycle_id / 时点` |
| 限幅 | 每单元**一行**（4612 单元/周期 ⇒ 量级可忽略）；`last_error` 截断（如 300 字符）；**同 code 同 cycle 只保留最后一次**（UPSERT） |
| 不改动 | 判定逻辑 / 提交语义 / 水位 / 写路径 / 队列状态机——**只读队列结果并记录** |
| 失败隔离 | 记录自身异常**一律兜住**（不得影响 applying；照 `code_contract` 的"不中断"约定） |
