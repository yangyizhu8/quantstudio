### 1.2 自锁环结构（缺陷态闭环）

```
写入部分成功（数据落库）
      ↓
提交期 write-write conflict ⇒ 整批 FAILED
      ↓
水位不推进（因批次判失败）
      ↓
下一轮 INCREMENTAL 重拉**同一窗口**（水位冻结在旧日）
      ↓
再次与「已部分写入的自身数据」+ 并发写者冲突
      ↓
再 FAILED ⇒ 水位再不动 ⇒ 循环   ← 结构性自锁，永不自愈
```

**关键判据**：`MAX(time)` 前进但水位不动 ⇒ **数据面与水位面已脱钩**（这是自锁环的指纹）。

### 2.2 ②审硬门：S1 失败分类 own-vs-foreign（**V 系硬门**）

> 判据基础 = **M1 生产观测字段**（`conflict_table` / `conflict_scope` / `peers_n` / `cross_process_candidate`）+ M2 作用域观测。

| 型 | 定义 | 判据 | 处置 |
|---|---|---|---|
| **own** | **与自身已写数据的幂等重写冲突**（同表同 batch 作用域；本批写的 key 与库内既有 key 重叠） | `conflict_table` 本表 + `conflict_scope` 含本 batch + 键落在本批写入窗口内 | **可解耦推进**，但**推进前必做行级校验**：窗口内 `COUNT(DISTINCT code)`（或对应粒度）须 = **预期基准 ± 容差**；校验不过 ⇒ **不推进** |
| **foreign** | 他方写者（他任务/他进程）与本报冲突 | scope 不符 / `peers_n>0` / 跨任务 | **不得推进**，走 **S2 让行**（≤120s → defer） |

**硬门性质**：①own 判定后**未做行级校验即推进** = 验收失败；②foreign 型被误判为 own 并推进 = 验收失败。
**容差口径**：以健康基准（`count(distinct code)` 中位数）±5% 为界，与既有巡检口径一致。
