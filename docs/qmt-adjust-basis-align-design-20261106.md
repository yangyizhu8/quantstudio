## 一、问题定义（含对 C2 定谳的**机制精化**）

### 1.1 已确证的事实层

`fc6f942` 定谳：T1=2026-06-01（两侧 d1=20260529）13 只中，**9 只价格超差（价格层分叉 C2）**、3 只全同（SYNTH，无除权）、1 只 NO_LOCAL（001331 本地缺 2 根，已转节点11）。

### 1.2 本轮新增判别：机制**不是**「纯基准日不同」

**判别法**：若仅基准日不同，则同一标的 `P_QMT(t)/P_LOC(t)` 对一切 t 应**恒为常数**。

**实测（`qs_ratio_check.py`，12 只可比）**：

|---|---|---|---|---|---|
| 002577 / 300214 / 600228 | 1.000000 | 1.000000 | 1.000000 | **0** | **恒定**（无除权） |
| 600060 | 0.999157 | 0.993193 | 0.996928 | **5.96e-03** | **跳变** |
| 600971 | 1.000000 | 1.000081 | 0.995474 | 4.61e-03 | 跳变 |
| 301557 | 1.000000 | 0.998088 | 0.995776 | 4.22e-03 | 跳变 |
| 301093 | 0.999977 | 0.999753 | 0.997045 | 2.93e-03 | 跳变 |
| 002568 | 1.001215 | 1.000284 | 1.003041 | 2.76e-03 | 跳变 |
| 300121 | 1.000000 | 1.000255 | 0.998604 | 1.65e-03 | 跳变 |
| 603859 | 0.999619 | 0.999733 | 0.998701 | 1.03e-03 | 跳变 |
| 301439 | 1.000000 | 1.000085 | 0.999195 | 8.90e-04 | 跳变 |

**结果：跳变 9 / 恒定 3**，且**恒定的 3 只恰为零除权标的**（与价格全同组完全重合）。

### 1.3 机制定谳（**修正 1.1 的措辞**）

> **不是「前复权基期不同」，而是「前复权口径不同源」**——两侧采用的**除权事件集 / 累积因子序列**不一致：
> - 无除权标的：两侧因子恒 1 ⇒ 逐位相同（3/3 恒定，互证）
> - 有除权标的：因子序列在**除权日跳变**，且两侧跳变点/幅度不同 ⇒ 比率不恒定
> - 方向可不同（>1 有 1 只、<1 有 3 只）⇒ 排除「单向基准平移」这种最简解释

**QD-2026-0023 的 `root_cause` 措辞已同步精化**（本轮同 commit 修正，避免知识库留错误机制名）。

### 1.4 为什么「甲案」在此机制下依然成立

甲案的本质是「**让 QMT 侧的价格序列与本地逐位一致**」。既然偏差来自因子序列不同源，那么**用本地因子序列去换算**即可根治——无论差异形态是基期平移还是事件集差异，都被同一手段覆盖。**这是甲案优于「调 QMT dividend_type 参数」的根本原因**：调参数只能改基期，改不了事件集。

## 二、修复方案（甲案实现）

### 2.1 核心难点与破法

**难点**：QMT 产物运行在 QMT 客户端内，**无法访问本地 DuckDB**；因此不可能在产物里直接读 `qfq_aux.db`。

**破法（沿用 D-30 快照先例）**：把「本地累积复权因子」**预计算成紧凑快照文件**，随产物部署；QMT 侧取**不复权原始价**，再按快照换算。

> D-30 先例已证明该范式在本项目可行：`_QS_QMT_INSTR_SNAP_PATH` 读本地 JSON 快照，三态缓存（loaded/disabled/broken/absent），且已确立「**文件存在即消费；实盘运行机不部署快照**」纪律，本方案**完全沿用**。

### 2.2 快照设计

**文件**：`output/qmt_snapshot/qfq_factor_snapshot.json`

**结构**（只存**跳变点**，不存逐日因子 ⇒ 体积可控）：

```json
{
  "enabled": true,
  "base": "20261106",
  "generated_at": "2026-11-06T19:xx+08:00",
  "source": "qfq_aux.db",
  "records": {
    "600971": [[20250612, 0.995474], [20260120, 0.998081]],
    "002568": [[20250703, 1.003041], [20251215, 1.001215]]
  }
}
```

- 键＝**6 位 code**（与 wrapper 内部归一后的 code 一致）
- 值＝`[[除权日 YYYYMMDD, 累积因子], ...]`，**升序**
- `base`＝本地因子表的基准日（**待实施前探测确认**，见 §九 第 1 步）
- 只导出**窗口内被 universe 覆盖且因子 != 1** 的标的 ⇒ 预估体积 < 1 MB

**换算公式**（QMT 侧）：

```
P_adj(t) = P_raw(t) × F(t) / F(base)
```
其中 `F(t)` = 快照中 **≤ t 的最后一个跳变因子**（无跳变则 1.0）；`P_raw` 由 `dividend_type='none'` 取。

### 2.3 wrapper 侧改动（框架层）

在 `_QS_QMT_HISTORY_EXT` 的取数路径：

1. `div` 选择：**有快照 ⇒ `'none'`（取原始价，自行换算）；无快照 ⇒ 维持 `'front'`（行为与今日一致）**
2. 取数后对 `open/high/low/close/preClose` 逐列乘 `F(t)/F(base)`
3. **成交量不换算**（QMT 侧已 ×100 折股，且复权不涉量）

**三态（仿 D-30，含 QD-2026-0022 的 fail-loud 纪律）**：

| 态 | 条件 | 行为 | 输出 |
|---|---|---|---|
| `loaded` | 文件存在 + `enabled:true` + 解析成功 | 换算 | `QS_QMT_QFQ_SNAP loaded n=<标的数> base=<日期>` |
| `absent` | 文件不存在 | 回退 `front` | **`QS_QMT_QFQ_SNAP absent`（fail-loud）** |
| `broken` | 解析失败 / 结构非法 | 回退 `front` | **`QS_QMT_QFQ_SNAP broken <原因>`（fail-loud）** |

> **关键设计决定**：`absent` / `broken` **必须打印**。理由——它们意味着「回到了已知有 C2 偏差的路径」，静默回退会让下一轮对照再次误判「差异已消除」（QD-2026-0021/0022 同族病：静默降级）。

### 2.4 导出脚本

`scripts/export_qfq_factor_snapshot.py`（新建）：从 `qfq_aux.db` 读因子表 ⇒ 计算累积因子 ⇒ 只保留跳变点 ⇒ 写快照 + 打印统计（标的数/跳变点总数/体积/时间窗覆盖）。

## 四、影响面

| 面 | 评估 |
|---|---|
| **本地回测** | **零影响**（不改本地取数；甲案只动 QMT wrapper） |
| **QMT 产物** | 六产物 SHA16 **必然换锚**（模板串变）⇒ 基线 v1.5 ＋ 矩阵追认 |
| **QMT 回测结果** | **预期改善**：价量因子输入与本地同源 ⇒ 选股差异应显著收敛（D 类 26 → 目标 ≤5） |

| 实盘风险 | **同 D-30**：文件存在即消费 ⇒ **实盘运行机不部署快照**（部署时不放文件即自动 `absent` 回退 front） |

**反向影响（须防）**：换算只在**有快照记录**的标的上生效；未记录标的（因子恒 1）按 1.0 处理 ⇒ 与现状一致，不引入新差异。
