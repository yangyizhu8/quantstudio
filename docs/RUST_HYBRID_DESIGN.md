## 2. 引擎级双跑对比器设计（新工件 · 立项令定案）

### 2.1 为什么 L1-L4 不可复用

既有 L1-L4 保真对比器对比的是「本地引擎 vs PTrade 桌面」**跨平台**差异（API 语义/数据口径/撮合行为）。本工件对比「Python 原版引擎 vs Rust 内核引擎」**同平台同数据**的逐位回归——差异只允许来自内核实现，任何位差都是缺陷。对象、判据、失败语义完全不同，复用会引入平台噪声。

### 2.2 架构

```
scripts/double_run_engine.py（新工件）
  输入：策略文件 + 窗口 + 引擎档位 + 数据根（QUANTSTUDIO_DATA_ROOT）
  ① 跑 Python 原版引擎（当前 main 路径）→ 结果目录 A
  ② 跑 Rust 内核引擎（--rust-kernel 开关注入，默认关）→ 结果目录 B
  ③ 逐位比对器：trades / nav 序列 / QS_FILL_AUDIT 事件流
  输出：PASS/FAIL + 首差异定位（字段/行号/期望值/实际值）+ 比对报告 json
```

- 双跑经同一 CLI 入口（`run_ptrade_strategy`）+ 同一数据根，仅内核开关不同——消除入口差异
- 比对三件套：
  - `trades.csv`：行数、逐行逐字段（date/code/action/volume/price/commission/tax/pnl）**字符串级**逐位比对（避免浮点格式化歧义，导出即字符串）
  - `nav_history`：逐日 nav/cash/market_value/benchmark/positions **位级**（repr 全精度）比对
  - `QS_FILL_AUDIT` 事件流：逐事件序号+逐字段位级比对（审计行由引擎输出，Rust 内核经 PyO3 触发同一格式）
- 浮点容差：**零容差**（逐位一致是 G3.5 双跑门标准；不因实现语言放宽——§3 契约保证可达）

## 3. 三处数值契约（逐位一致口径 · 行号全部实测核对）

| 硬点 | 实测源码锚点 | 定案方案 | PyO3 依据 |

| ② f64 乘加链运算顺序 | 费用链 `backtest_engine.py:1106-1125`（cost_amount→commission→transfer→total，含减一手重试分支）；avg_cost `:1138`；pnl `:1183`；撮合滑点 `:1057-1059` | 逐序翻译：Rust 侧按源码语句顺序逐条 f64 运算；**禁 FMA / fast-math / 自动向量化重排**（Rust 默认不重排 f64 运算、无 fast-math 编译开关，合约写死：Cargo profile不开 opt-level=3 之外的激进攻项、代码不用 `mul_add`） | Rust 语言语义（默认严格 IEEE 754 顺序求值）；依据 /rust-lang/reference |
| ③ int() 向零截断 | `round_to_lot libs/shared_ashare_rules.py:50-52`（`max(int(raw/lot)*lot, 0)`）；买入 `int(buy_value/fill_price) :1101`；卖出 `int(sell_value/price) :1169`；公司行为 `int(pos.volume) :853/:947` | Rust `as i64` 同为向零截断，同构复刻；负零/大值边界与 CPython 语义一致（f64→i64 as 转换在溢出时饱和，CPython int() 抛 OverflowError——本域输入恒正恒有限，饱和路径不可达，注释声明） | Rust Reference（casts 章节：float as int 向零截断） |
