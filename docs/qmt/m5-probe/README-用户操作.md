## §2 环境准备（一次性）

1. 打开 QMT 客户端并登录（回测/模型交易环境）；
2. **数据管理 → 补充数据**：
   - **财务数据**（M5-14 前提；`get_financial_data` 依赖本地已下载的财务数据，见
     `docs/qmt/inner-api/07-行情函数.md:1837`「使用前需要补充本地数据」）；
   - **日线历史**：至少覆盖探针标的 `000001.SZ` 与六策略回测窗口；
3. 确认探针标的 `000001.SZ` 与板块「沪深A股」在本地可见。

> 若某类数据无法补充，请在回传材料中**如实注明**（缺项将判为 `UNRESOLVED`，不算失败）。

## §3 运行探针（一次取证 11 项）

1. **编码转换（必做）**：仓库内探针为 UTF-8 存储，QMT 要求 GBK 物理编码。在探针所在目录执行：
   ```powershell
   python -c "import pathlib; p=pathlib.Path('m5_probe_qmt.py'); p.write_bytes(p.read_text(encoding='utf-8').encode('gbk')); print('GBK_OK')"
   ```
   （预期输出 `GBK_OK`；转换后文件首行仍为 `#coding:gbk`）

2. 将 `m5_probe_qmt.py` 放入 QMT 策略目录（或「模型交易 → 新建策略」粘贴其内容）；
3. 以**回测**方式运行一次（建议回测窗口 ≥ 20 个交易日，以便采集 handlebar 节拍）；
4. **导出输出日志**：包含所有以 `QS_M5_PROBE:` 开头的行（QMT 界面「日志/输出」面板复制或导出文件）。

> **证据要点**：`QS_M5_PROBE:` 行即为结构化证据。若某行出现 `"ok": false`，请**原样保留**
> （那是有效证据，说明该 API 在真实环境下不可用/形态不同）。

## §4 运行六策略回测（数值对照素材）

1. 六策略 QMT 产物位于 `output/qmt_export/<strategy_id>/qmt/<strategy_id>_qmt.py`
   （strategy_id：`CANSLIM突破成长选股策略` / `fall_reversal` / `tech_etf_mvo_rotation` /
   `vol_regime_mom_rev` / `weekly_smallcap_growth_momentum_10` / `周频小市值成长动量（三层止损）`）；
2. 逐个导入 QMT 并回测：**窗口建议 ≥ 1 年**（覆盖周频/月频调仓时点——M3 桩冒烟观察项 O-1
   「五策略 20 bar 零订单」需放大窗口方能归因）；
3. 每个策略导出：**回测报告**（净值/收益）+ **订单明细** + **持仓明细**（若界面可导出；不可导出则截图或复制关键表）；
4. 若某策略运行报错，请**原样保留报错文本**（这是最有价值的证据）。

## §6 回传后流程（本会话批3）

1. **P-4 归因脚本**解析回传 → 逐项判定（钉死值 / `UNRESOLVED` + 原因）；

## §7 常见问题

| 现象 | 处置 |
|---|---|
| 探针无输出 | 确认文件为 **GBK** 编码且首行 `#coding:gbk`；确认以「回测」方式运行（handlebar 需被驱动） |
| `get_trading_dates` 在 init 内报错 | **这是预期证据**（`06-系统函数.md:12`），原样保留即可 |
| 财务数据全空 | 先完成 §2 的财务数据补充（M5-14）；仍空则在回传中注明 |
| 六策略某策略零订单 | 属观察项 O-1，正是要归因的现象——放大窗口后原样报告即可 |
| 不确定某步骤 | **宁可如实记录"未执行/不确定"，也不要推测性填写** |
