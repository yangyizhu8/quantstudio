## 一、背景与动机

### 1.1 两次同因事故

| 实例 | 时间 | 泄漏件 | 当时标注 |
|---|---|---|---|
| **#2** | 2026-09-18 | `c8c1b75`（MCP 重试有界件） | ④验收有条件通过 + 缺陷待修 + ⑤未确认 |
| **#3** | 2026-09-20 | `4a863af`（passthrough DROP-REPLACE 缓解方案） | **「六步①，待审」** |

**两次根因完全相同**：

> **检查动作做了、判据用错**——C7 ① （打印 `origin/main..HEAD` 清单）**每次都执行了**，
> 但 ③ 的判据只覆盖「**本笔闸门是否齐备**」，**未覆盖「清单中其他笔是否已过闸门」**。
> 即把「**本件已批准**」误当成「**清单全部可推**」。

C7 配套铁律本已写明「任何**非本件提交**出现在待推送清单中，一律**先声明、后由归属会话确认闸门，不得默认放行**」——
**但该条依赖人工目视**，而同类错误已发生两次 ⇒ **必须有机器兜底**。

### 1.2 关键对抗性事实（先想清，否则方案是纸糊的）

**纯"脚本门"拦不住裸 `git push`** —— 没人调用它，它就等于不存在。

**真正的技术拦截点**是 Git 的 **`pre-push` hook**：`git push` 时由 Git 自动执行，
**非零退出即中止推送**。故本方案**必须**包含 hook 接线，否则只是"又一份要人记得跑的清单"。

## 二、范围与边界

### 2.1 新增交付物

| # | 文件 | 作用 |
|---|---|---|
| **D1** | `scripts/prepush-gate.ps1` | **核心判据**：读 `origin/main..HEAD` 清单，含非本件提交即拒绝 |
| **D2** | `.githooks/pre-push`（入库） | **技术拦截点**：Git 在 `git push` 时自动调用 D1 |
| **D3** | `core.hooksPath` 配置 | `git config core.hooksPath .githooks` —— 使 hook **随仓库分发**（`.git/hooks/` 不入版本库） |
| **D4** | `docs/ops-verification-conventions.md` C7 增补 | 机器门语义 + 放行通道 + 留痕格式 |

### 2.2 不改动

- 不改推送 URL 配置（`origin` 维持 `fetch=plus / push=plus+qs`）；
- 不改既有 C7 人工三查（**机器门是叠加，不是替代**——④ `eco/main` 检查仍在）；
- 不引入服务端 CI 依赖（本门纯本地，推送前生效）。

### 2.3 放行通道（总调度指定语义）

**唯一合法例外**：经**用户裁定批准**的**捆绑推送**（如生态件带 `98af33d` 先例）。

- 须显式提供裁定引用：**`QS_PUSH_BUNDLE_RULING=<裁定标识>`**（如日历节号）；
- 且须**列明**允许捆绑的提交：`-AllowAlso <sha1,sha2>`；
- **判据**：清单中所有非本件提交**必须逐一落在 `-AllowAlso` 内**，否则仍拒推；
- **强制留痕**：放行事实写入 `docs/handoff/push-bundle-rulings.log`（`docs/` 属豁免层，不触发同步门）。

**⇒ 机器拦人、例外走裁定、不留后门**：**无裁定引用的捆绑一律 exit 9**。

## 三、任务拆解

### T1 · 核心判据（D1）

```
输入：-Commit <本件 sha 前缀> [-AllowAlso <sha 列表>] [-ReportOnly]
流程：
  1) 清单 ← git log --format="%H %s" origin/main..HEAD
  2) 本件 ← 清单中匹配 -Commit 的项（不存在 ⇒ 直接 FAIL，防误传）
  3) 其他 ← 清单 − 本件
  4) 其他为空  ⇒ PASS（正常单笔推送）
  5) 其他非空：
       a. 无 QS_PUSH_BUNDLE_RULING ⇒ FAIL（exit 9），打印逐笔 sha+subject
       b. 有引用但 -AllowAlso 未覆盖某笔 ⇒ FAIL（exit 9），列出**未覆盖**的笔
       c. 全部覆盖 ⇒ PASS + 写留痕（时间/裁定引用/清单逐笔）
输出：逐笔清单（sha + subject）+ 判定 + 退出码（0 PASS / 9 拒绝 / 2 用法错）
```

### T2 · Hook 接线（D2/D3）

`.githooks/pre-push` 语义：Git 推送时把**待推 ref 的本地 sha** 通过 stdin 传入；
hook 据此取 `origin/main..<local-sha>` 清单 → 调用 D1。

- **`-Commit` 由 hook 从 stdin 解析**（`refs/heads/main <local> <remote>` 的第三列）；
- **hook 不传裁定引用** ⇒ **默认严格**：任何非本件提交一律拒推；
  需要捆绑时由**人在命令行显式导出 `QS_PUSH_BUNDLE_RULING`** 后再 push（**故意设计**：
  例外必须是有意识的动作，不能由 hook 自动放行）。
- 启用：`git config core.hooksPath .githooks`（**一次性配置**，随仓库 `docs` 记录）。

### T3 · 留痕（D4）

**格式**（追加一行/次）：
```
2026-09-20T11:30+08:00 | ruling=<裁定标识> | commit=<本件> | bundled=<sha,sha> | by=<会话标识>
```

### T4 · 文档与接线说明

`docs/ops-verification-conventions.md` C7 增补：机器门语义、放行通道、`core.hooksPath` 启用步骤、
以及**已知可绕过面**（见 §四 R1）。

## 四、风险描述

| # | 风险 | 规避 / 诚实说明 |
|---|---|---|
| **R1** | **`git push --no-verify` 可绕过 hook** | **技术上无法阻止**（Git 设计如此）。对策：① C7 人工三查**照旧执行**（机器门是叠加）；② 留痕日志使**绕过后无记录**可被事后审计发现；③ 纪律上升级为「**任何 `--no-verify` 推送须在回报中声明**」。**本方案不声称"绝对拦死"** |
| **R2** | **hook 未启用**（`core.hooksPath` 未配 / 新克隆未配） | D4 文档写明启用步骤；**推送回报须附「hook 已启用」自证**（`git config --get core.hooksPath` 输出） |
| **R3** | **`-AllowAlso` 被滥用**（把裁定当万能通行证） | **强制一一对应**：裁定引用 + 显式列明 sha；**未列明即拒推**；留痕可追 |
| **R4** | **误判本件**（`-Commit` 传错） | 本件在清单中**必须存在**，否则 FAIL（防"传个不存在的 sha 让全部变其他笔"或反之） |
| **R5** | **hook 影响正常单笔推送**（误拦自己） | 单笔推送时"其他"为空 ⇒ 直接 PASS；验收含**正常单笔不误拦**用例 |
| **R6** | **Windows 下 hook 执行环境**（`.githooks/pre-push` 无扩展名，由 Git bash 执行） | hook 写成 **sh 兼容**（调 `pwsh`/`powershell` 执行 D1），或 hook 为 sh、逻辑在 ps1；验收含**真实 `git push` 触发**用例 |

## 五、验收要点

**三类核心场景 + 两类边界**（全部**实测**，非纸面）：

| # | 场景 | 构造 | 期望 |
|---|---|---|---|
| 1 | **单笔本件** | 仅 1 笔本地领先 | **PASS**（不误拦） |
| 2 | **含他件·无裁定** | 本地领先 2 笔 | **exit 9 拒绝**，逐笔打印 |
| 3 | **含他件·有裁定且列明** | 同上 + `QS_PUSH_BUNDLE_RULING` + `-AllowAlso` 覆盖 | **PASS + 留痕** |
| 4 | **含他件·有裁定但未列明** | 裁定引用存在，`-AllowAlso` 缺某笔 | **exit 9**（**不留后门**） |
| 5 | **真实 `git push` 触发** | 实际执行 push（指向本地裸仓，不打真远程） | **hook 真的拦住** |

> 场景 5 用**本地裸仓**做远端（`git init --bare`），**绝不拿真远程试错**。

## 六、质量判据

1. 五类场景逐条与期望一致（含"真实 push 被 hook 拦住"）；
2. **正常单笔推送零误拦**；
3. **例外必须显式**：无裁定引用 ⇒ 一律拒；
4. 留痕格式固定、可 grep；
5. **不声称绝对安全**：R1 的 `--no-verify` 绕过面在文档与回报中如实披露；
6. **六步全程**；`scripts/` 属共享层 ⇒ **推送后同步门强制无豁免**；
7. 回退点：实施前 `git stash create -u` + `store` 持久化。
