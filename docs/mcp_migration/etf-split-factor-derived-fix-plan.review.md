## 二、必须修复（P0，代码级）

### P0-1：`already_handled` 代码格式不匹配（必现 bug，会导致股票重复送股）

positions 与 `result.corporate_actions` 中的 code 均为 **QMT 后缀格式**（`_to_qmt` → `'600000.SH'`，见 `backtest_engine.py:721/742`）；方案用 `bare = code.split('.')[0]`（`'600000'`）去比对 → **永远不相等** → 所有有记录的股票除权日都会在 stock_dividend 路径之外被反推路径再次送股。

修复（任选其一，推荐前者）：
```python
already_handled = {self._to_qmt(str(a.get('code'))) for a in self.result.corporate_actions
                   if a.get('date') == day_str}
# 判断处：if self._to_qmt(bare) in already_handled: continue
```
且新记录 append 的 `'code'` 也统一用 QMT 格式，避免同一列表混两种格式。

### P0-2：未吸附的 ratio 仍会执行送股，与方案 §九 自述矛盾（现金分红必现误触发）

方案代码（§六 217-221 行）：
```python
snapped = round(ratio * 2) / 2
if snapped > 0 and abs(ratio - snapped) / snapped < 0.005:
    ratio = snapped
if ratio <= 1.01:
    continue  # 吸附后不触发
```
`ratio = 1.0347`（510880 典型现金分红日）→ snapped=1.0，偏差 3.47% > 0.5% → 不吸附 → **1.0347 > 1.01 → 执行送股 +3.47% 幽灵股、avg_cost 错误摊薄**。

方案 §五 声称"ratio ≈ 1.0+微小偏差（如 1.005）吸附到 1.0 后不触发"只在收益率 <0.5% 时成立；实测现金分红带 1,575 次事件（收益率 1%~10%）**全部会误触发**。§九 风险表"异常 ratio 不吸附保守不送股"与方案自身代码矛盾。

**必须明确未吸附时的行为**（见 P1-3 规则），未吸附一律不得直接送股，且打 WARN 日志。

## 三、必须决策（P1，语义级）

### P1-3：吸附规则需覆盖"非 0.5 倍数真实折算"（189 次），建议按带区处理

"0.5 倍数"只是启发式（实测 512890≈2.0462 等真实折算并非 0.5 倍数）。建议规则：

```
ratio = prev_close / curr_preClose
ratio < 0.99          → 份额合并（见 P1-4），对称处理
0.99 ≤ ratio ≤ 1.01   → 非除权日，跳过
1.01 < ratio < 1.10   → 现金分红带：不送股，跳过 + WARN（TD-ETF-DIV）
ratio ≥ 1.10          → 吸附（0.5 倍数、容差 0.5%）：命中用吸附值，未命中按原值送股 + WARN
```

- 159995（1.9993→2.0）、515880（1.9987→2.0、3.0019→3.0）、513100（5.0019→5.0）→ 吸附命中 ✓
- 512890（2.0462）、510500 2022-08-29（1.1455）→ ≥1.10 未吸附 → 原值送股 ✓（现金分红单次事件不可能 ≥10%，此带区误触发风险可接受）
- 510880/510500/518880 等现金分红（1.01~1.10）→ 跳过 ✓（方案测试 3 的 `ratio=1.37 → 不吸附` 断言需按新规则修订为"1.37 ≥1.10 → 原值送股"）

### P1-4：份额合并（ratio < 0.99）完全未覆盖（全宇宙 725 次）

合并日（如 511030≈0.1、510580≈0.248）若不处理：股数不变、价格跳升 → **净值虚涨 1/ratio 倍**（0.1 → 净值 ×10）。公式与送股对称（`volume ×= ratio`、`avg_cost /= ratio`，注意整手取整），建议对称处理：吸附 0.5 倍数（容差同 0.5%），未吸附 WARN+跳过。若暂不处理，必须登记技术债并日志 WARN（当前方案对这类事件是**静默**错误）。

### P1-5：股票路径分工前提不成立（stk_div 全 0 + 仅 2026 数据），需二选一

- **方案 X（推荐，最小影响）**：反推路径仅对 `is_etf(bare)` 生效。股票行为完全不变 → 验收标准 4"股票不回归"严格成立；股票送股缺失另立技术债（见 §五）。
- **方案 Y（通用兜底）**：跳过条件从"当日有记录"改为"当日记录 `stk_div > 0`"（当前 stk_div 全 0 → 反推路径对股票也生效）。能顺带修复股票送股，但：① 现金分红日（2155 条 2026 记录）仍会误触发幽灵送股，需依赖 P1-3 带区规则；② 股票回测结果必然变化（含此前无记录股票的 17,824 个除权日），必须逐项说明并与黄金结果对比，不能只断言"股票不回归"。

## 八、勘误与补充核实（2026-08，tushare 接口实测）

对 §一.3"ETF 侧因源上无精确数据"的修正（用真实 tushare token 实测 + 官方文档全表核查）：

1. **股票 dividend 接口**（[doc_id=103](https://tushare.pro/document/2?doc_id=103)；注意 doc_id=14 是"上市公司数据"模块目录页）实测：纯 A 股（`159995.SZ` → 0 行；`600000.SH` → 76 行，字段含 stk_div/stk_bo_rate/stk_co_rate/cash_div/cash_div_tax）。股票侧回填可行性不变。
2. **基金分红接口官方名为 `fund_div`**（[doc_id=120](https://tushare.pro/wctapi/documents/120.md)，`fund_dividend` 不存在）：实测存在，`510500.SH` 的 `div_cash`（0.087/0.091/0.062/0.149）与本地 preClose 差额（prev_close − preClose）**逐分精确吻合** → **ETF 现金分红金额有精确结构化来源**。但：① 覆盖不全（159915/518880 有真实分红却返回 0 条，接入前须逐 ETF 核查）；② 同事件重复行需去重；③ 项目已 MCP-only（QuantStudio secrets.env 无 tushare token），接入需恢复 tushare 单表采集（用户决策）或等云端提供对应表（当前 full_table_inventory.json 无 ETF 分红表）。
3. **ETF 份额折算/拆分/合并：无任何结构化接口**（fund_split/fund_convert/fund_scale 均实测"请指定正确的接口名"；官方 `fund_` 前缀接口仅 10 个）。`fund_adj` 因子跳变 = prev_close/preClose（159995 实测 1.9993，与本地同一信号同一精度，仍需吸附到 2.0）；`fund_share` 总份额跳变混入每日申赎，不精确。
4. **对方案的净影响**：preClose 反推兜底维持必须（份额折算无精确源）；TD-ETF-DIV 重新定性为"金额可精确获取（fund_div.div_cash），但覆盖不全 + 需去重 + 需用户决策恢复 tushare 单表源或云端扩展"，不再表述为"无法分离金额"。
