## 1. 落地七件（A-G）

### 件 A · 对齐生命周期门（闭环枢纽：对齐从事后审计升格为管线门禁）

- **内容**：①转换产物（qs-compile）验收清单新增必选项「平台首跑 S1 对齐报告」；
  ②策略生命周期状态机：`generated → converted → local-passed → platform-run → aligned →
  graduated`（未过对齐门不得标记毕业/分发）；
- **载体**：校验器清单（NO-LOOKAHEAD-INCLUDE 同模式）+ `docs/strategy-compiler/`
  生命周期契约文档补一节；
- **改动面**：校验清单 1 项+文档 1 节；策略/引擎零改动；
- **三型判定**：**新增检测型**（verdict 可被新证据改变：未跑对齐=WARN/FAIL，跑了且达标=PASS）；
- **验收**：新策略走全管线状态机流转正确；既有策略不回溯（存量豁免，登记制）。

### 件 B · S3 案件路由器 + S4 收敛台账（连接件）

- **内容**：S3=判别特征规则库（每案闭环回灌一条：首偏日单日突跳+preClose 缺口=公司行为类；
  委托分歧在先=触发链类；现金流先偏=费用类……），S1 报告自动输出候选类型；
  S4=收敛台账 `knowledge/alignment-convergence.md`：跨策略×时间的残差矩阵
  （本案例种子数据：3.88pp→2.23%→V2'''）、新案率曲线、平台期告警（连续 M 轮残差不动
  ⇒ 存在未发现系统性漏洞的信号）；
- **载体**：`scripts/`（S1 扩展输出）+`knowledge/`；
- **三型判定**：新增检测型（纯增量报告，不改判定行为）；
- **验收**：四象限全案历史用 S3 复跑，路由结论与人工归因一致（DAT-16→CORP 类等 6 案回归）。

### 件 C · 知识库注入生成端（第⑥环建制化）

- **内容**：skill R2 能力勘察阶段加载 `knowledge/contracts/` 全部契约档案作为生成约束
  （平台语义边界：零股卖出/摊薄口径/合并处理/E1 取数/ETF 动态池），生成器直接产出契约内
  调用模式（范本：四象限 submit_target_amount 形态）；skill 提示词骨架加「契约面」一节；
- **载体**：`skills/quantstudio-strategy-compiler/`（项目内，双推即达客户）；
- **改动面**：skill 骨架 1 节+contracts 目录引用；生成器逻辑零改动（约束注入是提示层面）；
- **三型判定**：**纯增益**（新生成策略从源头落在已对齐子空间；存量策略零影响）；
- **验收**：抽查新生成策略含契约内调用模式（如清仓含零股全清分支）≥1 处；六策略不重转不受影响。

### 件 D · 循环编排 SOP（常态运转）

- **内容**：`docs/alignment-loop-sop.md`——每新策略=看板任务挂生命周期状态机；每案=六步
  件；季度收敛复核挂 FW6/晨检节奏；S4 台账更新触发条件（每案闭环/每策略毕业时强制）；
  **客户自持版同步覆盖**（不含总调度私有机制，含任意智能体可执行步骤）；
- **载体**：项目 docs（双推即达客户）+三件套/看板机制（本侧协调，铁律复用）；
- **三型判定**：纯增益（文档件，零行为改动）；
- **验收**：SOP 按文走一遍四象限案（纸面演练 PASS）。

### 件 E · 智能体入口转链（客户侧开箱）

- **内容**：`CLAUDE.md`/`.cursorrules`/`GEMINI.md` 一行 include/复制指引 AGENTS.md；
  README「客户使用」节补三行说明（Codex 原生读 AGENTS.md；其他 agent 按转链文件）；
- **改动面**：3 个一行文件+README 一节；
- **三型判定**：纯增益（新增入口，不改任何现有行为）；
- **验收**：Claude Code/Cursor 在客户克隆仓测试读取（内部模拟一次）。

### 件 F · 数据落地客户版（依赖：MCP 全数据源替代线收口）

- **内容**：客户拉取后建 `data/quantstudio.db` 的管道说明（数据源授权/同步命令/校验）；
- **载体**：随数据源线的客户交付文档（该线在建，节点后置）；
- **三型判定**：纯增益（文档）；**依赖外部线，排期跟随**。

### 件 G · 收敛判据与维度宣布（循环的终点仪式）

- **内容**：`contracts` 增「维度对齐档案」：连续 N 个新策略首跑 S1 全绿（N≥3 起）⇒ 该 API
  维度宣布对齐，转维护态（只响应平台演化）；S4 台账自动统计触发提示；
- **三型判定**：新增检测型；
- **验收**：判据机检（S4 脚本）+首例候选维度走查（预计 ETF 日线策略域在 CORP-02 后具备候选资格）。

## 4. 风险与边界（诚实申报）

1. **平台侧回测通道=用户域**（日志导出模式已跑通；全自动需平台定时通道，您域裁定项）；
2. 平台演化动态注入新差集——收敛为棘轮式（已消除不复发），非终点静止；
3. 智能体能力差异由客观判据兜底（测试黄金化+S1 残差阈值机器判）；
4. 知识库膨胀治理：contracts 季度 sweep+supersedes 语义；
5. 多策略并发案件调度容量：三件套既有机制，必要时您域加开执行会话。

## 5. 回退与治理

- 每件独立六步+独立 revert（A 门禁可单点关停：清单项摘除即回退）；
- 全链无守护进程、无新增常驻服务——循环由「策略事件驱动」（新策略/新日志到达才转），
  零额外算力占用；
- 治理：闭环资产唯一权威源=仓库版本（双推同步，无第二分发通道）。
