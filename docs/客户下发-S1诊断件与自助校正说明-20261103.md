# 客户下发材料（草案）· QFQ 辅助库路由诊断与记录校正

> 状态：**草案**（随修复版下发前定稿；不含任何客户数据）
> 适用：出现 `AuxRouteError: source_generation='mcp-gen1' 的辅助库不存在: .../data/D:\...`
> 影响面：`stock_daily` / `etf_daily` / `stock_minutes` 三个增量任务（共用 mcp-gen1 路由）

---

## 1 现象与影响（先让客户看懂）

- 现象：这三个任务在**取数前**就失败，日志末尾是一屏 traceback；
- 原因：`qfq_source_cutover` 里有一条历史路由记录，其 `aux_db_path` 是本项目**迁移前机器**的
  Windows 绝对路径；在你的 macOS 上它被当成相对路径拼接，得到 `data/D:\...` 这种畸形路径；
- 影响：这三张表**停止更新**；其余 70 个任务不受影响。

## 2 S1 · 只读诊断（客户可自助，零写入）

命令（在项目根执行）：

```bash
qs-cutover-diag            # 人类可读
qs-cutover-diag --json     # 机器可读报告（随工单回传我方）
```

输出包含：

| 字段 | 含义 |
|---|---|
| `records[]` | 每条 cutover 记录：`cutover_id / source_generation / status / aux_db_path / migratable` |
| `migratable=false` 的判定依据 | 该值与当前平台形态不符 / 目标库不存在 / 路径根不在项目内 |
| `suggested.aux_db_path` | 建议的新值（按当前机器的绝对路径生成） |
| `writes` | 恒为 `0`（证明零写入） |

**纪律**：S1 只读，不改库、不建文件、不停进程；报告可安全回传。

## 3 S2 · 校正执行（默认由我方执行；客户自助需按 §3.2 约束）

### 3.1 我方执行（优先路径）

我方在约定窗口内执行，步骤：备份（记录快照 + DB 文件级双备份）→ CAS 校验 → 插新记录 +
旧记录 `status='superseded'` → 复验 → 审计行落盘。客户无需操作。

### 3.2 客户自助（保留能力，需严格约束）

```bash
qs-cutover-rehost --plan <S1报告.json>                 # 默认 dry-run：只打印将做什么
qs-cutover-rehost --plan <S1报告.json> --apply \
    --expect-aux-db-path "D:\miniQMT策略实盘\...\qfq_aux_mcp_gen1.db"
```

- 缺 `--apply` ⇒ 只打印方案；
- 缺 `--expect-aux-db-path` 或该值与库内现值不符（CAS 不符）⇒ **拒跑，库零变化**；
- 备份失败/缺失 ⇒ **拒跑**（双备份都要）；
- 全过程写审计行 `data/logs/qfq_cutover_repair_audit.log`。

## 4 执行后验证清单（客户自查）

1. `qs-cutover-diag --json` ⇒ 原记录 `status=superseded`，新记录 `migratable=true`；
2. 单跑一次 `stock_daily` 增量 ⇒ 不再出现 `data/D:\...` 报错，日志出现 `written=` 或 `no new data, skip`；
3. GUI 任务页三张表状态恢复为「成功/完成·审计告警」（不再是失败）。

## 5 回滚

- 记录快照 JSON：原样回写该行（含 status 与时间戳）；
- DB 文件级备份：整体还原（需停采集）；
- 回滚后 `qs-cutover-diag` 的读数应与执行前逐位一致。

## 6 不变更声明

- 不改 `qfq_aux_paths.json`（你的配置是正确的）；
- 不删除任何日志/备份；
- 不触碰其余 70 个任务与任何数据表内容。
