### 2.2 ~~方案 P0-A（原设计）~~ 【②审驳回】→ 改为 P0-A'（挡 + 清偿）

**驳回记录（②审 2026-11-07 22:0x；我方核查后确认审核方正确）**：原 P0-A 主张「gate 用全表计数 ⇒ 历史存量恒超 ⇒ 收窄到本周期」——**该机理判断错误**。

| # | 驳回理由 | 实证 |
|---|---|---|
| 1 | **FP-6（2026-10-20）已实现类似收窄**，运行时仍卡 | `hold_reason` 原文 = `dead_letter=**428** 超过阈值 0`（**窗口内**计数，非全表 17,520）；全表数只进 health 报告 |
| 2 | 收窄到「本周期新增」后，**本轮 60 单元仍会新增死信、仍然挡** | `qfq_cycle_run`：`exec=60 ok=0 fail=60` ⇒ A 解不了当前死锁 |
| 3 | 只按时间豁免旧死信 = **放水位越过已知 stale 证券** | **数据质量倒退**，不可接受 |

⇒ **原 P0-A 作废**（"收窄"价值已被 FP-6 覆盖；"豁免"取向有害）。

#### 2.2b 方案 P0-A'（②审方向指令）：判据**保持窗口内**，处置从「挡」升级为「挡 + 清偿」

```
窗口内死信（当前 428 条）
  → ① 自动 requeue，有限次重试（建议 ≤2 次，记录 attempt）
  → ② 穷尽仍未成功 → 进「豁免清单」（显式注记 + **须人工确认**）
  → ③ 人工确认豁免后，才移出窗口内计数
  → ④ gate 判据仍是「窗口内死信=0」，但该 0 是"清偿后的 0"而非"豁免后的 0"
```

| 项 | 内容 |
|---|---|
| 与 P0-A 本质差别 | P0-A 改**判据口径**（放宽）；A' 改**处置动作**（清偿），判据不放宽 |
| 预置依赖 | **依赖 P0-D 的分桶清单**；依赖失败源修复（P1-A / ART）否则 requeue 仍失败 |
| 风险 | requeue 产生新的重拉负载（有限次，可控） |
| 交付形态 | **属新设计件，须单独回炉过①→②审**（②审明确） |
| 启用条件 | **仅在批 1+2 后仍不收敛时启动** |

### 2.3 方案 P0-B（推荐·并行）：表级隔离——单表问题不冻结其他表

**改法**：`_commit_or_hold_watermarks` 逐 intent 判定，替代全局 `passed`：

```python
for source, table, freq, cand in intents:
    table_passed, why = self._table_gate(conn, table, cycle_id)   # 新函数
    if table_passed:
        advance + status='committed'
    else:
        status='held', hold_reason=f"{table}: {why}"
```

| 项 | 内容 |
|---|---|
| 核心论点 | 即使 P0-A 后仍有失败，也应**只 hold 出问题的表**，不该四表连坐 |
| 表级判据（建议） | ①该表本轮无新增死信 ②该表无 orphan ③该表 candidate ≤ 表内 MAX（数据确已到位） |
| 预期效果 | 四表可独立解冻；`etf_daily` 的问题不再拖累 `stock_minutes` |
| 风险 | 逐表判定增加一次查询/表（4 次，可忽略） |
| 回退 | `QS_QFQ_GATE_TABLE_SCOPE=0` 恢复全局开关 |

### 2.5 方案 P0-D（**解冻必要条件**·②审升格 + 有条件授权）

> ②审裁定：P0-D 从"必配"**升格为「解冻必要条件」**，且**批 2 提前**（与 P0-B 同批）。
> 理由：解冻钥匙 = 「本轮单元成功 + 窗口内死信清零」，**两者都靠 D 和失败源修复，都不靠 A**。

**动作（按 `effective_date` 分桶，②审硬性要求）**：

| 桶 | 判定 | 处置 | 禁止 |
|---|---|---|---|
| **窗口内** | `effective_date ∈ [窗口起点（etf_daily 09-04）, candidate]` | **必须 requeue 重试**（它们是提交区间的真实数据空洞） | **禁止直接归档** |
| **窗口外** | `< 窗口起点` 或已过 candidate | 可归档（保留统计快照） | — |

| 项 | 内容 |
|---|---|
| 前置 | ①**无锁窗**（daemon 停）②**备份** `qfq_trigger_queue` ③**先出 dry-run 清单给审核方过目再执行** |
| 风险 | 不可逆 ⇒ ②审"有条件授权"，清单过目是硬门 |
| 备注 | 超 SLA 的 47,199 pending 同样按 `effective_date` 分桶：窗口内 supersede/requeue、窗口外可批量关闭 |
