## 🔹 方案（三件：档案 + 机检 + 走查）

### G-1 维度对齐档案（contracts 增件）

**产出**：`knowledge/contracts/dimension-alignment.md`（新档案，形态同构于 api-semantics 建档模板）。

**每条维度一节，六要素**：
1. 维度名 + 覆盖 API 集（如 ETF 日线域：`get_history`/`order_target_value`/`get_positions`/`get_etf_list_local` 等）；
2. 对齐判据口径（S1 verdict「已对齐」或「残差达标」，阈值 <0.5%）；
3. **连续对齐计数**（N 值+累计策略清单：策略 id/首跑日期/verdict/证据指针）；
4. **宣布状态**：`候选`（N<3）→ `已宣布·维护态`（N≥3，转只响应平台演化）；
5. 平台演化响应记录（宣布后遇平台版本变更 → `graduated → re-aligned` 复验记录）；
6. 关联指针（S4 台账行 / registry 案号 / 契约档案交叉引用）。

**索引登记**：`knowledge/README.md` 导览表 + `registry.md` 交叉引用各一行（簿记）。

### G-2 收敛判据机检脚本（S4 脚本）

**产出**：`scripts/check_dimension_alignment.py`（新脚本，只读+提示输出，**不改任何判定行为**）。

**输入**：S4 台账（`knowledge/alignment-convergence.md` 的机器可读面）+ 维度档案 + 既有 S1 JSON 产物；
**输出**：
- 每维度当前连续计数与状态；
- **候选提示**：连续 N≥3 且状态=`候选` → 提示「可宣布该维度对齐（待用户确认）」；
- **维护态告警**：已宣布维度出现新案/平台演化 → 提示「需 re-aligned 复验」；
- 退出码：`0`=无提示、`3`=有候选/告警（供 CI 或人工巡检挂载）。

**纪律**：脚本**只产提示不自动宣布**（宣布=用户确认动作，对齐 lifecycle「唯一硬门」语义）；
N 阈值与「首跑」定义（策略首次 `platform-run` 后的首份 S1 报告）写入脚本常量+档案口径。

### G-3 首例候选维度走查（ETF 日线策略域）

**动作**：以既有证据件回填该维度对齐记录——四象限（CORP-01/02 全链后首跑）、
其它 ETF 日线策略首跑记录（有则计入，无则如实标「暂无」），判定当前 N 值与状态；
**产出**：维度档案首条实例 + 走查结论（是否达宣布门槛）。

## 🔹 八项计划

**① 阶段**：闭环七件最后一环（A/B/E/C/D/PDO 知识环已落）；六步：本件①→②审→③实施→④验收→⑤确认→随批⑥。
**② 目标**：收敛从「人工看台账」升为「机检判据」；维度宣布机制落地（档案+机检+首例走查）。
**③ 分工**：主导=本会话；②审=ZCode；③实施=**zcode_code 委派**（脚本为实现型编码——`check_dimension_alignment.py`
属「写脚本」，触发委派条件；档案/走查为数据工件由本会话直执）。
**④ 事项**：G-1 档案（+README/registry 登记）→ G-2 机检脚本（含单测：候选/告警/无提示三态）→
G-3 首例走查（回填档案）→ ④验收证据 `docs/evidence/loop-g-acceptance-<日期>.md`。
**⑤ 待确认**：宣布动作的确认权归属（建议=用户；与 lifecycle 硬门一致）；
N 阈值是否沿用 3（母计划原文 N≥3，建议沿用）；
**⑥ 风险**：
- S4 台账「机器可读面」当前是 Markdown 表格——机检需定义稳定解析口径（或要求台账同步产 JSON；
  **建议**：脚本优先消费 S1 JSON 产物集，Markdown 台账作人工核对源，避免脆解析）；
- 历史首跑记录可得性：早期策略未必留有 S1 报告 → 走查如实标「暂无」，不虚增 N；
- 「首跑」定义歧义（策略重跑/参数寻优轮次是否计数）→ 口径写入档案（建议：同策略 id 只计首次合格记录）；
- 宣布后阈值收紧（lifecycle L22 表述）的具体收紧量未定 → 本件只落「机制+提示」，收紧量化登记 M5/后续件。
**⑦ 合规**：六步流水线；新增检测型（只产提示）；纯增益（不动既有判定/引擎/校验器）；编码委派纪律；
平台代码前置查询纪律（本件不涉平台 API，无此义务）。
**⑧ 验收判据**：
- ①维度档案落位（六要素+README/registry 登记）且与 api-semantics 形态同构；
- ②机检脚本三态单测全绿（候选 N≥3 / 维护态告警 / 无提示）+`--help` 可用+退出码语义正确；
- ③首例走查结论落档（ETF 日线域 N 值+状态判定，无记录处如实标「暂无」）；
- ④**不改既有行为**：`run_contract_gate.py --strategies` PASS；既有台账/档案 diff 仅新增；
- ⑤脚本只读+提示（grep 核验：无写台账/自动宣布代码路径）。

⑧·**判型声明**：**新增检测型**（判据可被新证据改变：N 累积到 3 即提示候选；平台演化即提示复验）——
非既有行为漂移。修复前置三问：①影响其他功能=无（新增档案+只读脚本）；②影响性能=无；③影响精度=无
（判定行为零改动，宣布仍由用户确认）。
