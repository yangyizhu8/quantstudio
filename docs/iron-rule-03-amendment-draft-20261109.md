## 一、问题与实测证据

**场景**：多会话共享同一 git 工作树，工作树高度脏（他线有大量未提交改动）。

**实测（2026-11-09，性能线）**：

| 项 | 实测 |
| --- | --- |
| 工作树状态 | `git status --porcelain` **855 项**（已跟踪已修改 **34** + 未跟踪 **815**） |
| 铁律 03 原配方执行 | `git add -A -- <本会话涉及路径>` → `git stash create` |
| **实际捕获范围** | **整树 40 文件，其中他线未提交改动 39 个** |
| 后果 ① | stash 列表留有**他线快照** ⇒ 误 `git stash pop` 会**连带恢复他线改动**（跨会话污染） |
| 后果 ② | 本线 stash 与他线自建 stash **编号交错** ⇒ 误 drop 会删掉**他线的回退点** |
| 后果 ③ | 原配方第①步 `git add -A` 本身即**跨他线 stage**（同铁律补丁「反向串车」族） |

**处置实证**：发现即 **立即 drop**（未 store 的对象不污染 stash 列表；工作树未变 ⇒ 无数据损失），改用**定向 patch 锚**替代：`git diff --output=<anchor>.patch -- <本会话路径>`，`git apply --check --reverse` 验证可用 ⇒ **可行且安全**。

## 二、拟修订条款（逐条）

### 修订 A｜新增「脏工作树」判定

> **A1** 操作前先跑 `git status --porcelain`。若**存在非本会话的 `M` / `??` 条目**，或总项数 > 0 且含他线改动 ⇒ 判定为**脏工作树**。
> **A2** 判定结论须**落盘到交接件/会话记录**（清单：哪几个是他线条目），后续回退后据此逐项核对。

### 修订 B｜脏树下禁用 `git stash create` 作回退点

> **B1** **脏工作树下禁** `git add -A -- <路径>` → `git stash create` 组合作回退点（实测会捕获他线未提交改动）。
> **B2** 改用 **per-path 定向 patch 锚**（二选一）：
> - **B2-a** 未暂存改动：`git diff --output=<anchor>.patch -- <本会话涉及路径>`（**路径逐一显式列出，禁 `-A` 跨路径**）
> - **B2-b** 已暂存改动：`git diff --cached --output=<anchor>.patch -- <本会话涉及路径>`
> **B3** **禁止用 PS 5.1 的 `>` / `Out-File` 写 patch**（写 UTF-16 ⇒ patch 不可用）。须用 `git diff --output=` 或 python `io.open(..., encoding='utf-8')` 写。
> **B4** patch 锚须**登记 sha256 + 路径**，与其它证据件同标准。
> **B5** 若他线条目**无法与本会话路径完全隔离**（同一文件内混有两方改动）⇒ **不得用 patch 锚**（会把对方改动一起锚进去/一起回退），此时**停手上呈**，由总调度裁定处置。

### 修订 C｜新增「回退点必须验证可用」（E-6 验证句）

> **C1** **任何形式**的回退点建立后，须**立即验证可用**：
> - patch 锚：`git apply --check --reverse <anchor>.patch` **通过**（能列出预期改动文件）
> - stash：`git stash show --stat <hash>` 能列出预期改动文件
> **C2** 验证不通过 ⇒ **视同没有回退点**，**停手重建**，不得继续破坏性操作。
> **C3** 理由（写入条款）：**建了但用不了的回退点比没建更危险——它让人以为有退路。**

### 修订 D｜原条款保留部分

> **D1** 原①中「精确路径」的精神保留：**任何 add/diff/patch 都必须显式列出本会话路径**，禁 `-A`/`.` 跨路径。
> **D2** 原④「回退优先逐文件定向手段，批量 git 回退是最后手段」保留。
> **D3** 原⑤「引用 stash 前必 `git stash show --stat <hash>` 核对」保留，并由 C1 扩展为**覆盖 patch 锚等一切形式**。
> **D4** 原「`git stash create` 不接受 `-u`，未跟踪件先入暂存才被捕获；不 store 会被 gc 清掉」保留（但脏树下根本不该走这条路）。
