## 一、缺陷定义（已定谳）

`_wm_health_median(table)` 取**全表**（无时间窗口）按日 `COUNT(DISTINCT code)` 的中位数作「健康基准」；而 `_wm_decouple_validate` 用它比对**当前窗口**逐日码数（±5%）。对**码数单调增长型表**（ETF 家族：2018 中位 360 → 2026 中位 2,007，八年约 5 倍），全表中位（1,060）恒远低于当前窗口（2,137）⇒ **必判 `code_count_out_of_tolerance`** ⇒ S1 对 ETF 类表**恒拒**（etf_daily 11-01/11-02/11-05 三次实锤 + 同批 `passed=49,997` 数据完整却判「码数不足」）。

## 二、改动范围（A′ 近期窗口中位）

| 项 | 内容 |
|---|---|
| **落点** | `quantstudio/pipeline/writers.py`：`_wm_health_median`(:1581) 唯一改动点（`_wm_daily_code_counts` 与 `_wm_decouple_validate` 的比对逻辑**不动**） |
| **新口径** | 健康基准 = **最近 N 个「有数据日」的按日码数中位数**（N 默认 **60**） |
| **实现要点** | ①取 `_wm_daily_code_counts(table)` 全量按日结果（已有函数，零新 SQL）②按日期倒序取最近 N 个日 ③`statistics.median` ④返回 `(median, sample_days=N 实际取得数)` ⑤**新增常量** `_WM_BASELINE_RECENT_DAYS = 60`，支持 env 覆盖 `QS_WM_BASELINE_DAYS`（回退阀） |
| **样本不足处置** | 近期日数 **< 8** ⇒ 沿用铁律 25 纪律 **fail-closed**（返回 `(None, sample_days)` ⇒ 校验判不过 + reason=`insufficient_recent_history`）——**不回落全表中位**（回落即重现本案缺陷） |
| **不动的面** | §2.2 own/foreign/unknown 判据；行级校验的 ±5% 容差；poison 机制；`_wm_expected_open_local_days` 缺开市日检查；S1 开关语义 |

### 2.1 N=30 / N=60 历史判据对照（供微调）

| N | etf_daily 基准（2026 近期） | 2026 窗口 2,137 是否在 ±5% 内 | 备注 |
|---|---|---|---|
| **60**（默认） | 待实施时实测（预期 ≈ 2,100-2,140） | 预期 ✓ | 更稳、抗单日异常 |
| 30 | 待实施时实测（预期 ≈ 2,120-2,150） | 预期 ✓ | 更灵敏、抗漂移差 |
| 全表（现状） | **1,060** | **✗ 超上限 92%** | 本案缺陷态 |

> 实施时须以实测填表（禁估算）；若 60 与 30 均通过且差异 <3%，取 60（稳）。stock_minutes 两值均应逐位等价（码数稳定）。

## 三、影响面（数据修正型·显式声明）

| 面 | 影响 |
|---|---|
| **etf 家族（etf_daily / etf_minutes 等增长型表）** | 基准由 1,060 → 近期中位（≈2,1xx）⇒ **从「恒拒」变为「按真实完整性判定」**——这是本案的**预期修正**（正确口径下应当放行的完整批次会放行） |
| **stock_minutes（码数稳定）** | 全表中位 ≈ 近 60 日中位（~5,216）⇒ **行为逐位等价**（硬门③） |
| **其他表** | 码数稳定的表不受影响；码数萎缩型表（若有）会被正确识别为「近期中位低」⇒ 仍按窗口比对（无新增放行风险） |
| **风险方向** | 唯一风险 = **真实缺数被误放行**（若窗口码数恰好落在近期中位 ±5% 内但缺某日）⇒ 已由**既有「缺开市日」检查**兜住（`_wm_expected_open_local_days` 分支，本案不动）⇒ 硬门②负向用例必须覆盖 |
| **不做** | 不动 etf_daily 数据本身；不做数据回填；不改 poison 键（人工处置） |

## 四、验收标准（四条硬门 + 可观测性）

| # | 判据 | 口径 |
|---|---|---|
| **V1** | **2026 窗口可过** | etf_daily 窗口 2026-09-07~10-16（或对应批次窗口）：`_wm_decouple_validate` 返回 `ok=True`，`median` ≈ 2,1xx，`bad_days` 空 |
| **V2** | **真实缺数据仍判不过（负向·必做）** | 构造 ①缺整日（删某日全部行）②缺码数（某日仅留 50% 码）③窗口末端缺日 三样本 ⇒ **均必须 `ok=False`** 且 reason 分别为 `missing_open_days` / `code_count_out_of_tolerance` / 边界缺失 |
| **V3** | **stock_minutes 逐位等价** | 同窗口同数据：改动前后 `_wm_decouple_validate` 返回的 `(ok, reason, median)` 三值**逐位相同**（median 允许 <1e-9 差异或完全相同） |
| **V4** | **既有 20 例全绿** | `tests/test_watermark_decouple_s1.py` 20 例 + 新增用例全绿；回归面（writers 相关）零衰减 |
| **V5** | **可观测性四要素（同批）** | `_wm_decouple_validate` 拒绝路径的**日志行**须输出：`median` / `tolerance_band=[lo,hi]` / `bad_days`（前 8 个 + 总数）/ `window=[t_min,t_max]`；poison 记录保留原字段 |
| **V6** | **回退阀** | `QS_WM_BASELINE_DAYS=0`（或 `QS_WM_BASELINE_FULL=1`）⇒ **逐位回退**到全表中位旧行为（用于对照与紧急回滚） |
| **V7** | **纯增益审计** | 数据修正型三审计（影响其它功能/性能/精度）：性能=零新增 SQL（复用 `_wm_daily_code_counts`）；精度=仅基准口径变化且由 V1/V3 双向锁定；其它功能=不改判据/poison/开关 |
