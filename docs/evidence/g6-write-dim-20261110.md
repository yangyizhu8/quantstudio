## 四、🔴 重大反例：new 路径在真实规模下**反而慢 1135 倍**

| 路径 | wall | 备注 |
|---|---|---|
| **old**（`QS_QFQ_OBS_INCREMENTAL=0`） | **0.066 s** | 批量写，120 条含 60 修订 + 60 新观测 + 60 alert |
| **new**（`=1`） | **74.947 s** | 慢 **1135×** |

**根因（已定位）**：`_inc_record_observations` 中「查相邻 `factor_time` 前值」的那条**逐条查询**（我在 v3.1 时**刻意保留、判断为「非瓶颈」**）——在 **4,500 万行** aux 上找相邻前值**无可用索引** ⇒ 全表扫 ⇒ **约 1.25 s/条**（74.9 s / 60 条 new 分支）。

**⇒ 对「G5 保持默认关」裁定的强力支撑**：本次实测证明，**若在生产库开启 `QS_QFQ_OBS_INCREMENTAL=1`，写入侧会从 0.07 秒级退化到分钟级**。默认关（=0）不只是「收益不足」，而是**避免性能倒退的必要保护**。

**⇒ 后续动作建议（呈裁）**：若将来要启用增量，**必须先**把「相邻前值」也做**块预取**（与 G5 的 `prefetch_factor_times` 同型：按 code 批量取该 code 的全部 `factor_time → 最新值` 映射，代替逐条查）。此为**新增改进项**，需走方案→审→实施流程，**不在本轮擅动**。

## 五、如实申报（未完成 / 口径边界）
