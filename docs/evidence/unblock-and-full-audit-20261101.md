### 3.3 ❌ 不可用的结论（方法缺陷，如实申报）

**我的脚本传了空 schemas**：

```python
aud = DataQualityAuditor(DB, {}, tables=None)   # ← {} 是空 schemas
```

`_audit_table_items()` 在 `tables is None` 时按 **schemas 顺序** 枚举 ⇒ **schemas 为空 ⇒ 表循环空转**，只跑了全局段。

**后果**：
- `wall=452.61s` **只是全局段**，**不含 23 表循环**；
- `issues=12` **只是全局段的问题**，不等于 10-31 轮次的「9 类错误 + 32 类警告」；
- 因此 **452.61s 与 10-31 的 1985.4s 不可比**（后者含 23 表）。

**正确做法**：用 `DataQualityAuditor.from_config(db_path(), config/alignment_rules.json, ...)`（`quality_audit.py:main()` 就是这么用的），或从 daemon 的 `writer.schemas` 取真实 schemas。

**我不重跑的理由（如实说明）**：
1. 首验的**核心判据（full 不缓存）已拿到**，重跑不会改变该结论；
2. 真正的 full 域耗时已有生产实测——**10-31 轮次的 1985.4s（含 23 表）**，那比我的合成 full 更真实；
3. 重跑需 33 分钟且会占用窗口，**收益不足**。
