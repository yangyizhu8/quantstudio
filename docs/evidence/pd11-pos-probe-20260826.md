## 2. 契约事实表（WP-A1 实施依据）

|---|---|---|---|
| F1 | `get_positions()` 键 = **XSHG/XSHE 四位后缀** | `.SS/.SZ`（`_get_ptrade_positions`） | **致命分歧源**：策略侧 `code in pos_codes` 裸串匹配恒 False → CANSLIM basis=-1、周频 tier1 静默 |
| F2 | Position 自带 **`sid` = `.SS` 两位后缀** | sid 同名同义 | 键归一的实证锚点（优先 sid，前缀规则兜底） |

## 3. 结论

1. **CANSLIM/周频止损失效根因闭环**：`get_Ashares()`（.SS/.SZ）选出的代码与 `get_positions()` 键（XSHG/XSHE）裸串不等 → `g.pending_buys` 匹配失败 → basis 恒 -1 / tier1 恒空。与双端日志行为（basis=-1.0000、tier1_marked=0、positions 恒 18、23 条 0 股废单）全部互洽。
2. **WP-A1 改动面收敛**：平台 Position 字段与本地 `ptrade_api.Position` 高度同构，wrapper 只需 ①键归一（sid 锚点）②amount>0 过滤 ③avg_cost 别名 ④输入归一防 .SH 崩溃——不需要大改属性映射。
3. **B1（delta 修复）平台侧入口确认**：`get_position(code)`（.SS/.XSHG 均可）→ `.market_value` 即现值，delta = value − market_value 可直接落地。

## 4. 遗留登记

- `.SH` 后缀致平台 get_position 内部崩溃（NoneType.asset）→ 报平台方；wrapper 侧输入归一规避。
- cost_basis 含费 vs 本地 avg_cost 不含费（F7）→ 登记为已知口径差，不在 WP-A 处理。
