## 二、平台公开 API 依据（逐字）

### 2.1 Context7 `/kay-ou/ptradeapi`

`is_trade()` 是 **PTrade 公有 API**，用途是**区分交易环境与回测环境**
（**不是**本地自创的「回测模式标记」）。因此在目标平台代码中
**必须保留原调用**，由平台自行判定环境；**不得**在转换期改写为字面量 `False`。

### 2.2 仓内逐字引文（`portability_rules.py` A-1 注释）

```
# 1) is_trade()——PTrade 公有 API，逐字文档依据（api-reference-en/utilities.md）：
#    迁入 PTRADE_REGISTERED_WARN（KEEP）。历史档 2 改写 is_trade()→False 正是
```

即：基线把公有 API 当本地实现改写，属**误判**；A-1 迁 KEEP 是**回归正确语义**。

### 2.3 为什么必须保留（语义论证）

原语义（`source_import.py` 注释逐字）：

```
# 原语义：initialize 内 `if not is_trade(): set_backtest()` 恒执行 → 配置生效。
```

改写为 `False` 后，`if not is_trade()` 恒为真 ⇒ 该分支在**交易环境也会执行**
⇒ 与平台真实语义**不一致**。保留原调用后，交易环境下该分支**不会**执行，
回测环境下按平台判定执行 ⇒ **与文档一致**。

## 四、验证要求（**不得仅把 `not in` 翻成 `in` 就当保真通过**）

### 4.1 调用上下文验证

- 定位产物中 `is_trade()` 的**实际调用点**（应出现在
  `initialize` 内 `if not is_trade(): set_backtest()` 一侧）；
- 断言该调用的**上下文结构**未被转换器改写（`if not is_trade():` 完整保留，
  不是被折叠成常量）；
- 断言产物中**不存在** `is_trade()` 被替换后的等价字面量痕迹
  （如 `if not False:` 这类改写残留）。

### 4.2 产物语义验证

- **分支语义**：在「回测环境」与「交易环境」两种假设下，
  `if not is_trade(): set_backtest()` 的执行结果**必须不同**
  —— 改写为 `False` 会使两者**相同**（这正是 A-1 要修的缺陷）；
- **不回归既有契约**：转换后产物中 `set_backtest()` 的调用条件与
  `ptrade_api` 侧回测模式开关的语义**不冲突**；
- **可执行级证据**：以受控 stub 注入两种 `is_trade()` 返回值，
  执行产物 `initialize` 体，断言**两种环境下的分支行为不同**
  （此条为**执行级**证据，非文本断言）。

> 4.1／4.2 均为**产物层**证据；文本断言只是其中最弱的一层。
