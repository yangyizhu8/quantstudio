## 1 基线读数（实测）

| 表 | 记录数 | 时间范围 | ★ 众数基线（sampled / bad / skipped / missing / unknown） | 占比 |
|---|---|---|---|---|
| `stock_minutes` | **6,856** | 2026-08-15T03:46 → 2026-11-04T16:57 | `5000 / 0 / 0 / 0 / 0` | 50.1% |
| `etf_minutes` | **7,646** | 2026-09-06T13:24 → 2026-11-04T09:28 | `5000 / 0 / 0 / 0 / 0` | 64.9% |

**次高频**为 `(5000, 0, 0, 0, None)`（stock 49.6%、etf 34.6%）——`unknown` 列为 NULL 是
**表结构演进前的旧记录**（`unknown_rows` 列是后加的），非异常；新记录一律有值。

**关键事实**：两表**全部记录 `bad = 0`（100%）**——历史上自检从未判定过"自洽偏离"。
⇒ 改后一旦出现 `bad > 0`，即为**判据漂移**（不是"发现了新问题"），须立即停线归因。

## 2 明晨对照判据（第 5 步硬门）

| 项 | 改后期望 | 不通过判定 |
|---|---|---|
| `sampled` | **5000**（抽样上限，与批大小无关） | ≠5000 且批内行数 ≥5000 ⇒ 抽样逻辑漂移 |
| `bad` | **0** | **>0 即失败**（历史 100% 为 0） |
| `skipped` | **0** | >0 即失败（窗口收窄可能误伤 → 见下） |
| `missing_factor_rows` | **0** | >0 即失败（同上） |
| `unknown_rows` | **0** | >0 即失败（同上） |

> **特别注意**：若改后 `skipped / missing_factor_rows > 0` 而 `bad = 0`，说明
> **±3 天窗口把本应命中的因子行挡住了** —— 这正是"保守方向"（不落错值），
> 但**仍属未达标的漂移**，须归因窗口计算（而非当作可接受）。此时按方案回退：
> `QS_QFQ_INVARIANT_FULL_FACTORS=1` 复跑对照，确认是否窗口导致。

## 4 附带发现（不在本方案范围，供调度参考）

- `qfq_selfcheck_log` 共 **14,502 条**（两表合计），说明自检**每批都落审计**——
  这本身是正确的观测面设计；但也意味着**每批一次 SQLite 写入**，在 233 批/轮下是
  233 次小写入（可忽略，不构成瓶颈）。
- `anchor_source` 绝大多数为 `caller`（写入锚可用），少数 `r3_reload`（兜底重载，
  那批日志有 `自检锚缺失，回退重新加载` 告警）——**`r3_reload` 出现频次可作为
  「锚传链健康度」的观测量**，建议纳入 P3/软锁后续观察，不属本次修复。
