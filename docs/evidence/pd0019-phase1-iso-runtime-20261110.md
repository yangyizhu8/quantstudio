## 三、必须上报的三项缺陷

### F1（P0 级 · 核心）**P0-1 虚拟持仓覆盖在实机未生效**

**证据（反推 `_delta`）**：
- 512890：委托 59,400 股 ＝ 目标 4,045,800 − **真实持仓 3,986,400** ⇒ `_current` 用了**真实持仓**
- 159934：委托 −3,900 ＝ 232,000 − 228,100 ⇒ 同样用真实持仓
- 若 P0-1 生效（虚拟 pos=0）⇒ `_delta = value`（512890 应约 5,004,690 元 ⇒ 受虚拟额度钳制约 74,700 股）

**代码侧已排除的**：
- TAIL 覆盖**在**产物里（L1986-1992，模块级 `if _QS_ISO_ENABLED:` 内）
- AST 顺序正确（L836 原版 → L1986 块内覆盖，**无反向覆盖**）
- TAIL **确实执行**（`QS_ISO_FILL` 证明 `_qs_iso_order_orig` 生效）

**高度锁定的根因假设**：**PTrade 对策略文件做静态解析**（我方既有注释：「平台静态白名单识别 class 语句，**变量持函数引用后调用会被 LOCAL-API-WHITELIST BLOCK**」，2026-08-22 平台实证）⇒ **模块级 `if` 块内的 `def` 可能不被平台静态识别**，`order_target_value` 体内的 `_qs_pos_amount` 调用被绑到**静态可见的 L836 原版**。
⇒ 这正好解释：**`_QSOrderRefState.*`（class 属性）生效 ✓，而模块函数同名覆盖不生效 ❌**。

**修正方向（待定级与②审）**：P0-1 改用**class 属性承载**（与 `_QSOrderRefState` 同法）：
`class _QSIsoRef: pos_amount = None` ⇒ 第一跳 `order_target_value` 内改为 `_QSIsoRef.pos_amount(security)`
⇒ 但需改**第一跳**（框架层允许，铁律 07），且需验证平台对 class 属性调用不 BLOCK。

### F2（P1）虚拟台账卖出记账为负

`QS_ISO_FILL code=159934.SZ amount=-3900 … pos=-3900` ⇒ 虚拟 pos 从 0 直接变 **−3,900**（负数）。
⇒ 虚拟台账未以真实持仓为初值，卖出即记负 ⇒ **`_qs_iso_pos_amount` 若被正确调用会返回负数**，进而污染后续 delta。
⇒ 修正：①卖出时 `pos` 钳到 ≥0；或 ②启用首日以真实持仓初始化虚拟 pos（需评估是否破坏"隔离从零开始"语义）。

## 六、F1 最小复现（2026-11-10 16:0x）——**「平台静态解析」假设被推翻**

> 按 R-20261110-02 裁①（先复现再回写方案件），以**真实产物片段 ＋ 桩**做最小复现。

### 6.1 复现方法

从产物 `ETF_f926a7_trade.py` **原样抽取两段**：L836-845（原版 `_qs_pos_amount`）＋ L1986-2000（TAIL `if _QS_ISO_ENABLED:` 覆盖块），
装配桩（`g.state`／`log`／`get_position`（返回真实 3,986,400）／`_qs_iso_*` 系列／`_QSOrderRefState`／原版 `_qs_cash_budget`），
再以 `caller()` 在**同文件外视角**调用（等价 `order_target_value` 体内 L1116 的调用形态）。

### 6.2 复现结果（含桩自检）

| 项 | 读数 | 判定 |
|---|---|---|
| 桩自检 `get_position('512890').amount` | **3,986,400** | 真实持仓桩**可见**（防"桩没接上导致 0.0"的假信号） |
| 桩自检 `_qs_iso_cash_avail()` | **100,000** | 虚拟额度桩正常 |
| `_qs_pos_amount('512890.SS')` | **0.0** | ✅ **覆盖生效**（虚拟，非真实） |
| `_qs_cash_budget('512890.SS')` | **100,000** | ✅ **覆盖生效**（虚拟额度，非真实 6,491,605） |

⇒ **Python 语义下，模块级 `if` 块内的同名 `def` 覆盖对"同文件内调用"完全生效。**
⇒ **「PTrade 静态解析 ⇒ if 内 def 不被识别」的假设不成立**（该假设是我方 §三 F1 的原始推断，在此**推翻**）。

### 6.3 剩余可能（二选一，需平台侧判定实验）

| 可能 | 说明 | 与已观测证据的相容性 |
|---|---|---|
| **P-a 贴装文件 ≠ 目录文件** | 用户贴装的是另一份产物 | banner `build=20261109-p1` **无法区分** 20:33 版（`6351206e`）与 12:20 版（`2870d298`）——因为我两次渲染用了**同一个 `__BUILD__`** ⇒ **该串不是唯一指纹**（我方设计缺陷） |
| **P-b 平台对代码做了变换** | 如 def 重排／if 展平后覆盖失效 | 无法本地验证；但 `_qs_iso_announce`／`_qs_iso_order_orig`（同 if 块内 def）**均被成功调用** ⇒ 平台能执行 if 内 def，只是"覆盖同文件内调用"这一环未见效 |

### 6.4 判定实验方案（最省成本，需用户配合一次贴装）

**探针小策略**（只打印、**不下单**，约 20 行）：

```python
def _probe_fn():
    return 'ORIG'
_QS_PROBE_ON = True
if _QS_PROBE_ON:
    def _probe_fn():
        return 'OVERRIDE'
def initialize(context):
    log.info('QS_PROBE_RESULT=%s' % _probe_fn())   # 关键读数
def handle_data(context, data):
    pass
```

| 读数 | 结论 | 后续 |
|---|---|---|
| `QS_PROBE_RESULT=OVERRIDE` | 平台支持同名覆盖 ⇒ **P-b 排除** ⇒ 回到 **P-a（贴装文件不一致）** | 需你复核贴装来源并核 sha |
| `QS_PROBE_RESULT=ORIG` | **P-b 坐实**（平台变换致覆盖失效） | F1 改 **class 属性承载**（裁①已照准），并**追加「覆盖类改法一律走属性」为框架判据** |

### 6.5 我方设计缺陷（本次暴露）

`__BUILD__` 在 20:33 与 12:20 两次重转中**用了同一个值**（`20261109-p1`）⇒ **构建标识不具备唯一性**，无法用于版本判定。
⇒ 修正（P2）：`__BUILD__` 应含**生成时刻**（如 `20261109T2027-p1`），使 banner 成为**唯一指纹**。

### 7.2 **F1 定性推翻（第 5 次自我推翻）**

**新证据**：产物 **L1590** 策略自定函数 `def submit_target_amount(security, target_amount, current_amount, reason)`
，其 docstring 逐字：

> 「按目标持仓数量计算实际买卖差额，并使用 **`order` 按数量提交委托**。ETF 买入和非清仓卖出数量按 100 份整数倍处理…」

且 **L1633** 为实际下单点：`order_id = order(security, order_amount)`。

⇒ **策略走 `order`（数量版），从未调用 `order_target_value`（金额版）**。

**由此推翻我方 F1 的定性**：

| 我方原判（§三 F1） | 真相 | 依据 |
|---|---|---|
| 「`_qs_pos_amount` 覆盖**未生效**」 | ❌ **不是失效**——`order` 包装**不做持仓查询**（数量已由策略算好）⇒ `_qs_pos_amount` **根本没被调用** | L1590 docstring ＋ L1633 调用点 |
| 「平台静态解析致 if 内 def 不被识别」 | ❌ 已被 §六 最小复现推翻 | 真实片段＋桩 ⇒ 覆盖生效 |
| 「`target_orig` 被 strict 覆盖后应拒单，但 rejects=0」 | ❌ `target_orig` 只在 `order_target_value` 的 `_delta<=0` 分支被调用 ⇒ **该分支从未进入** | 同上 |

**交叉验证（拆单形态）**：512890 买 **59,400 股**被拆成 **2 × 29,700**（等分）。
`order` 数量版拆单 = 按股数等分：`k = ceil(59,400/49,000) = 2` ⇒ `per = 29,700` ✅ **完全吻合**。
⚠️ 而我此前按**金额**路径推算（`73,477.80/1.237/49,000`）也得到 29,700 —— **两条路径恰好同值，掩盖了差异**（这是本轮最危险的误判来源）。
