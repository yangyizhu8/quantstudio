## 三、决定性对照（原故障路径复现 + 修复验证）

从**四象限产物的实际源码**抽取 `_qs_data_proxy` / `_QSDataProxy` / `_QSDataItem` / `normalize_security_code` / `safe_float` / `get_market_price`，用代理实测：

```
safe_float(1.777)                        = 1.777
[正向]  get_market_price('512890.SS', proxy) = 1.777  → FIXED
[对照]  get_market_price('512890.SS', None)  = 0.0    → 旧缺陷复现（data=None ⇒ 整轮中止）
[对照]  get_market_price(无价标的, proxy)     = 0.0    → 与旧行为同构回落（不引入新行为）
```

**三条同时成立**才构成验收价值：正向证明修复有效、第一条负向证明测试确实打到故障路径、第二条负向证明修复不改变降级语义。

> 取证过程中的一次**假信号**（已证伪，记录以免后人重踩）：初次复验时 `safe_float` 恒返 0.0，误以为 A 未修好；真因是抽取沙箱缺 `np`（numpy）——`safe_float` 内 `np.isnan` 抛 NameError 后走 `except → default_value`。**沙箱缺依赖会静默产出 0.0 假结论**，故此类复验必须同时打印依赖函数的直接读数（`safe_float(1.777)=1.777`）作为沙箱自检。

## 四、实施中的两处**设计调整**（与①方案的差异，如实申报）

1. **D 的落点简化（降风险）**：①方案原设计为改造 MOUNT 结构（新增 `_deploy_daily_entry` + `equiv` 形态一′），风险高。实施改为**复用 PERSIST 钩子**：`after_trading_end` 落盘时把 `qs_cur_orders` 滚动进 `qs_prev_orders`，护栏在下次执行的首次下单前消费并清空 ⇒ 天然「每日一次」，且**零 MOUNT 结构改动、零 equiv 新形态**。撤单开关 `guards.cancel_stale_orders` 默认 `false`（不可逆动作留用户闸门），关闭时滚动块整体不注入（不留无人消费的死状态）。
2. **E′ 纳入本批（范围外新增）**：③实施开工核查时发现幂等台账跨日锁死（P0，次日全量下单被拦），比 A 更致命。按铁律 08「框架问题立即解决」当场修复并纳入本批，**未挂账**。

## 五、已知边界与遗留

- **收敛判据的中间态**：`tests/test_deploy_closedloop.py` 的收敛检查要求「末轮 N=0」。轮 16 记录 N=5（本批发现的 5 项），故在轮 17 验收登记前该检查必然 FAIL——这是**判据按设计在报告真相**（当前轮未闭合），不是代码回归。轮 17（验收轮，N=0）登记后恢复 PASS。
- **`--no-smoke` 口径**：三策略重导用 `--no-smoke`（`status=PARTIAL`，`source_import=api_portability=PASS`）。smoke 是回测冒烟层，与本批部署转换层无关；产物已落盘且 deploy 全 PASS。
- **撤单未开启**：D 的自动撤单默认关闭，需用户显式开启（`guards.cancel_stale_orders: true`）。**呈批前提已订正**（2026-11-06 03:1x）：原「待 2026-11-03 14:50 复跑后按实际挂单情况呈批」的时点前提已失效（该日运行结果未回传，且本机不可取证——见下条）；现前提改为「**取得平台侧【委托】表中含未终态挂单的交易日证据后**」再单独呈批，判据＝①存在真未成交挂单（终端委托状态非 5/6/8/9）②护栏 `陈旧挂单巡检` 告警行可见 ③用户明确同意开启；三者齐备才呈批，**未取得挂单证据前不呈批、不默认开启**。
- **PTrade 日终是否自动撤单**（B-2）：未取证，候用户侧查证回填；不影响本批结论（D 的告警在两种情形下都有价值）。
- **E（运行周期错误）**：策略自检常量 15:00 与挂载时点 14:50 的表述差异，不影响下单；框架无可靠手段识别「哪个字面量是调度自检时点」⇒ 零越权，登记待专门轮次以「档位时点暴露为模块级常量」消歧。
- **`source_import.py` wrapper 覆盖率**：`wrapper_hash` 覆盖面**不含** `_QS_ORDER_SPLIT_EXT`（本次改动的模板），故 `wrapper_hash` 未变（`7a424f397983` 前后一致）；`--reverify` 仅更新了 QMT 复证日期。该事实已核对，非漏追认。
- **★ E′ 验证时点订正（2026-11-06 01:5x，产物代码级复核）**：④/⑤ 阶段预登记的「**11-04 次日首单不被拦**」**不成立为可靠验证点**——E′ 的拦截只在「**当天存在下单尝试**」时才可能被触达，而三策略的实际下单日面并不覆盖 11-04：

  | 策略 | 下单面（产物代码依据） | 11-04 是否会尝试下单 |
  |---|---|---|
  | 四象限ETF轮动 | 月度首个交易日调仓（`ETF_f926a7_trade.py` L1461 `g.last_rebalance_month != current_month`）＋ **每日**单标的止损（L1508 → L1408 `submit_target_amount(security, 0, …)`）＋ 组合回撤风控再平衡（L1495–1505） | **条件可达**：仅当某标的跌幅 >5% 或组合回撤 >5% 才触发 |
  | F-Score选股RSRS择时 | **仅**月度首个交易日（L2163 `g.last_rebalance_month != month`；L2164 回写） | **不可达** |
  | 全球资产轮动 | **仅**首次建仓（L1139 `if not g.strategy_started`）＋ **126 策略日**动态调仓（L1200–1206 `should_dynamic_rebalance`） | **不可达** |

  **判别力附加条件**：即使 11-04 四象限触发止损卖出，也**未必能证伪 E′**——幂等台账键为 `(security, side)`，若 11-03 是**买入**、11-04 是**止损卖出**，方向不同 ⇒ 天然不碰撞 ⇒ 即便修复失效也不会被拦 ⇒ **假通过**。

  ⇒ **可靠验证点订正为「下一个必然下单且存在同标的同方向碰撞的交易日」= 2026-12-01**（12 月首个交易日，四象限/F-Score 必调仓）。判据精确为：**12-01 首笔委托中，是否出现「11-03 已用过的同标的同方向」组合**；若该组合不存在，则该次验证**不具判别力**，须另找碰撞样本，不得以「未出现拦截」判 PASS。
  机理侧已由 23 用例（E′ 语义）＋ 三产物恢复后 `g.state['orders_done'] = []`（`strat_0c202b` L1093／`ETF_f926a7` L1426／`F-Score_RSRS_149655` L2100）覆盖；平台侧验证点随之顺延至 **12-01**，不再是 11-04。
- **★ 加速替代路径（已备案·2026-11-06 02:2x，总调度采信后登记）**：不必等到 12-01，**提前取得有判别力的 E′ 平台侧证据**有两条路径——**甲（确定性下单日）**：构造一个**必然发生下单尝试**的交易日（四象限路径：某标的单日跌幅 >5% 触发 `check_single_stop_loss` 卖出，或组合回撤 >5% 触发 `risk_rebalance_pending` 再平衡；或直接取四象限/F-Score 的**月度首个交易日**），使「有下单尝试」这一前提成立；**乙（碰撞样本前置核验）**：在取该日证据**之前**，先从平台【委托】表确认 11-03 存在**与该日将下单标的同方向**的委托（幂等台账键为 `(security, side)`），否则该日证据**不具判别力**，只能记「未观测到拦截」而**不得判 PASS**。两条路径须**同时满足**方成立（甲保证有事件，乙保证事件会撞上未清空的台账）。
- **模拟盘下单语义核对（本线无待改项·2026-11-06）**：按用户 2026-11-06 纠正口径（「暂缓转 live」仅暂缓**实盘真实资金下单**；**模拟盘下单从未暂缓**；模拟盘＝委托真正打进**账户**可见委托/成交痕迹，模拟盘→实盘是「换账号+权限」而非「换代码」），本线三产物的模拟盘语义**已符合**：产物部署于 PTrade 模拟盘（国金 PBOX UAT，账户 `99005258`），委托由**券商平台**受理并可在其【委托】/【普通持仓】表查到真实委托号与成交痕迹（2026-11-02 实测：PTrade 委托表已见 9 标的拆单委托号、持仓表非空）——**不存在**「内部撮合替身」类实现，故该口径纠正**不要求本线任何改动**；本线 11-03 14:50 的预期亦据此为「平台侧应出现真实委托/成交痕迹」，而非内部回放记录。
- **11-03 平台侧运行痕迹不可本地取证（如实申报）**：本机 PTrade 客户端 `D:\Ptrade\ptrade_UAT` 当日日志止于 **09:49:53**（`OnClosed 客户端程序退出`；此前 09:02 一次登录 400 错误、09:47–09:49 量化界面弹框），`Users/` 下**无任何 `*_state.pkl`**（无 `after_trading_end` 落盘）；用户回传的初始化日志时点为 **09:56–09:57**（晚于本客户端退出 7 分钟）⇒ 策略运行于**券商服务器侧**（日志含「当前服务器配置为…执行拉起本交易操作」），本机客户端开合**不影响** 14:50 触发。⇒ **本机两侧证据均不能判定 11-03 14:50 是否真跑过**（本机无痕迹 ≠ 未跑），平台侧取证仍须用户回传。
