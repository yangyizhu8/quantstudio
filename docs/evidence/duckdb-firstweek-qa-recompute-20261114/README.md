### 1.1 关键更正（我方上一轮表述有误，此处更正）

> **`qa_failed_count` 是「命中行数」，不是「命中文件数」。**
> 源码 L136 记录的是 `文件名:行号`，L144 取 `len(qa_hits)` ⇒ 单位是**行**。
> 本批数据中「命中行数 144 = 命中文件数 144」**恰好相等**（每个命中文件只有 1 行命中），
> 但这是**本批数据的巧合**，**不能**据此把该指标定义成文件数。我方上一轮把它写成「8 个命中文件」、
> 并把「51→8」解释成「他线修复见效」，均为**口径误述**，此处更正。

### 1.2 抽样时点声明（重要限定）

观测记录是**每日抽样时点**（11-08 有 5 行，11-09 有 3 行，11-10 有 2 行，11-11～14 各 1 行，合计 14 行）。
⇒ **14 条记录 ≠ 11-14 全天已过；也不等于全周各时段无故障。**
本包所有「0 命中」结论，适用范围**严格限定为**「已落盘日志文件中的实测」，不外推到未落盘时段。

- **首周窗口（11-08～11-14）**：日志 **49** 个，命中文件 **0**，命中行 **0**。
- **首周窗口之前（≤11-07）**：命中行 **144**（全部）。

### 3.3 机制说明（为什么「51→8」会单调下降）

`qa_failed_count` 的**分母是「mtime 最新 60 个日志」**（滑动），分子是这 60 个里的命中行数。
随时间推移新日志产生，11-01／11-07 那批老命中文档**逐个滑出 60 名之外**，计数**自然下降**，
**与「缺陷是否已修复」无因果关系**。

⇒ 该指标可用于「**当前是否仍在发生**」，**不可**用于「**历史是否已修复**」或「他线是否在收敛」。

## 四、本包**不**能证明的事（防越界引用）

1. **不能**证明「全周无故障」——只覆盖已落盘日志；未落盘/被轮转删除的时段与文件不在覆盖内。
2. **不能**证明「11-14 全天无故障」——11-14 只有 07:30:31 一个抽样时点；本包生成于当日下午，**当日尚未结束**。
3. **不能**证明「他线已修复」——只能说明「首周已落盘日志中无该关键词命中」。
4. **不能**因某项 0 命中而改判整体 PASS。脚本 `verdict` 现为 **FAIL / exit_code=1**（判据代码本轮**未改**，
   无授权改），且 FAIL 由**多项 ✗** 构成（见 `output-verdict.txt`：`daemon_absence_excused`／`no_qa_failure`／`once_running`）。
   **三项输出各自独立**：全量归桶 0 命中 ≠ top60 分母无问题 ≠ 脚本判定通过。
5. **不能**推断缺席时段内「绝无其他实例」——见 §5。
6. **不能**把 `daemon_absence_excused` / `once_running` 的 False 读作「发生了缺陷」——
   二者是**观测项**（记录「豁免是否命中」「此刻是否有 once 轮在跑」），却被现行 `all(checks.values())` 并入判定，
   属**判据设计问题**，已另出六步方案件 `docs/handoff/duckdb-obs-checks-verdict-design-20261114.md`（**未过②审不改脚本**）。

## 五、供血缺席段的证据分级（应审核要求修正）

审核指出：**缺席时长需区分实际 START／EXIT 与最后活动线索；相邻记录不足以证明中间绝无其他实例。**
据此把此前「6 段缺席 ≈28h」的说法降级重述：

| 级别 | 含义 | 本窗口对应证据 |
|---|---|---|
| **A 级（双端实证）** | 有 `START` 行 + 对应 `EXIT` 行，间隔即确证在位 | 38020 01:11:01→01:12:41｜36788 15:13:06→15:58:19｜36372 →11-12 04:12:15｜35108 →11-12 14:10:18｜53244 11-12 18:30:02→11-13 16:06:17｜39200 11-13 22:57:41→当前 |
| **B 级（仅 START 无 EXIT）** | 有 `START`，EXIT 记 `UNKNOWN(lost)`（wrapper 同时消失） | 25852 11-10 21:17:46｜32000 11-10 22:35:57｜50560 11-12 17:29:11｜38660 / 41964（各 3 分钟内 exit 1） |
| **C 级（仅读数线索）** | 只有日表进程读数，`daemon_exitcode.log` **无对应行** | 44904（11-08 15:58 读数）、34512（11-09 07:31 读数）、49060（11-10 07:31 读数）、468（11-10 00:22 前） |
| **D 级（推断，非实证）** | 两个已记录事件之间的**间隔** | 例：11-13 16:06:17 EXIT → 22:57:41 START 的 6h51m |

> **D 级只是「相邻已记录事件之间的间隔」**：`daemon_exitcode.log` 存在**有进程无日志行**的情况（C 级已证实），
> 因此**不能**据此断言该间隔内「绝无任何实例运行」。此前表述「缺席 6 段 ≈28h」应降级为
> 「**A/B 级可确证的在位区间之外，存在至少 6 段已记录空档；空档内的实际供血状态未经证实**」。
