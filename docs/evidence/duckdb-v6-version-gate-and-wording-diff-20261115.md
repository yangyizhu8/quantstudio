## 一、版本门：改动前 → 改动后

### 1.1 行为对照表

| 情形 | **改动前（第四轮）** | **改动后（第五轮）** | 变化性质 |
|---|---|---|---|
| 版本 + `source_id` 一致，内容一致 | `RESTORE-EQUIV: OK`，exit=0 | 同（不变） | 无 |
| **版本不一致，探针相同** | **`RESTORE-EQUIV: OK`，exit=0**（仅打印一行 note） | **`CROSS-VERSION-INCOMPARABLE`，exit=5，不输出 OK** | 🔴 **判据收严** |
| 版本一致，`source_id` 不同 | 未单独判（仅比版本号） | 与版本不同同处理 ⇒ exit=5 | 🟠 补漏 |
| 探针不一致 | `HASH-SEMANTICS-DIFFER`，exit=4 | 同（不变） | 无 |
| 同版本内容不一致 | `MISMATCH`，exit=1 | 同（不变） | 无 |

### 1.2 exit 码定义（改后完整）

| exit | 含义 | 是否构成「恢复验证通过」 |
|---|---|---|
| `0` | 同版本链 + 七面全一致 | ✅ **是（唯一）** |
| `1` | 同版本链 + 存在不一致 | ❌ 否（MISMATCH） |
| `3` | 基线文件缺失 | ❌ 否 |
| `4` | `hash_probe` 不一致（hash 语义不同） | ❌ 否（拒比） |
| **`5`** | **跨版本（version 或 source_id 不同）** | ❌ **否（本次新增：不判成功）** |

### 1.3 `hash_probe` 的角色变更

| | 第四轮 | 第五轮 |
|---|---|---|
| 作用 | **拒比 + 放行**（相同即视为语义相同并放行） | **仅拒比** |
| 依据 | 「探针相同 ⇒ hash 语义同 ⇒ 可跨版本比」 | **已推翻**：3 个常量表达式相同只说明它们碰巧一致，**不足以**证明全类型同语义 |
| 实现 | `if probe differs: exit 4` 否则继续给 OK | `if version/source_id differs: exit 5`（先于任何成功判据）；`if probe differs: exit 4` |

### 1.4 实测证据（本机同时装 1.4.5 与 1.5.6）

```text
同版本链 1.4.5 → 1.4.5
  RESTORE-EQUIV: OK
    scope: schemas=['main'] tables=2
  exit = 0

跨版本 1.4.5 → 1.5.6 （三探针完全相同、五面摘要完全相同）
  CROSS-VERSION-INCOMPARABLE
     baseline: version=v1.4.5 source_id=f31be57c18
     current : version=v1.5.6 source_id=069cc9f9b5
     hash_probe baseline: {'h1': '6075358136372562340', 'h2': '16795888908304218441', 'h3': '4014082151575868669'}
     hash_probe current : {'h1': '6075358136372562340', 'h2': '16795888908304218441', 'h3': '4014082151575868669'}
     -> This is NOT a same-version chain. ... NO success verdict is issued here (exit=5).
     (digests below are printed for reference only, NOT as a pass/fail verdict)
     ref.columns  baseline=0dc99b37...  current=0dc99b37...
     ref.rows     baseline=38a0e839...  current=38a0e839...
     ref.data192  baseline=b821103e...  current=b821103e...
     ref.indexes  baseline=ce6e56f1...  current=ce6e56f1...
     ref.constraints baseline=7df87ecc...  current=7df87ecc...
  exit = 5

同版本 1.5.6 删一行
  RESTORE-EQUIV: MISMATCH
     x ROWS [main.stock_daily]: 1 != 2
     x CONTENT [main.stock_daily] digest differs
  exit = 1
```

> **第 2 段是本次退修的核心**：探针相同、五面摘要也相同，**仍然 exit=5 不给成功**。

## 二、措辞差异：撤回与保留

### 2.1 🔴 撤回的表述（原文 → 处置）

| # | 撤回的原文（第四轮） | 处置 | 撤回理由（已写入通知） |
|---|---|---|---|
| 1 | 「三路独立盐 ⇒ **192 位**求和」 | **删除** | `hash(x)` 与 `hash(x,'S2')`/`('S3')` 是**同一次调用的不同参数形式**，**无依据证明相互独立**；据此推算位宽属**无依据外推** |
| 2 | 「生日界意义上，随机碰撞期望约 **2^96 个（行对）**」 | **删除** | 同上（位宽前提不成立，生日界随之不成立） |
| 3 | 「三路盐把**构造代价**抬到 ~**2^96** 量级」 | **删除** | 同上 |
| 4 | 判据表 E 面标题「逐表内容一致（**192 位**）」 | 改为「逐表内容一致（**工程摘要**）」 | 不主张三盐独立 |
| 5 | 「三路**独立盐**」（口径表/正文多处） | 改为「三次调用 / 分别比对，**不主张三者独立**」 | 同上 |

### 2.2 ✅ 保留且可复核的表述（均为实测）

| # | 保留内容 | 实测依据 |
|---|---|---|
| 1 | 用 `sum` **非** `bit_xor` ⇒ **对行重复敏感** | 3 行 vs 同 3 行+1 重复 ⇒ 摘要**不等**；XOR 在成对重复下**相互抵消** |
| 2 | `HUGEINT` 累加器**不溢出** | 实测 3×(2^64−1)=`55340232221128654845` 正确；62 GB 按 6.2 亿行外推上界 ≈`2^93` < `2^127` |
| 3 | 聚合**顺序无关**（集合语义） | 同表乱序插入 ⇒ 摘要相等 |
| 4 | **七面覆盖**（schema集/表集/列/行数/内容/索引/约束） | 9 个逐面注入用例「只报该面、不串面」 |
| 5 | 索引与约束**分视图取** | `PRIMARY KEY` **只在 `duckdb_constraints()`**；普通 `CREATE INDEX` **只在 `duckdb_indexes()`** |
| 6 | `duckdb_constraints()` 同一 `NOT NULL` 可能**多行重复** | 实测 `s1.a` 两条 `NOT NULL` ⇒ 整体排序比对、**不去重** |

### 2.3 定位变更

| | 第四轮 | 第五轮 |
|---|---|---|
| 摘要定位 | 隐含「有强度保障的完整性摘要」 | **工程摘要**：发现意外损坏/漏拷/错配/少行多行；**不提供密码学或概率强度保证**；**不用于对抗蓄意伪造** |
| 三盐好处 | 「独立性 ⇒ 192 位强度」 | 「**经验性冗余**」——单盐下偶然同和时多一层区分机会，**不是可量化安全强度** |

## 三、全文件 SHA 的正确定位（新增）

| 手段 | 证明什么 | **抓不到什么** |
|---|---|---|
| 全文件 `Get-FileHash`（源 vs 副本） | **物理字节一致**（拷贝忠实） | **WAL 未重放 ⇒ 字节一致但打开后少数据**（v5 缺陷正是如此）；任何打开期逻辑转换 |
| 七面比对（默认） | 打开后**逻辑内容**七面一致 | 主库中间区域字节被改但逻辑不可见；物理布局差异 |

> **结论**：两者**互不替代**。默认做七面比对，全文件 SHA 作**可选加强**；要两者都覆盖须**同时做**。
