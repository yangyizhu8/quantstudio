## 七、⑧ 综合推断（**推断级，非逐列实测定论**）

**基于上述六项实测事实的推断**：

1. 库内 11-09 / 11-10 的 bar 在 **10:49 之后被 UPDATE 覆盖**（`update_time` 是今天）；
   UPDATE 会把 `update_time` 改写为当前值 ⇒ 覆盖前的旧 `update_time` 不可见。
2. 覆盖前，库内这两天的数据是**较早写入的版本**（更早的采集轮次）。
3. fresh（QuestDB ≡ MCP）侧这两天的数据是**上游修正后的版本**。
4. 两者逐位不同 ⇒ `MinuteDiff` 判 100% changed **是正确的**（不是误判）。
5. ⇒ **这 266 万行 UPDATE 是「必要的重算」，不是「无效写」。**

**⇒ 这与铁律 25「上游可变因子持续微调 ⇒ 库内值 = 写入时上游量的产物」完全一致。**

**⇒ 因此：「优化掉这 266 万行」的设想**不成立**——它们必须写。**
