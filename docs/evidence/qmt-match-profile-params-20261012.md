## 1. 根本事实：QMT 无「回测撮合参数」文档概念

大 QMT（迅投客户端内置 Python）是**实盘/模拟盘交易终端**：`passorder` 为实盘下单接口，费率由券商柜台配置、成交由交易所撮合——**文档不存在「回测撮合参数」章节**（Context7 + 本地形态库 16 文件核）。因此 `match_profile: qmt` 的本质 = **本地引擎模拟 QMT 实盘成交的假设集**，参数值来源分三类路径定谳（下表双列证据链）。

## 3. 引擎参数映射（match_profile: qmt 取值方案）

本地引擎现行参数（`backtest_engine.py:326-391` 撮合口径区）：

| 引擎参数 | ptrade 缺省（现行） | qmt 提议值 | 依据 |
|---|---|---|---|
| `match_price_mode` | close（现行默认） | `next_open` 或按策略声明不变（成交价口径由 #1 最新价原则映射：信号日次日执行=以执行时点最新价近似） | A 类 #1 |
| `stamp_tax`（如引擎有此参数位） | 现行值 | 卖出 0.5‰ | B 类 #2 |
| `transfer_fee` | 现行值 | 双边 0.001% | B 类 #3 |
| `commission_rate` | 现行值 | **候反推**（临时用账户合同值或复测定谳） | C 类 #4 |
| `slippage` | 现行值 | **候反推** | C 类 #5 |

> 注：具体参数位名与单位以引擎实施轮代码现状为准（本表为口径层定谳，实施轮对齐参数名）。
