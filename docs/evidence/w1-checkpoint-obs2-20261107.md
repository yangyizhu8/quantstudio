## 三、【P0】根因升级：etf_daily 的 DuckDB ART 索引损坏

**首个 fatal（06:03:11）**：

```
ERROR [mcp_etf_daily_mcp_20261107_060156_d88e8e] ❌ FAILED[streaming]:
  FATAL Error: Corrupted unique ART index "PRIMARY_etf_daily_0":
  encountered an existing gated leaf in unique index while inserting
```

**完整故障链（本轮最重要结论）**：

```
06:03:11 etf_daily 写入 ⇒ DuckDB 主键唯一索引损坏（PRIMARY_etf_daily_0，existing gated leaf）
   ⇒ database has been invalidated（DuckDB fatal 后进程级句柄整体失效，连带所有连接）
   ⇒ [Watermark] get_last_date 读失败 ⇒ 按无水位处理（return None）      ← W5 仪器捕获 ③b
   ⇒ 判定「无锚点（首次/升级后）」
   ⇒ stock_minutes 退化为「建基线」全量拉取 2026-01-01→2026-11-07
      （≈310 天，全市场分钟级 ≈4.8 亿行量级，代价：小时至数十小时）        ← 最坏后果
   ⇒ 该轮 QFQ post-ingest 异常（水位保持，下轮重试）
   ⇒ 水位永久冻在旧值，每轮重演
```

**⇒ 这是对 W1 呈裁前提的重大修正**：水位冻结在 11-07 这一轮的**直接触发器是索引损坏**（写 etf_daily 必 fatal ⇒ 该轮后续全部写/提交失败），**不是（或不仅是）gate 不提交**。链① W1 针对的是「gate/意图层」，而本轮暴露的是**存储引擎层的索引损坏**——两者是**不同层**的问题，W1 修不了索引损坏。
