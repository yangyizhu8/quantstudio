## 一、点3 先定谳（取数口径）——**我方错误，已定位到具体机制**

### 实测（`2025-06-03` 窗口 `(2025-06-03, 2025-06-04)`）

```
manifest: total_rows=3214  shard_count=1
实际解出 DataFrame 行数 = 3214
唯一 ts_code 数 = 1626          ← 唯一码数只有 1,626（而非 3,214）
trade_date 取值数 = 2           ← 【根因】两个交易日都在样本内
时间范围 = 2025-06-03 ~ 2025-06-04
重复 ts_code 行数 = 1588        ← 每码两行（次日）
代码前缀: 15(967)/51(811)/16(513)/56(352)/50(308)/58(177)/18(44)/52(22)/53(20)
```

**根因**：服务端时间窗为**左闭右开**（`[ts, te)`），我方用 `(D, D+1)` 取当日数据——
这**本身正确**；但统计时**未再按 `trade_date` 过滤**，于是把 `D` 与 `D+1` 两个交易日
的行**合并统计**，导致"n=3,214"（≈2×1,607）。

**修正后**：单日唯一码数 **1,626**（含 09-04 的话各约 1,607）——与云端 **1,600** 吻合
（余差可由退市/停牌/上市未满等口径差解释）。

**连带影响评估（如实披露）**：

| 结论件中引用 | 是否受影响 | 说明 |
|---|---|---|
| §3.2 单码三点对照（159327） | **不受影响** | 单码按 `bare` 精确取值，与样本量无关 |
| §3.3 两表 amount/vol 对照 | **不受影响** | 同上（同码同日单点） |
| §3.5 跨表 close 比值分布（82.36%，2,347 码） | **口径需标注** | 该统计是**按码 join 后**的数量（各码取当日 15:00 bar），非 manifest 行数；数值本身自洽，但**样本口径表述失准** |
| §3.4 全市场 `close/(amount/vol)` 中位 = 10.0005 | **需重述样本口径** | 见 §三（该值含次日行；但两日比值同量级，中位数结论方向不变） |

## 二、点2 容差口径差（96.75% vs 82.36%）——**两数均自洽，我方未标注口径**

### 复核实测（同一比值序列，不同容差）

```
可比码数 = 1446（按码 join 后）
容差 ±0.1% → 49.9308%     容差 ±0.5% → 63.9696%
容差 ±1.0% → 79.0456%     容差 ±2.0% → 88.7967%
容差 ±5.0% → 94.3983%
比值分布: P1=0.3324  P5=0.9654  P50=1.0000  P95=1.0027  P99=1.1310
```

**解释（可代数核对）**：同一分布下容差放宽必然单调抬升命中率——
±1% → 79.05%、±5% → 94.40%，与云端 **96.75%（±5%）** 同量级；
差值（94.40% vs 96.75%）可由**样本口径不同**解释（云端 1,600 码口径；我方 join 后 1,446 码，
且分布含 P1=0.3324 的**分裂子集**拉低）。

**我方疏失**：结论件 §3.5 只写了「≈1(±1%) = 82.36%」，**未标注**：
① 容差取值；② 样本为 join 后码数（非单日全市场行数）；③ 分布含 P1=0.3324 的子集。
⇒ **已按本件修正口径表述**：后续引用一律带三元标注（容差 / 样本口径 / 子集说明）。

**附带核对（我方主动复算）**：两表 `adj_factor` 数值精度不同（云端 3 位小数）⇒
严格 `==` 比较**低估**一致率；改为「相对差 < 0.1% 视为一致」后一致率 = **99.31%**
（先前报的 87.55%~89.69% 系严格相等口径）。此项同样属**口径标注缺失**，一并修正。

## 三、点1 「~10×」被单位差证伪——**接受，我方"口径分裂"定性过强**

### 复核实测

```
日表全样本 close/(amount/vol): 中位 = 10.000455   std = 1.256755   变异系数 = 12.57%
分位: P1 = 3.3338   P25 = 9.9822   P50 = 10.0005   P75 = 10.0165   P99 = 10.1043
```

**判读**：
- P25~P75 = **9.9822~10.0165**（极窄）⇒ **~10× 的常数性成立**，与"单位换算"解释一致
  （云端 `amount` 与 `close×vol` 之间存在**固定 10 倍**的换算关系，属**单位口径**而非数据错误）；
- 但 P1 = **3.3338** 且 159327 实测 **3.3445（= 10/3）** ⇒ 存在**偏离 10 倍的子集**
  （与云端指出的「分钟表 r² 双重复权 + B 类混存」方向一致）。

### 结论修正（原 → 现）

| 项 | 原结论（勘误前） | 修正后结论（勘误） |
|---|---|---|
| ~10× 的性质 | 「系统性**口径分裂**」 | **主要是单位换算**（常数 10 倍，P25~P75 窄至 0.03%）——**非口径分裂** |
| 真实缺陷 | 未识别 | **分钟表 r² 双重复权 + B 类混存**（云端定位，归**生产端**）；日表侧存在偏离 10 倍的子集（P1=3.33，159327 实测 10/3），与之一致 |
| 客户端还原链 | 「输入口径不可信」 | **维持**（该结论不依赖 ~10× 定性：tdx 外部基准已判分钟表 close ÷ tdx ≈ 0.3325） |
| 本项闭环路径 | 需上游澄清口径 | **维持**，且已升级为「**已响应 · 修复派单 Trae（生产端）**」 |

**我方定性错误的自查**：
1. 把「常数 10 倍」误读为"数据错误/口径分裂"——**漏了"先检验常数性（变异系数）再定性"**这一步；
   （本件 §三 的变异系数 12.57% 拆开看：主体在 9.98~10.02 内，离群子集拉高了总变异——
   正确做法是**先看分位数窄度**，再判是否常数。）
2. 把「分钟表 ÷ tdx ≈ 0.3325」的偏离，直接归因到"两表口径分裂"，
   而未区分「单位换算（可解释）」与「双重复权（真缺陷）」两类成因。

**纠正措施**：后续凡涉"倍数异常"的定性，必须先做**常数性检验**（分位数窄度 + 变异系数 +
离群子集分离），再区分「单位/换算类」与「逻辑/缺陷类」——已作为方法论补记。
