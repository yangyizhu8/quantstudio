## 5. 实测暴露并已修复的两个缺陷（如实披露）

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | **PS 5.1 `-File` 调用且路径含中文时 `$PSScriptRoot` 为空** ⇒ `-KitDir` 参数绑定空串报错（安装器直接失败） | 阻断安装 | 安装器改双回退（`$PSScriptRoot` → `$MyInvocation.MyCommand.Path`）＋KIT_VERSION 存在性校验＋显式报错提示 `-KitDir` |
| 2 | **接入清单阶段顺序缺陷**：原「先建库后装机检」，但 `kb_draft.py` 需 scripts/ 已就位 | 首次接入卡壳 | 清单与 kit README 增「**顺序提示**」：先 `install.ps1 -NoHook` 拿脚本 → 建库 → 装钩子/CI |
| 3 | （加固）安装器原会无脑设 `core.hooksPath=.githooks`，**husky/lefthook 仓会被废掉既有钩子** | 破坏性 | 安装器检测既有 hooksPath：非 `.githooks` ⇒ **WARN 跳过并给手动接入片段**；写 `.githooks/pre-push` 前**自动备份** |

## 6. 边界与风险（如实）

1. **复制分叉**：kb-kit 副本各自演进；`KIT_VERSION`＋`-Sync -CanonicalRepo` 管理，schema 三字段与问法口径以主仓 `docs/templates/kb-entry-schema-v1.md` 为准；
2. **安装器仅 PowerShell**：Linux/macOS 项目需手抄（scripts 为纯 Python 可直接用），bash 版列为后续；
3. **试点 2 无种子条目**：`kb_hook` 现体检 0 件（正常跳过）——首月 R/B/H 需其线先沉种子条目，本批不代编；
4. **CI 为可选**：两个试点均未装 workflow（`-InstallCI` 未用）；M3 模板已随 kit 分发；
5. 试点项目均为**未提交**状态（其 git 工作树新增未跟踪/已改文件），提交权归各线。
