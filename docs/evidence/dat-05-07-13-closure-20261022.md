## 一、DAT-05 日期边界 —— **已锚定**

`get_history`（`ptrade_api.py:1486-1488`）签名与边界行为（逐条实勘）：

| 行为 | 实现 | 语义 |
| --- | --- | --- |
| 双签名兼容 | `:1500` `if isinstance(security, int):` ⇒ **第一位置参数为 int 即「count-first」模式**（PTrade 官方签名） | security-first / count-first 均可 |
| `security=None` | `:1517-1518` `return pd.DataFrame()` | **返回空 DataFrame，不抛异常** |
| `count=None` | `:1519-1520` `count = 20` | 默认 **20 行** |
| **行数不足** | `:1470` `frame = frame.tail(int(count)).copy()`；`:1607` `sliced[...].tail(count)` | **取最后 count 行；实际不足时如实返回实际行数——不凑数、不报错、不补 NaN 行** |
| 时点锚定 | 默认 `include=False`（`:1488`） | 末行为 **D-1**（E1 铁律；与 DAT-03 一致） |
| 缓存 | `:1528-1532` 当日同参缓存 | 同参同日只查一次 |

⇒ **边界结论**：`tail(count)` 语义 + 不足如实返回 ⇒ **末行锚定、首行随可用行数浮动**；调用方不得假设「恰好 count 行」。

## 二、DAT-07 fallback 链 —— **已锚定（链路实名）**

| 层 | 位置 | 事实 |
| --- | --- | --- |
| **装配点** | `providers/base.py:245-248` | `calendar = DuckDBCalendarProvider(db_path)` → `market = DuckDBMarketDataProvider(db_path, calendar_provider=calendar)` → `cls(market, DuckDBFundamentalDataProvider(db_path), DuckDBReferenceDataProvider(db_path), calendar)` |
| **结论** | — | **单一数据源（DuckDB）四件装配，无多源降级链**；顺序＝Calendar → Market（持有 calendar）→ Fundamental → Reference |
| 引擎侧 | `backtest_engine.py:436` `self._providers = providers` | 引擎**只接收注入**，内部无 fallback 链 |
| 数据根级 fallback | `backtest_engine.py:40` | configured / environment data roots 作为**部署 fallback** |
| 静默边界守卫 | `fidelity_config.py:11` | **禁止静默单端 fallback**——须显性报错或降级 + WARNING |
| 跨源对照 | `calibration.py:10`／`fidelity_compare.py` | 走对照工具，不靠运行时降级（归 DAT-15） |

⇒ **「fallback 链」在本仓不是多源链，而是「单源 + 数据根兜底 + 静默禁止守卫」**。登记为已锚定，**不以"没有 fallback"冒充"未实现"**——这是设计事实。

## 三、DAT-13 字段缺失三态 —— **已排查（规律在案、未成文统一）**

先排除误判：先前 grep 到的 `return None` / `return ''` **全部属内部私有助手**
（`_build_code_index`／`_engine`／`_engine_account`／`_qs_normalize_date_arg`／`_qs_record_trade_day`），**不是公开 API 契约**。

按**公开面**重判，三态规律如下：

| 返回形态 | 公开 API 例 | 缺数据时返回 |
| --- | --- | --- |
| **集合型** | `get_trades()`／`get_open_orders()` | **空列表 `[]`**（`ptrade_api.py:2654-2658`：无 `_today_trades` 即 `[]`） |
| " | `get_history(security=None)` | **空 DataFrame**（`:1517-1518`） |
| **单值对象** | `get_position(code)` 未命中 | **零视图**（`amount=0` 的 Position 对象，非 None）——QD-2026-0009 §④ 契约 |
| " | `get_order(order_id)` | **`None`**（`ptrade_api.py:2645` 前，close/open 模式直接 `return None`） |
| **字符串型** | 日期类字段（QMT 侧实测 `m_strOpenDate=''`） | **空串 `''`**（POS-17 已登记"判空须 `not v` 不能 `is None`"） |

**🔴 已登记的实质不对称**：同为"查不到"，`get_position` 给**零视图**、`get_order` 给 **`None`**。
- 这不是 bug：`get_position` 的零视图是**有意设计**（策略惯写 `get_position(c).amount == 0` 判空仓），`get_order` 的 `None` 复刻平台 close/open 分支；
- 但**两者规则未成文统一**，且**未像 QD-2026-0008 ②条**（"空串≠None"）那样固件化 ⇒ 故记 **已排查**而非已锚定。

**待补（下轮，纯本地）**：把「集合→空容器／单值对象→零视图或 None／字符串→空串」写成一条**成文契约**（可落 `knowledge/contracts/data-caliber.md`），并在 portability 侧加一条提示（与 POS 7 字段 WARN 同批更经济）。
