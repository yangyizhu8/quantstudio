## 1. 方案简式（①）

**问题**：P2-b 的 KB 体检以内联 python 形式嵌在 prepush-gate 中，族规则硬编码（PD_ENUM + 分支判断）；
kb_draft 硬绑 `knowledge/qmt` 与 QMT 六枚举。⇒ 无法复制到新项目，也无法容纳 PD 九枚举族。

**设计（两轴分离）**：
- `kb-info.yaml` 增 `families:` 段（= schema 轴）：`id_pattern / fix_layer_enum / fix_layer_multi /
  domain_vocab / required_fields / fix_layer_keywords(可选) / dir / entry_glob`；
- `registries:` 保留（= 归属轴：owner/scope/lifecycle），一个 registry 可含多族（kb-main 即 qd+pd）；
- 新脚本 `kb_hook.py`：通用体检（读 families → entry_glob 路由 → 族 schema 校验；
  frontmatter 解析复用 `kb_preflight.parse_entry` 单一事实源）；
- `kb_draft.py` 泛化：`--kb <族目录>` + 族定位（families[].dir）→ 枚举校验/编号前缀/判层关键词全由族驱动；
  族未声明判层关键词 ⇒ 必须显式 `--layer`（不跨族猜测）；
- prepush-gate 改为调用 `kb_hook.py`（内联 python 删除）；过滤面放宽为 `knowledge/.+\.md`，由族路由决定体检范围。
- 接入模板包 4 件：kb-info 模板 / 族 README 模板 / 接入清单 / install_kb_hook.ps1。

**影响面**：QD 族行为等价（validate_entry 覆盖的九项检查族化后一一对应）；PD 族由「专用分支」改为
「族 schema 数据」；新增 `--kb`/`--json`/`--strict` 参数不改变默认行为。
**回退**：prepush 内联块可从 git 历史取回（`2aaedd0f` 前版本）；kb-info v2 向下兼容（旧版无 families ⇒
kb_hook 跳过族校验并提示，不报错）。
