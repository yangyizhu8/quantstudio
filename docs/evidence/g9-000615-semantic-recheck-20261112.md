## 一、🔴 先自报一个我自己的 bug（它曾产出 100% 虚假差异）

| 项 | 内容 |

| **根因** | 两侧时间基准不一致：`fresh` 侧用 `Asia/Shanghai`（北京日期），`db` 侧我用了 `utcfromtimestamp`（UTC 日期） |
| **实测依据** | `stock_daily.time=1515513600000`：UTC 解析 = 2018-01-09 16:00（**错**）｜+8h = **2018-01-10 00:00（对，与 mcp `fresh` 的 2018-01-10 / open=10.74 完全吻合）** |
| **修正** | `ms2date()` 加 `CST_OFFSET = 8*3600` ⇒ **库内 `time` 存的是「北京零点」的 epoch-ms** |
| **教训** | **若「独有日期」全部落在同一个星期几，几乎一定是基准错位而非真差异**——这是比逐条比对更快的判据 |
