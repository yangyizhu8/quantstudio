## 三条契约（逐条）

### ① 钩子：wrapper 消费面仅在 handlebar 期可用
- 实测 v3（after_init）：`A1/A2` 全 `RuntimeError('QS-QMT: ContextInfo 尚未注入（init/handlebar 执行前调用了 wrapper）')`
- 平台文档称 after_init「可用于取数」，但**本 wrapper 有 ContextInfo 守卫** ⇒ **以实现为准**
- 正解：探针/消费方在 `handlebar` 期调用

### ② 显式 C：覆盖生命周期壳后必须传 C=C
- 实测 v4（handlebar 但未传 C）：**仍全 RuntimeError**
- 机理：wrapper 公开函数签名 `(…, C=None)`，内部走 `_qs_pick_ctx(None)` 读**模块级 `g`**；
  `g` 由 **wrapper 自己的 init/handlebar 壳**捕获；探针覆盖同名函数 ⇒ 壳不执行 ⇒ `g` 从未注入
- 正解：`get_positions(C=C)` / `get_Ashares(C=C)` / `get_position(code, C=C)`
- v1（`_qs_get_trade_detail(C, 'POSITION')`）之所以成功即因**显式传 C**

### ③ 零视图：判命中须用 amount>0，禁 truthiness
- `get_position`（`source_import_qmt.py:770-779`）：
  `pos = _qs_get_positions(C).get(code)`；`if pos is not None: return pos`；`return _QmtPositionView(code, 0, 0, 0.0)`
- ⇒ 未命中返回**零视图对象**（恒真）⇒ `if get_position(x):` 永远成立
- 实测 v5 因此误得「四种写法全 HIT」；v6 改 `amount>0` 后得真值：`.SH` HIT / `.SS`、`.SZ`、裸码 MISS

### ④ 静默 miss：形态不匹配 → 零视图 → 误判空仓
- 端测：`get_position('510360.SS')` 返回 `amount=0.0`（该标的实有 26900 股）
- 策略若写 `if get_position(code).amount == 0: 买入(...)` ⇒ **重复买入**
- 端内通常不触发（策略码来自 `get_Ashares()`，形态 `.SH/.SZ` 自洽）；风险在**硬编码字面量/跨端复用 PTrade 形态码**

## 影响面

- **探针设计**：v3/v4/v5 三次失败全部源于①②③ ⇒ 后续探针必须遵守三条规则
- **策略消费**：④ 仅在硬编码形态时暴露；已定位的精确键消费方（`SG-MS-PEG-HL:491/557/595`、`四象限:306/797/1171`、`tech_etf_mvo:395`、`周频:344`）——其中 `周频:344` 用 `code not in get_positions()` 属**成员测试**（不走 get_position 归一）⇒ 若 code 形态错则直接进入建仓分支，**风险更高**
