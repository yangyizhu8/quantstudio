## 1. 方案简式（①）

**问题**：机检只有「推送前」（pre-push kb_hook）一道，远端无卡点——他人/他机推送坏条目，本地 hook 拦不到。

**方案**：新增 `.github/workflows/kb-schema.yml`（唯一新增文件）：
- 触发面＝`push/PR` 且 `paths: knowledge/**`（无知识库改动则不跑，零噪声）；
- 取改动条目件（`git diff --name-only BASE..GITHUB_SHA`，BASE 优先取 PR base sha → push before → 零 sha 回退 `HEAD~1`）；
- 调 `scripts/kb_hook.py --files … --json` 分族体检（与本地 pre-push **同一脚本**，单一事实源）；
- **WARN 起步**：job 级 `continue-on-error: true` ⇒ 不合规不阻断；观察一轮后由总调度裁升阻断（删该行 + `--strict`）。

**影响面**：仅新增文件；`contract-gate` / `strategy-contrib-*` 三个既有 workflow 零改动。
**回退**：删除本文件即净（无其他引用）。

### 3.4 关于 `act` 的替代说明（如实）

本机 `bash` 为 **WSL 版**（`C:\Windows\system32\bash.exe`），其路径语义（`/mnt/d/...`）与 GitHub runner（`/home/runner/work/...`）不同，
**不用 WSL 硬跑 workflow**；按照准口径以「YAML 结构机检 + git 命令逐行等价模拟 + kb_hook 同参实跑」替代。

## 4. 已知边界与风险

1. **未在真实 GitHub Actions 上触发过**（本批未推；本地无 act 且 WSL 不适合）——首次真实触发留观察窗，
   若需可在 M4 试点项目上先行验证同样的 workflow 模板。
2. `--files $(cat kb_files.txt)` 依赖**文件名不含空格**（QD-/PD-/XX- 前缀族约定，文件内已加注释）。
3. 零 sha（首推新分支）已回退 `HEAD~1`；若仓库首次提交无父提交则该回退失败——对已有历史仓库不构成风险。
4. `continue-on-error: true` 下失败显示为 neutral（不阻断合并）——正是 WARN 起步语义；升阻断需两项同改（删行 + `--strict`），不可只改其一。
