## §1 目标与范围

**目标**：以**最小用户域负担**取得 QMT 真实环境证据，钉死十四项平台契约，据此：
① 修正产物 wrapper 的实测假定（E1 `[-2]`、财务形态、日历、节拍）；② 关闭 M3.1 段二；
③ 为后续策略 QMT 化提供已验证的 API 语义基线。

**范围**：仅本管线产物的 QMT 真实环境实测；**不含**撮合数值对照的完整对齐（另立）；
不含分钟域（deny 域）。

**关键设计（降低用户域负担）**：十四项中 **11 项可由单一「探针策略」一次性取证**——
用户在 QMT 客户端运行一次探针 → 打印结构化证据 → 回传。**不逐项做实验**。

## §4 用户域操作清单（专呈件 · 批1 成文后单独呈报）

草案骨架（正式件见 `docs/qmt/m5-probe/README-用户操作.md`，批1 产出）：

1. **环境准备**：QMT 客户端登录 → 数据管理 → 补充**财务数据**（M5-14 前提）+ 日线历史；
2. **运行探针**：将 `m5_probe_qmt.py` 放入策略目录 → 以「模型交易/回测」方式运行一次 →
   导出输出日志（含 `QS_M5_PROBE:` 前缀行）；
3. **跑六策略**：六策略 QMT 产物逐个回测（建议窗口 ≥ 1 年，覆盖周频/月频调仓时点）→ 导出
   回测报告 + 订单/持仓明细；
4. **回传**：按 P-3 模板打包回传（**脱敏**：无需真实资金账号，'testS' 占位即可）。

**操作风险提示（写入手册）**：探针为**只读**（不下单）；六策略回测为**回测模式**（非实盘）；
**严禁在实盘账号上运行**。

## §5 验收判据（M5）

1. 探针输出含 `QS_M5_PROBE:` 结构化行，覆盖 §2 的 11 项（缺项须显式 `UNDETERMINED`）；
2. 十四项**逐项判定**（钉死值 / 明确 UNRESOLVED + 原因），无"待验证"悬空；
3. **M5-1 钉死后**：M3.1 段二执行（轨 A 显式声明接入 + 三策略端到端取值正确）→ **合并验收关闭**；
4. 据实测修正的产物假定（E1 末根 bar / 日历 / 节拍）以**框架层改动 + 回归**落地（若需改动，走六步）；
5. 归因表入证据文档；既有回归全绿。

## §6 与 M3.1 段二的衔接（写死）

- **触发**：M5-1 钉死 `get_financial_data` 真实形态后；
- **动作**：`_qs_get_fundamentals` 调用点 `shape=` 改传实测形态（**轨 A 显式声明**）；
- **验收**：三策略消费面（CANSLIM / weekly_smallcap / 周频小市值）端到端取值正确；
- **约束**：若真实形态非既有两形态 → 扩展解析分支 + 回归，**不得放宽 M3.1 段一第①条**（不确定仍保守）；
- **关闭**：结论写入 M5 证据文档 + 回填 M3.1 证据文档 → **合并验收关闭**。
