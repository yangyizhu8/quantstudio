## 一、背景与动机

1. 客户逐月核验实锤：`stock_minutes` **2026-02/03/04/05 四整月缺失**（~9,200 万行），`etf_minutes` 缺 2025-12（客户口径）；备份库与主库逐月覆盖一致——**主库既有历史缺口，非打包引入**。
2. 覆盖申报缺陷定谳：既往报告以 min/max 范围式表述掩蔽中段空洞（**案例十**）→ 本方案全链覆盖申报一律**逐月矩阵**判据（`strftime('%Y-%m')` GROUP BY），禁 min/max、禁"范围连续"表述。
3. 与重出包（20260913，FY2015–17 修复）同窗口推进；用户裁定将技术债提前，借交付窗口一并兑现。
4. **范围基准（令 (a)）**：09-14 07:00 数据会话**全史对账表定稿**为准——"stock 四月 + etf 一月"系 09-13 深夜直查暂定集；07:00 对账表已发现的**月内缺额段（实测示例：某些"✓"月内月度覆盖率 74.9% / 83.9% / 67.6%）必须一并入范围**。对账表定稿即**范围冻结**，冻结后不再扩面（新发现走台账另案）。

## 二、范围与边界

**范围内**：stock_minutes 2026-02~05（暂定集）+ etf_minutes 2025-12 + **07:00 对账表定稿的全部缺额段（含月内缺口）** 的回补、质量闸、v2 终版包。
**范围外**：分钟 ETL 调度批次本体改动（另查登记）；策略线 R5/G3.5（跑 r5_maincopy 副本，零耦合）；9/13 v1 包的数据补发（令 (e) 语义，见 §五）。
**主库写面硬边界**：03:00–05:30 守护任务禁挤占；16:00 ETL 前收尾决策；**写面优先序（令 (c)）**：dev apply（G1 依赖）> 21:00 DailyBackfill > 回补小批次（批间放锁、E-3 可用）。

## 六、D2 部署日影响评估（§2.5，v1.1 新增）

**结论：D2 部署路径零直接依赖 duckdb 写锁，回补与 D2 并行可执行；配套如下。**

1. paper 运行时 = L1（盘后 NDJSON 导出文件）+ L2（TDX 实时）+ L3（MCP 回源），运行期不连 duckdb → 08:45 QMT→09:05 premarket→09:15 常驻链路零冲突；
2. **08:00–09:30 锁净空窗**为硬约束（覆盖 premarket 与早段开盘的任何潜在读库依赖，不赌理论）；
3. **FM（factor-monitor）安排（令 (f)）**：暂停登记 06:00–09:30 → **09:30 自动恢复**（不依赖人工）；恢复后补一次新鲜度核验报；暂停计入 D2 采证，不算异常——域归线调度，随 v1.21 变更节点执行；
4. G3.5 双跑读 r5_maincopy（不同文件，仅磁盘顺序 IO 共享），与 T3 零锁冲突；R5.5 起跑若逢 T3 顺延批（16:30+/次日）→ 经总调度排时序，两线不自行互踩；
5. **后置保险**：起跑门 ② 交易线任何未预见 duckdb 依赖 → T3 全案顺延 D2 收盘后，不需重走审计。
