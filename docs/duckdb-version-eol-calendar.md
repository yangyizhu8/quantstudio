## 三、到期复核的三类触发

| 触发 | 判定方式 | 产出 |
|---|---|---|
| **里程碑到点**（90/60/30） | 守护脚本按日历与当前日期算天数 | 一条待办复核提醒（`--emit`） |
| **上游发布新补丁** | 人工/外部传入 `--patch-note "duckdb 1.5.7 发布"` | 一条待办复核提醒 |
| **缺陷单关闭**（含 `duckdb#23645`） | 同上（`--patch-note "duckdb#23645 closed"`） | 一条待办复核提醒 |

## 四、用法

```bash
# 只读判定（默认日历 = docs/duckdb-version-eol-calendar.json）
python scripts/check_duckdb_eol_guard.py --check

# 模拟指定日期（自测/演练用；不改任何状态）
python scripts/check_duckdb_eol_guard.py --check --as-of 2026-10-18 --json

# 叠加「新补丁/缺陷单关闭」触发，并落一条复核提醒
python scripts/check_duckdb_eol_guard.py --check --patch-note "duckdb#23645 closed" \
    --emit docs/evidence/eol-review-reminder.md
```

**退出码**：`0` = 无到期复核提醒（无事）｜`1` = **有到期复核提醒（需人处理）**｜`2` = 错误（缺日历 / 参数非法 / 日期格式错）。

**判型（铁律 18）**：**新增检测型** —— 只读判定 + 生成提醒条目，**不改任何既有可观察结果**、不触碰数据库、不改配置。
