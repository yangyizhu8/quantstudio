## 二、客户回报路由预置（三路由体例）

> 体例沿用 CASE-005（三客户统一简版）的「现象 → 动作 → 归属」三段式；
> 下方**触发条件列**随会话 2 定稿件内容填入（本会话先预置骨架，防回报到手时无路由）。

| 路由 | 触发现象 | 预置动作 | 归属/时限 |
|---|---|---|---|
| **R1 常规确认** | 客户回「已更新 + 验证清单全过」 | 登记回执（客户/日期/版本号/关键验证行）→ 转总调度审核 → ⑥ 案例归档 | 按**客户映射**归属线（jabberwock → 本会话；美德双休 → 会话 2）；24h 内登记 |
| **R2 需现场证据** | 客户回「更新后仍有异常」但未带证据 | 按定稿件指定项**取回证据**（日志片段 / 版本号 / 关键成功行 / 相关状态文件）→ 转总调度审核 | 同上；收到后 24h 内出结论或转派 |
| **R3 立即升级** | 客户回「数据停更/服务不可用」等严重现象，或证据显示既有修复未生效 | **立即升级**：转总调度 → 定归属会话 → 必要时启动 D+0 级止血流程；**保留现场（不删/不改关键文件）** | 归属线 + 总调度；**即时** |

**路由状态**：R1/R2/R3 **已激活**（N-20260924-01 下发后，2026-09-24 起对美德双休生效；本会话线对 jabberwock 同体例常备）。

**路由纪律（三条硬约束）**
1. **不越权下结论**：客户回报现象未经取证不得归因（沿用「先复现/取证，禁止未证实归因」铁律）；
2. **不静默处置**：任何回报都要落回执（含未闭环项的挂账与解除条件），不得口头带过；
3. **不绕闸门**：若需再下发补丁/通知，走「出件 → 编号登记 → 用户审定 → 下发」。
