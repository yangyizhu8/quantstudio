# ops 族 `off → warn` 最小激活计划（待审 · 本轮不激活）

> **性质**：最小激活计划，**另审**。本件提交不改变任何族档位（四族仍全 `off`）。
> **依据**：R4（2026-11-13）「下一步出仅 ops off→warn 最小激活计划：当前条目范围、起时、告警／消费验证、误伤处置和已批准回退配方。计划另审，本轮不先激活、不全族 strict。」
> **方案正本**：`docs/handoff/kb-placeholder-gate-design-20261112.md` v3（§3.3 档位交互 / §3.4 转档权限）
> **实现现状**：`scripts/kb_hook.py`（`placeholder_report` / `check_files` / `main`）；证据 `docs/evidence/kb-placeholder-gate-impl-20261113.md`

## 1 激活范围（当前条目）

| 项 | 值 |
|---|---|
| 族 | **仅 `ops`**（`knowledge/ops/OPS-*.md`） |
| 当前条目 | `OPS-2026-0001` / `0002` / `0003` / `0004` / `0005`（**共 5 条**） |
| 条目状态 | 5/5 已过实质性复核：trigger 均为真两段式、`feedback` 至少一项实质、零字段假填（0003 的 7 处「占位」为正文引述，本门不扫正文） |
| 其它族 | **保持 `off`**（qd/pd/db 不动；db 存量 42 件占位不满足激活前置） |
| 不涉及 | 不升 `strict`、不建存量登记 JSON（ops 已无存量占位）、不改 pre-push 挂载强度 |

## 2 起时

| 项 | 值 |
|---|---|
| 起时条件 | 本计划获批 **且** 实施提交落地（同一提交内置下列两键） |
| 配置改动 | `knowledge/kb-info.yaml` 的 `ops` 族：`placeholder_gate: "warn"`、`placeholder_gate_since: "<落地日期>"` |
| 生效范围 | 自该提交起，凡 `kb_hook` 扫描 `ops` 条目（任意调用方、含 pre-push 链）均产出 `warn` 报告 |
| 观察窗 | **7 个自然日**（起时 + 7d）；窗内**只 warn、不改 verdict**（W1 用例已证：warn + `--strict` 也不 FAIL） |
| 窗末动作 | 出一页观察报告（fake 命中数 / 误伤数 / 新增条目数），再决定是否申请升 `strict`（**另审**，不自动升） |

## 3 告警与消费验证

### 3.1 告警形态（warn 档）

| 通道 | 形态 |
|---|---|
| CLI 文本 | `[placeholder:warn] <file> : stage=entry fake=N mention=[…] notes=[…]` + 每条 fake 明细 + `.draft.` 诊断行 |
| JSON | `placeholder[]: {file, level, stage, fake[], mention[], notes[], diagnostics[]}` |
| 退出码 | **恒 0**（warn 不阻断；与 `--strict` 叠加亦然） |

### 3.2 消费者清单（谁看这些告警）

| 消费者 | 触发点 | 窗内要求 |
|---|---|---|
| 本线（⑥）每轮自检 | 每轮 KB 体检时跑一次 ops 族 | **读数入上报块**（不得沉默丢弃） |
| `pre-push` 链 | push 前体检（若该链调用 `kb_hook`） | warn 不阻断推送；读数落日志 |
| `kb_draft` 起草 | 新建 ops 条目时 | 草稿态打 `DRAFT: 含 N 处占位`；正式落位前须清零 |
| 人工评审 | 条目复核时 | 以 `mention`/`fake` 明细作为复核线索（**不作完成证明**） |

### 3.3 消费验证判据（窗末）

| 判据 | 阈值 |
|---|---|
| 新增/修改条目的 `fake` 命中 | **0**（若有 >0，须逐条处置并留痕） |
| 误伤（合法内容被判 fake） | **0**（>0 触发 §4） |
| 告警被消费 | 观察窗内至少 **3 次**体检记录含 `[placeholder:warn]` 行（证明告警真的在流，而非静默） |
| 未启用族不变 | qd/pd/db 的 payload 与窗起时**逐位一致**（每次体检附 sha256） |

## 4 误伤处置

| 步骤 | 动作 |
|---|---|
| 1 记录 | 误伤即登记：文件、字段、原值、为何合法、`classify` 判定结果（**不得只口头说明**） |
| 2 隔离 | 该条**不改判据**；如影响面小，由起草方改写内容规避（如把"占位"改述为"留白字段"），并留改写前后对照 |
| 3 升级 | 同类误伤累计 **≥2 例** ⇒ 提方案修订（改 `FAKE_PREFIX_RE` 或增设受检字段豁免面），**须另审** |
| 4 禁止 | **不得**以"临时降档/临时跳过该文件"方式绕过；降档走 §5 配方（且属放宽检测，须审批） |
| 5 反向 | 若误伤源于"内容确实以占位词开头"（如 legit 的"占位符说明"），按 §2.0.2 既定取舍**保持从严**，由内容侧改写 |

## 5 已批准回退配方（本件申请批准；批准后即为"已批准配方"）

> 语义前提（R2 纠正）：`warn → off` 是**放宽检测**，不是"安全方向"。本配方因此写明**触发条件**，不得随意使用。

| 项 | 内容 |
|---|---|
| 触发条件（任一） | ①出现 P0 误伤导致正式条目被错误标记且影响下游；②告警噪声使体检读数不可用；③总调度/审核方指令停止 |
| 执行动作 | **单行配置回退**：`ops` 族 `placeholder_gate: "off"`、`placeholder_gate_since: null`；**不动代码** |
| 同一提交要求 | 提交信息须含：回退理由、触发条件编号、回退前最后一次体检读数（含 sha256） |
| 验证 | 回退后立即跑全库体检，payload 与窗起时基线**逐位一致**（sha256 相同） |
| 限制 | 仅 `ops` 单族；**不得**顺手把其它族置 non-off；回退后 3 个自然日内须出归因结论 |
| 不复用 | 代码级回退（`git revert`）仅用于实现缺陷，不用于档位调整 |

## 6 本轮不做（边界重申）

- 不把任何族改为 `warn`（四族全 `off`，`placeholder_gate_since` 全 `null`）。
- 不升 `strict`、不动 `pre-push` 的 `--strict` 用法。
- 不建 `scripts/data/kb-placeholder-baseline.json`（ops 无存量占位，无需冻结）。

## 7 待审清单（请审核方逐项表态）

1. 范围「仅 ops 5 条」是否认可（含 0005 已补实）；

4. 误伤处置「不改判据、≥2 例才提修订、禁止临时降档绕过」是否认可；
