## 0 先纠正三处验收声明（审核要求"验收声明先纠正"）

| # | 此前表述（错误/不完整） | 纠正后 |

## 1 范围与「批内检测」边界（审核第②条）

### 1.1 激活范围

### 1.2 批内边界（**必须显式声明**，不得默示为全库）

`duplicate_id` 检测**只覆盖本次 `--files` 输入集合**（"批内"）。

**实测证据（隔离副本演练⑤，2026-11-13）**：

```
仅传 knowledge/ops/OPS-2026-9003.draft.md（旧同 id 件不在输入）⇒ bad=0   ← 看不到冲突
同批传 OPS-2026-9003.md + OPS-2026-9003.draft.md          ⇒ bad=2 含 duplicate_id
```

⇒ **只提交新增重复件时，现实现看不到与存量同 id 的冲突**。这是**已知盲区**，不是待修复缺陷（属设计边界），激活前必须二选一（**另审**）：

| 方案 | 内容 | 代价 |
|---|---|---|
| **甲（维持批内 + 显式声明）** | 文档写明"仅批内"；冲突靠 CI/全量体检（`kb-schema.yml` 与人工全族扫描）发现 | 提交期漏检；依赖后续全量扫描 |
| **乙（命中 id 回查族目录）** | 检测到某 id 时，按族 `entry_glob` 扫族目录，取者**存量身份集合**比对 | 每次体检多一次目录扫描；需定义"跨族同 id 是否算冲突"（暂定：仅同族） |

**本次申请按「甲」起步**，并明确**发现机制**（R5 修正）：

- 撞 id 的**唯一发现机制＝每日全 ops 全量人工扫描**（见 `ops-warn-execution-sheet-20261113.md` §2）；
- **不得**依赖"漏检被撞见"触发升级——漏检**无法自证**（这是甲方案自带的盲区，不能用"出过事再改"掩盖）；
- **CI 的改动件扫描不构成全库兜底**（它只扫本次改动）；
- 若 30 天内出现 **≥1 次"新增件与存量撞 id"**（由每日全量扫描发现）⇒ 转「乙」另审。

## 5 误伤处置（不变，五步）

1. **记录**：文件、字段、原值、为何合法、`classify` 判定（不得只口头说明）。
2. **隔离**：不改判据；影响面小则由起草方改写内容规避，留前后对照。
3. **升级**：同类误伤 **≥2 例** ⇒ 提方案修订（另审）。
4. **禁止**：以"临时降档/跳过该文件"绕过；降档走 §6。
5. **反向**：内容确以占位词开头者**保持从严**。

## 7 strict 档与 CLI `--strict` 的契约差异（审核第⑦条：本轮不启用 strict）

| 维度 | 本门 `placeholder_gate: strict` | CLI `--strict` |
|---|---|---|
| 作用对象 | **仅占位判定**（fake 命中） | **全部 `bad` 项**（六必填/枚举/域/recurrence/feedback/status/duplicate_id/占位-strict） |
| 生效方式 | 命中 ⇒ 并入该条 `bad` | 有任一 `bad` ⇒ **进程 `rc=1`** |
| 叠加语义 | strict 命中经"并入 bad"**间接**触发 `rc=1`（须同时带 `--strict` 才体现为退出码；不带则仍只报 `bad`） | 与本门档位正交 |
| warn 档 | 命中**不**并入 bad ⇒ **即使带 `--strict` 也不产生 `rc=1`**（演练④） | — |
| 本轮状态 | **不启用**（四族全 `off`） | 既有用法不变 |
