## 1 R1 · 开工面扩展（草案条文）

> **R1（开工留痕）**：凡框架层/转换管线相关的实施轮，开工前**必须**完成一次知识库检索并在本轮 Plan 或方案文档中留痕，格式沿用既有可机检式：
>
> ```
> 知识反哺：[命中] <条目名>（<域>/<文件名>，YYYY-MM-DD）        # 可多条，各占一行
> 知识反哺：[无命中] <检索域清单>，YYYY-MM-DD
> 知识反哺：[豁免] 本轮无技术决策内容                            # 纯文案/紧急热修
> ```
>
> - 检索目标：`knowledge/qmt/`（QD 条目，按 `domain` 过滤）＋ 通用库对应域 MOC；
> - **豁免亦须留痕**（禁止静默跳过）；
> - 与既有「六步流水线方案①」**共用字段**：方案面留痕＝开工留痕的子集，不重复记录两次。

**机检口径（建议，落位时一并定）**：Plan 文本中 `grep -c "知识反哺："` ≥ 1；缺失 ⇒ ②审判不完整。

## 2 R4 · 验收面新增（草案条文）

> **R4（验收沉淀）**：每轮验收申报必须包含一行——
>
> ```
> 本轮沉淀：<QD-YYYY-NNNN>            # 本轮新增/更新的条目 id（可多个）
> 本轮沉淀：N/A（理由：<一句话>）      # 无可沉淀时必填理由
> ```
>
> - 判据：`本轮沉淀` 字段非空且**二者之一成立**（id 存在且该条目过 schema 机检 / N/A 带理由）；
> - **N/A 不是免检**：连续 3 轮 N/A 须在下一轮说明「为何无沉淀」（防形式化 N/A）；
> - 沉淀条目必须过 `kb_preflight.py` 的 `validate_entry`（`domain`/`trigger`/`recurrence` 三字段齐）。
