# 客户通知稿：QuantStudio 组件 duckdb 版本升级至 1.5.6（通知编号 5）

> **状态**：**草稿，未下发**。下发须经用户确认闸门（铁律 01 六步第⑤步）——本通知**仅由总调度转发**，执行会话不代下发。
> **建议下发时间**：不晚于 **2026-11-17**（1.4.x 线 EOL 日）。
> **适用范围**：使用 QuantStudio 主仓（GUI / daemon / 采集链）并会启动采集的客户端。

---

## 一、这次要做什么

QuantStudio 的数据库组件（duckdb）将从 **1.4.5 升级到 1.5.6**。
**代码与依赖必须同批升级** —— 只升依赖不升代码（或只升代码不升依赖）都会导致程序**拒绝启动**。

这是**预期保护行为，不是故障**：项目对 duckdb 版本设有启动闸门，不在允许集合内的版本会被拦下并给出修复指引。

## 二、允许的版本集合

| 版本 | 是否允许 |
|---|---|
| 1.4.5 ～ 1.4.x（`1.4.5 ≤ x < 1.5`） | ✅ 允许（维持现状） |
| **1.5.6** | ✅ 允许（本次目标版本） |
| 1.5.0 ～ 1.5.5 | ❌ 不允许 |
| 2.0.x 及以上 | ❌ 不允许（首跳不含） |

> 说明：1.5.x 中存在一个上游缺陷（`duckdb#23645`，索引删除在特定条件下会触发致命错误），
> 该缺陷在 **1.5.6 仍未修复**，只是不再静默出错。本项目经过实测核对该缺陷对本项目**无暴露面**（详见随附技术说明），
> 故 1.5.6 纳入允许集合。若您需要继续留在 1.4.x，请按第四节降级，不要直接跨到 2.x。

## 三、升级步骤（建议在非交易时段执行）

1. **停止采集进程**：关闭 GUI，并停止 daemon（Windows 计划任务名：`QS_DaemonForever`）。
2. **升级代码**：拉取最新版 QuantStudio 代码（`git pull`）。
3. **升级依赖**（与第 2 步**必须同批**）：

   ```bash
   pip install "duckdb==1.5.6"
   ```

   > 请**使用显式版本命令**，不要用 `pip install -r requirements.txt` 以外的其它版本约束写法；
   > 也不要用 `pip install -U duckdb`（会装到未纳入允许集合的最新版本）。

4. **自检**（一条命令，输出即结论）：

   ```bash
   python -m quantstudio.pipeline.duckdb_version_gate --check
   ```

5. **恢复采集**：重新启动 daemon（Windows：`schtasks /Run /TN QS_DaemonForever`）。

## 四、自检输出怎么读

| 输出 | 含义 | 您需要做什么 |
|---|---|---|
| `PASS 1.5.6`（退出码 0） | 版本与门禁均正常 | 无需操作，可恢复采集 |
| `PASS 1.4.5`（退出码 0） | 仍在旧版本，也允许 | 可正常运行；如要升级请按第三节执行 |
| `FAIL <版本>`（退出码 1） | 当前版本**不在允许集合** | 执行第三节第 3 步升到 1.5.6（或按第五节降级） |
| `ERROR …`（退出码 2） | 依赖缺失或版本串不可读 | 报运维，附**输出原文** |

若程序启动时提示「拒绝启动」并打印 `duckdb` 版本与修复指引，属上述第 3 行情形（退出码 3），按提示执行即可。

## 五、如果需要留在 1.4.x（降级）

```bash
pip install "duckdb==1.4.5"
```

降级同样需要**先停采集**；降级后请再跑一次第四节的自检命令确认 `PASS 1.4.5`。

## 六、性能提示（请留意，可能影响您的调度安排）

升级到 1.5.6 后，**批量写入路径**的耗时约为旧版的 **4–6 倍**（本机实测）：

| 单批行数 | 旧版（1.4.5） | 新版（1.5.6） |
|---|---|---|
| 300 行 | 约 0.6 秒 | 约 **3.9 秒** |
| 1000 行 | 约 3.3 秒 | 约 **13.4 秒** |
| 5000 行 | 约 15.4 秒 | **超过 90 秒未完成**（超时） |

这**不影响数据正确性**，影响的是该辅助表刷新的**时延**。若您的采集表批次达到千行量级，请相应放宽该任务的调度超时，
或在升级后观察首日采集耗时；必要时可将该表批次拆分。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报「duckdb 不在放行集合」 | 代码已升、依赖未升（或反之） | 停采集 → 按第三节第 3 步升级依赖 → 重新自检 |
| 自检命令报「无法导入 duckdb」 | 解释器选错 | 用**项目实际使用的那个解释器**执行自检（如 `C:\...\Python311\python.exe` 或项目 venv 的 python） |
| 升级后某个表刷新变慢 | 见第六节 | 调超时或拆批次；如影响主流程，请反馈给我们 |
| 采集正常但日志出现 `Failed to delete all rows from index` | 命中 1.5.x 上游缺陷（`duckdb#23645`） | **立即反馈并附日志片段**；必要时按第五节降级 |

## 八、需要您反馈的情况

- 自检命令输出与第四节表格**不一致**；
- 升级后采集报错、重复写入，或出现第七节第四行的日志文本；
- 您的部署环境使用了**我们未覆盖的 duckdb 版本或解释器组合**（请附 `python -c "import duckdb;print(duckdb.__version__)"` 输出）。

请在反馈中附上：自检命令的完整输出、Python 与 duckdb 版本、以及报错日志片段。
