## 一、修复了什么

在把**本地策略转换为 PTrade 策略**的过程中，有一段逻辑负责**从策略源码中提取「行业剔除清单」**
（用于过滤银行、非银金融等板块）。

**原实现存在缺陷**：它会**扫描源码中所有「6 位数字」的字符串**，**无法区分「行业代码」
与「其他用途的 6 位数字」**。实测发现它会**把无关内容当成行业代码**，例如：

- 把「**北交所存量映射表**」（约 200 个代码）**整表**当成了行业代码；
- 把代码中的**特殊标记值**当成了行业代码。

**后果**：这些误提取的内容会被**写入转换后的 PTrade 策略**，导致平台端**逐个去查询这些
并不存在的行业** —— **拖慢运行，且行业过滤实际失效**。

**现已修复**：改为**只在明确的行业声明位置提取**（如 `ic in ('801780', ...)` 这类结构化写法），
并**排除注释与说明文字、特殊标记值、已知无关的代码表**。
判据采取**保守策略**：**宁可提取不到并给出告警，也不误收**。

## 二、对您已转换产物的影响 —— **建议自查（约一分钟）**

**可能受影响的**：您此前转换过的、**源码中含「其他 6 位数字」**的策略。

**自查方法**：在您转换产物（`*_ptrade.py`）中查找这一行：

```
_QS_INDUSTRY_CODES = ( ... )
```

| 看到的内容 | 判断 | 您需要做什么 |
|---|---|---|
| 只有**少数几个**行业代码（如 `('801780','801790','480000','490000')`） | **正常** | **无需处理** |
| **空括号** `()` | **正常**（该策略没有行业剔除声明） | **无需处理** |
| **一长串代码**（几十上百个，多为 `43xxxx` / `83xxxx` / `87xxxx` 开头） | **误提取** | **请重新转换**（见 §三） |

**若无法判断**：把该行内容发给我们，我们帮您核对。

## 三、客户侧更新操作

```bash
cd <您的 QuantStudio 项目目录>
git pull origin main
```

- **回测功能**：**无需配置改动**；若程序正在运行，**重启后生效**；
- **策略转换**：更新后**重新执行一次转换**，即可得到修正后的产物；
- **已转出的、判定为「正常」的产物无需重转**（结果本来就是对的）。

## 四、验证清单

1. 更新后跑一次常用回测，确认正常；
2. **与更新前对比同一策略、同一区间**：**交易笔数、最终净值应完全一致**
   （本次修复**不影响回测结果**，只影响转换产物）；
3. 若您有转换过的 PTrade 策略，按 §二 表格自查 `_QS_INDUSTRY_CODES` 行；
4. 可选自检：
   ```
   python -m pytest tests/test_industry_code_extract.py -q
   ```
   应显示 **16 项通过**。
