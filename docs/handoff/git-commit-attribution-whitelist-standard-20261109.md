# 推送分账标准：显式 SHA 白名单法（2026-11-09 总调度立为第二批组批标准 · 全线适用）

> **裁定**：第二批组批的**各线分账一律用显式 SHA ＋ 校验命令**；⑦ 的 attribution map 与本白名单**并池**（map 负责归属判定，白名单负责执行核验，两者互校）。
> **来源**：2026-11-09 节点⑲ 实测——按标题关键词分账**误判他线 7 笔**（`ptrade-deploy` PD-0019 系 4 笔、R-PERF-15/27 系 2 笔、PD-0019 入册 1 笔）；且**白名单外含 `duckdb` 字样的 5 笔全部属他线**（`177cea0`/`5c646ed`/`9b939e6`/`93592fa` etf_daily ART 链 ＋ `3be300d` R-PERF-15）。

## 一、三条硬动作（各线照做）

1. **分账凭据只认显式 SHA 列表**——每线维护一份「本线白名单」文件（路径见 §三），**一行一个 SHA**，按提交先后追加；
2. **禁关键词自动判定归属**——`grep` 标题里的项目词（如 `duckdb`/`perf`/`deploy`）**不能**作为归属判据：跨线共享主题词会让**他线笔被算进本线**（本轮实证 7 笔）；归属必须**人工按内容判定**（提交内**文件路径** + 标题 + 制品归属三项合看）；
3. **推送前实态重列**——未推总笔数**随各线提交持续增长**（本轮实测 97 → 101），任何「我方 N 笔」的历史值**不可直接沿用**，须当轮 `git log origin/main..HEAD` 重列。

## 二、归属判据（人工内容归属，三项合看）

| 项 | 看什么 | 反例（不可用） |
|---|---|---|
| ① 提交内**文件路径** | `quantstudio/`、`scripts/`、`docs/evidence/` 等本线制品目录 | — |
| ② 标题 | 描述的**制品/判据/事件**是否属本线 | 含共享主题词≠属本线（如 `fix(duckdb) etf_daily ART` 属 etf_daily P0 链） |
| ③ 制品归属 | 该产物由哪条线的问题域产生 | — |

> **author 字段不可用作分账依据**：本仓多会话共享同一 git 身份（实测全部为 `yangyizhu8`），**无法**按 author 切分。

## 三、白名单文件与校验命令（模板）

**白名单文件**：`docs/handoff/<线标识>-push-whitelist-<YYYYMMDD>.txt`，一行一个 SHA（`#` 开头为注释），例如节点⑲的：`docs/handoff/duckdb-push-ledger-batch2-20261108.md` 内「我方笔·显式 SHA 白名单」章节。

**校验命令（推送前必跑，输出应恰为白名单行数）**：

```bash
# 1) 取白名单 SHA（各线替换为自己的列表）
git log --format='%h|%s' origin/main..HEAD \
  | grep -E '^(c1b0248|bf98a35|4ac840a|c2fe26a|2d8b94e|faf461f|0936f24|5929305|3058c87|78972ea|be264af|2cd3b64|3dd4973|1a54916|377021e|a63fdfe)\|'

# 2) 取未推总笔数（授权面口径）
git log --oneline origin/main..HEAD | wc -l
```

**判定**：
- 输出行数 **≠ 白名单行数** ⇒ 本线有新笔未入白名单 ⇒ **补录后再推**；
- 未推总笔数 − 白名单行数 ＝ 他线笔数 ⇒ 推送授权面按此**全量对齐**（主分支线性历史，`git push` 一次即推出全部未推笔，**技术上无法只推本线**）。

## 四、与⑦ attribution map 的并池分工

| 层 | 负责 | 产物 |
|---|---|---|
| **归属判定层** | ⑦ 的 attribution map：逐笔判定「这笔记属哪条线」 | map 行（含 SHA↔线映射） |
| **执行核验层** | 本白名单：把归属结论固化为可复跑的 SHA 列表 | 白名单文件 ＋ 校验命令 |

两套**互校**：map 有而白名单无 ⇒ 漏录（须补）；白名单有而 map 无 ⇒ 归属存疑（须复核）。

## 五、已知事故形态（避免重犯）

| 形态 | 后果 | 防线 |
|---|---|---|
| 关键词分账 | 漏推他线笔 / 误报他线笔为本线（认证据面失真） | 显式 SHA ＋ 人工内容归属 |
| `git commit --amend -- <paths>` | 以 index 成提交 ⇒ **把他线 staged 文件带进本线 commit** ＋ 历史留同标题孪生 | 修历史用 `reset --soft` ＋ 精确 `commit --only`（见记忆 `3a90b3a0`） |
| 改码未验证即提交 | 缺陷入库，自检才暴露 | **先跑验证再提交** |
| 沿用旧「我方 N 笔」 | 授权面与实态不符 | 推送前实态重列（§一·3） |
