## 3 每次记录格式（逐行，落 `docs/evidence/kb-ops-warn-log-20261113.md`）

```
<ISO 时间戳> | 配置锚: HEAD=<sha7> kb-info.sha256=<前12> | 档位=<off|warn> | 文件清单=<N 件: OPS-…, …> | fake=<n> mention=<n> duplicate_id=<n> | 处置=<无|补实-条目号|误伤-编号|其他>
```

- **配置锚**必须同时含 `HEAD` 与 `kb-info.yaml` 的 sha256（防"档位被谁改过"不可追溯）。
- **文件清单**必须逐个列名（不写"5 条"了事），以便事后核对输入集合。

## 4 观察窗精确起止（R5：三分不天然同刻）

| 时刻 | 定义 | 记录要求 |
|---|---|---|
| **T1 工作树生效** | `kb-info.yaml` 落盘为 `"warn"` 的文件修改时间 | 记实际时刻（文件 mtime **仅用于此溯源**，不作判据） |
| **T2 提交生效** | 该配置进入 git 的提交时刻 | 记 commit SHA + 提交时间 |
| **T3 首次消费** | 本会话**首次以 warn 档跑全 ops 并留痕**的时刻 | 记 ISO 时间戳；**观察窗自 T3 起算** |
| **窗止** | T3 + 7 个自然日（同一时刻） | 到时出观察报告；**不自动升 strict** |

> 三者通常不同刻，逐项记录，**不得合并成一个"起时"**。

## 6 回退等价判据（R5 修正：不比原始 SHA）

**问题**：`off` 档输出**不含** `placeholder` 键，`warn` 档含 ⇒ 两者原始 sha256 **必然不同**，不能用"原始 SHA 相同"判等价。

**判据（成对对照）**：

1. 固定**同一条目快照**（同一批 `--files` 清单）与**同参数**；
2. 先取 **off 档预期基线**：把档位置 `"off"` 跑一次，得 `P_off`（无 `placeholder` 键）；
3. 回退后（`"warn"` → `"off"`）再跑一次，得 `P_after`；
4. **判定**：`P_after` 与 `P_off` **逐位相同**（原始 SHA 相同）⇒ 回退到位。
5. 若需比较 **warn 档与 off 档**（非回退场景）：**剥离 `placeholder` 键后**比较，两者其余键值须逐位一致；比较的是"剥离后形态"，**不是**原始字节。
