# 客户通知（第 4 号）· DuckDB 组件缺陷预警与预防性更新

- **状态**：**已下发（2026-09-21）**
- **性质**：**预防性更新预警**（非事故通知）
- **依据**：上游缺陷 `duckdb#23645`（1.5.x 全线受影响，修复未随 1.x 发布）；版本目标经 **A 案验证 + 社区实证**定谳
- **配套**：钉版提交 `5913785`（`pyproject.toml` L20/L45 + `requirements.txt` 三处一致）
- **措辞纪律**：不渲染内部细节（无表名 / SQL / 内部代号）；含更新步骤与验证清单

---

## 一、预警定性（先说不影响什么）

这次通知是**预防性质**的，不是故障通报：

- **不影响您已有的数据** —— 已采集、已交付的数据完好；
- **不会损坏数据** —— 该问题不会造成数据错误或丢失；
- **可能的影响是**：**长期运行后，数据采集可能停下来**（更新写入失败 → 采集暂停），
  重启程序**只能临时恢复**，之后还会再停。

**所以我们建议您在方便时做一次更新** —— **不必紧急**，但建议尽早。

## 二、发生了什么（通俗解释）

我们使用的数据库组件（DuckDB）在**长年累月地反复写入**之后，其**内部的索引结构**会出现异常：
当程序尝试**更新某张表**时，这个更新动作会失败，进而**让整个数据库连接不可用** ⇒
**后续的数据采集任务全部停住**。

**它的特点**：

- **不报"小错"，而是"停摆"** —— 一旦触发，采集就停了；
- **重启能暂时恢复**，但**通常几十分钟内会再次触发**（我们实测到的节奏是重启后约 37 分钟）；
- **触发条件是"长期反复写入"**，所以**用得越久越容易碰上**。

**我们已确认**这是**组件自身的问题**（已被上游确认为缺陷，且在 1.5.x 全线存在；
官方修复计划在下一大版本中提供）。**不是您的操作问题，也不是我们的数据有问题。**

## 三、客户自查（约 30 秒）

在您的项目目录下执行：

```
pip show duckdb
```

看输出中的 `Version:` 一行：

| 显示 | 判断 |
|---|---|
| **1.5.x**（如 1.5.5） | **受影响** —— 建议按第四节更新 |
| **1.4.x 或更低** | 暂不受此问题影响 |

## 四、更新动作

**第 1 步：更新代码**

```
cd <您的 QuantStudio 项目目录>
git pull origin main
```

**第 2 步：把数据库组件切到安全版本**

```
pip install "duckdb>=1.4.5,<1.5"
```

**第 3 步：确认**

```
pip show duckdb
```

`Version:` 应显示 **1.4.5**（不再是 1.5.x）。

**说明**：

- 本次更新**不改变任何策略、不改变回测逻辑与结果**，只调整底层组件版本；
- 若程序正在运行，**重启后生效**；
- 该命令为**通用直装**，与您的安装方式无关（源码运行或包安装均适用）。

## 五、兜底：如果更新前就已经出现采集停止

**判断方法**：若您遇到**采集长时间不动**，且日志中出现 `invalidated` 字样
（如 `database has been invalidated`），说明**已经触发过这个问题**。

**此时请先联系我们** —— **不要自行反复重启，也不要手工修改数据库文件**。
我们会根据您的情况**出具数据重建指引**（该问题的标准处置是**用新鲜文件重建数据库**，
须由我们按您的情况给出具体步骤），确保数据完整性。

**请一并提供**：日志中该错误的**时间点**与**前后若干行**（便于我们判断影响范围）。

## 六、说明

- 本通知为**预防性预警**，**不影响已有数据**，请勿因此暂停正常使用；
- 更新**不必紧急**，建议在您方便的时间窗内完成；
- 若自查后确认不受影响（1.4.x），**本次可暂不操作** —— 我们会持续跟踪该组件后续版本，
  待官方大版本提供修复并验证通过后，再另行通知升级。
