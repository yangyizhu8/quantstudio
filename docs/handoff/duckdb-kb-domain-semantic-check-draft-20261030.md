# db 族 schema 增强草案：域语义对照校验项（与⑥协同 · 待⑥落地）

- **日期**：2026-10-30｜**发件方**：duckdb 数据库升级执行会话（节点⑲）｜**收件方**：⑥会话（族主）｜**抄送**：总调度
- **触发**：2026-10-30 ⑲ 入族后自纠 —— `DB-2026-0001`（duckdb 1.5.x `executemany` **性能**劣化）按族 README §2.2 定义应为 **`D1` 引擎行为与性能**，而⑲入族时按**自身回执件**的语义表标为 `D2`（写入语义）⇒ **错位一格**；`kb_hook.validate_record` 机检**只验取值合法性**（D2 ∈ vocab ⇒ PASS），**验不出语义归属错位** ⇒ 属**机检盲区**。
- **裁定**：总调度 2026-10-30「域语义对照校验项照准 —— 与⑥协同入族 schema 增强；入族后逐条按族 README 域定义复核的**硬动作**一并写入」⇒ 本件是**增强草案**（供⑥落地）；硬动作部分**已写入族 README §5**（⑲侧已落）。

## 一、增强项设计

### 1.1 族 schema 增「域语义对照表」（`kb-info.yaml` families 段，db 族）

```yaml
    - id: db
      …
      domain_semantics:                 # 新增：域 → 语义与判定要点（唯一口径 = 族 README §2.2）
        D1: {name: 引擎行为与性能,       keywords: [性能, 耗时, 劣化, 吞吐, 引擎行为, latency]}
        D2: {name: 数据完整性与写入语义, keywords: [写入语义, 内容, 行数, 列序, 覆盖, 静默]}
        D3: {name: 约束与 schema 契约,  keywords: [主键, PK, 约束, 唯一, 指纹, ON CONFLICT, schema]}
        D4: {name: 版本升级与兼容,      keywords: [版本门, 升级, 兼容, 回归面, duckdb#, EOL]}
        D5: {name: 工程纪律与制品一致性, keywords: [判据, 回扫, 制品, 纪律, 提交, 判据失准]}
```

### 1.2 机检增强（`scripts/kb_draft.py` ＋ `kb_hook.validate_record`）

| 判据 | 规则 | 处置 |
|---|---|---|
| **域命中为 0** | 条目的 `symptom`+`root_cause`+`fix_target` 三段文本，对该族 `domain_semantics` 的关键词**命中数为 0** | **不落盘**（fail-closed），报「域语义不匹配：请核对族 README §2.2 域定义」 |
| **域命中为多** | 命中 ≥2 个域 | 落盘但在 `notes` 记「域语义歧义（命中 D?+D?）⇒ 需人工复核」并回显到起草输出 |
| **域命中为 1** | 命中恰好 1 个域 | 通过（与 `--domain` 显式值一致时最佳；不一致时按「域命中为 1 但 ≠ 显式值」记 notes 提醒） |

⚠️ 关键词命中是**粗筛**，不追求语义完备 —— 目标是**把「错位一格」这类错误从「机检看不见」变成「机检会提醒」**；终审仍以族 README 域定义人工逐条复核为准（§二硬动作）。

### 1.3 机检覆盖范围

- `kb_draft.py` 起草时即刻校验（落盘前）；
- `kb_hook.validate_record` 复校时校验（已落条目被重校也走同一判据 ⇒ 改域后重校能发现残留错位）。

## 二、硬动作（**已写入 `knowledge/db/README.md` §5**）

> **每一条新条目落盘后，必须按本 README §2.2 的域定义逐条复核 `domain` 归属**（不得沿用起草前的语义表）；不一致即改并登记变更记录。

| 步骤 | 动作 | 责任 |
|---|---|---|
| 1 | 对照族 README §2.2 域定义逐条复核 `domain` | 入族方（起草者） |
| 2 | 不一致 ⇒ 改 `domain` 并在 §变更记录登记（含错位事实） | 入族方 |
| 3 | 机检（增强后）跑一次 `kb_hook.validate_record` 复核 | 入族方 |

## 三、我方三条的自查结果（按族 README §2.2 域定义）

| 条目 | 主题 | 现 `domain` | 按族 README 应为 | 结论 |
|---|---|---|---|---|
| `DB-2026-0001` | `executemany` **性能**劣化（4–6 倍） | **D1**（已自纠，原 D2） | **D1 引擎行为与性能** | ✅ 已一致 |
| `DB-2026-0002` | 覆盖链静默清空**主键**（约束） | **D3** | **D3 约束与 schema 契约** | ✅ 一致 |
