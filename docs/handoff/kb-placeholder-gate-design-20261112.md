## 2 规则定义（真实语法，可机检）

### 2.1 占位词表（唯一判定源）

```python
PLACEHOLDER_TOKENS = ("待补充", "待填", "TODO", "TBD", "FIXME", "placeholder", "占位")
```

- 判定：对字段值做 `casefold()` 后 `any(tok.casefold() in value)`；命中即判**占位**。
- **不看长度**：短而真实的「条件：重启 daemon；问法：怎么又掉了」合法；长而占位的「待补充：最小复现触发条件（一句话可判定是否命中）」非法。
- 空值/`null`/`None` 字符串另由既有 `为空` 判据处理，不归本门。

### 2.2 `trigger` 两段式（真实语法）

**语法定本**（正本一行）：

```
trigger := <复现条件> "；" "问法：" <口头问法>
```

机检判据（四条**全部**满足才算通过）：

| # | 判据 | 正则/实现 |
|---|---|---|
| T1 | 含分隔符 `；`（**全角**，与既有 25 条正样本一致） | `"；" in value` |
| T2 | `；` 之后（允许空白）紧跟 `问法：` | `re.search(r"；\s*问法[：:]", value)`（**冒号兼容全/半角**，防中文输入法差异） |
| T3 | `问法：` 之后内容非空且 ≥4 字 | 截取后半段 `strip()` 后 `len >= 4` |
| T4 | 两段均不含占位词（§2.1） | `not is_placeholder(each_half)` |

- **`；` 全角为唯一合法分隔符**：不兼容半角 `;`——因为既有 25 条正样本全用全角，兼容半角会引入两套写法；若独立审认为需兼容，改为 `[；;]` 并在 README 明示（本方案默认不兼容）。
- 反例：`"待补充：最小复现触发条件"` ⇒ T2/T4 双失败；`"重启后进程不活"` ⇒ T2 失败（缺问法段）；`"条件；问法："` ⇒ T3 失败。

### 2.3 `feedback` 三键（派单第 4 点的漏口）

现状判据：`any(fb[k] 非空)` —— 占位串算"非空"⇒ 漏放。

**新判据**：

| # | 判据 |
|---|---|
| F1 | 三键中**至少一项**满足「非空 **且** 非占位 **且** 非 `null`/`None` 字面量」 |
| F2 | 三键中**任何**被填写（非空）的键，**不得**是占位串（即"填了占位"比"留 null"更差，直接不合格） |

- 设计取舍：**允许 `null`**（"该通路无回哺"是合法声明），**不允许假填**（占位）。这保住既有条目里 `contract_row: null` 的合法用法，同时堵住「待补充」糊弄。
- 反例：三键全 `"待补充：…"` ⇒ F1/F2 双失败；`contract_row: null, gate_rule: "例", template_patch: null` ⇒ PASS（唯一非 null 项非占位）。

## 3 族范围与灰度（不直接收紧全族）

### 3.1 族级开关（写进 `kb-info.yaml` families）

```yaml
  - id: ops
    placeholder_gate: strict        # off | warn | strict   （默认 off＝不改变现状）
    placeholder_gate_since: "2026-11-12"
```

| 档位 | 行为 |
|---|---|
| `off`（默认） | 完全保持现状，本门不介入（**上线首日全部族为 off**） |
| `warn` | 检出即打印 `PLACEHOLDER[warn]` + 计入 payload 的 `placeholder_hits`，**不改变 verdict** |
| `strict` | 检出即 FAIL（并入既有 `bad` 列表，复用 verdict 语义） |

### 3.2 推进顺序（按实测存量排队，先小后大）

| 阶段 | 族 | 前置 | 判据 |
|---|---|---|---|
| **A** | **ops** | 节点12 补齐 4 条空壳（trigger＋feedback）→ 我方复核 PASS | ops 4/4 合规后再开 `strict` |
| B | qd / pd | 各有 2／3 件占位需补 | 补齐后 warn→strict |
| **C** | **db** | **存量 42 件占位**，须先出存量处置方案（§5） | 未处置前**保持 off**，不 warn（避免 42 条噪声刷屏） |

- **A 阶段即本方案的最小可验证闭环**：ops 单族 strict 落地 → 证明门有效 → 再推其它族。
- 未列入的族（未来新族）默认 `off`，新建族时在 README 明示是否启用。

### 3.3 与既有判据的关系

- 本门**只增不减**：既有六必填/枚举/域/`recurrence`/`status`/`feedback 非空` 判据全部保留，本门在其后追加（顺序：非空 → 枚举 → 本门），保证**报错文案可区分**（`trigger 占位` vs `trigger 为空`）。

## 4 草稿态 vs 正式态（派单第 3 点）

**问题**：起草期难免先写占位（`kb_draft.py` 生成骨架时就是占位），若草稿态也 strict 会逼人绕过工具。

**方案（不改 schema、不动 `status` 词表）**：

| 态 | 承载 | 占位检测 |
|---|---|---|
| **草稿态** | `kb_draft.py` 生成的 `.md`（默认落 `<kb>/` 但**未过机检不入库**；或显式 `--out tmp/`） | **允许**占位，但：①生成即打印 `DRAFT: 含 N 处占位，正式落库前须补实`；②`--json` 输出 `placeholder_hits` 字段 |
| **正式态** | 已过 `kb_hook.validate_record` 并落在 `knowledge/<族>/` 的条目 | 按族 `placeholder_gate` 判（off/warn/strict） |

- **"正式"的判据是落位与机检，不是 `status: open/closed`**——不新增 status 值（避免动 `status_vocab` 与既有 91 条）。
- 例外入口：`kb_hook --allow-placeholder`（显式开关，**仅用于存量核对/临时放行**，打印 `ALLOW_PLACEHOLDER(显式)` 便于审计）；不做环境变量隐式开关（防"忘记关"变成永久漏口）。
