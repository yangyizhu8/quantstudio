## 1 落位文本 v2（拟写入 `AGENTS.md` 的条文，逐字稿）

> ### 【铁律】知识反哺 R1/R4：开工留痕与验收沉淀（2026-10-23 落位）
>
> 1. **R1（开工留痕）**：凡框架层／转换管线／知识库机制相关的实施轮，开工前**必须**完成一次知识库检索，
>    并在本轮 Plan 或方案文档中留痕，格式沿用既有可机检式（**复用既有字段，不另设新字段**）：
>
>    ```
>    知识反哺：[命中] <条目名>（<族>/<域>/<文件名>，YYYY-MM-DD）      # 可多条，各占一行
>    知识反哺：[无命中] <检索面清单>，YYYY-MM-DD
>    知识反哺：[豁免] 本轮无技术决策内容                            # 纯文案/紧急热修
>    ```
>
>    - **检索面（唯一口径）**：① **主**＝结构化条目库 `knowledge/**`，按 `knowledge/kb-info.yaml` 的
>      **families 分族** ＋ `domain` 过滤；② **辅**＝通用库 `knowleage_base` 对应域 MOC（只读参考，**不回写**）。
>    - **族 schema 独立**：QD 族六枚举、PD 族九枚举（允许多落点 `+` 连接）——检索与引用**须写明族名**，
>      跨族枚举**不得混用**。
>    - **豁免亦须留痕**（禁止静默跳过）；与既有「六步流水线方案①」共用同一字段，方案面留痕＝开工留痕的子集。
>
> 2. **R4（验收沉淀）**：每轮验收申报必须包含一行——
>
>    ```
>    本轮沉淀：<族前缀>-YYYY-NNNN            # 本轮新增/更新的条目 id（可多个）
>    本轮沉淀：N/A（理由：<一句话>）          # 无可沉淀时必填理由
>    ```
>
>    - **判据**：条目必须过 **`kb_hook.validate_record` 按族校验**（族 schema 取自 `knowledge/kb-info.yaml` families 段）。
>      **按族校验，不套用他族枚举**（QD 族专用 `validate_entry` 不得用于 PD 族）。
>    - **起草路径**：`python scripts/kb_draft.py --kb knowledge/<族> --symptom … --domain … [--layer …]`；
>      `fix_layer` 缺省按族关键词自动判定并**打印判据**，机检不过**不落盘**。
>    - **族注册**：新族须在 `knowledge/kb-info.yaml` 的 `families` 段登记（`id_pattern`／`fix_layer_enum`／
>      `fix_layer_multi`／`domain_vocab`／`required_fields`），否则机检按默认族口径误判。
>    - **N/A 不是免检**：连续 3 轮 N/A 须在下一轮说明「为何无沉淀」（防形式化 N/A）。
>
> 3. **跨项目面**：新项目接入走 **`kb-kit/`**（`install.ps1` 幂等安装：`scripts/`＋`templates/`＋pre-push 钩子〔WARN 起步〕＋可选 CI）；
>    接入后其族 schema 与本条同构，R1/R4 留痕格式**不变**。
>
> 4. **与既有铁律的关系**：本条**不是**新铁律，而是两条既有铁律的执行面细化——
>    【六步流水线方案①强制知识反哺留痕（2026-10-10）】的**开工面扩展** ＋
>    【新功能模块闭环收敛（验证→修复→沉淀→回哺）】的**每轮落地钩子**。
>    收敛判据（连续 3 轮 R_i=0）**不变**；②审、⑥用户确认节点**不因此增删**。
