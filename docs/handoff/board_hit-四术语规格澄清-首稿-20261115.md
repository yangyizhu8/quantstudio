## 二、四术语逐项规格（已有定义／参考实现／新设计候选）

### 2.1 命中（hit）

| 维度 | 内容 |
|---|---|
| **类别** | 新设计候选（无用户原文）＋ **已有数据可直接判** |
| **可判条件（候选）** | **C-a**：limit_list_d.limit_type=U（或 limit=U，**两字段语义待确认**）<br>**C-b**：limit_list_ths.status ∈ {换手板, 一字板, T字板}<br>**C-c**：close ≥ stk_limit.up_limit ×（1−ε）（自算，与 fb 现用口径同族） |
| **字段可得时点** | stk_limit／limit_list_d／limit_list_ths **均为日频、收盘后可得** ⇒ **T+1 可判**，不必盘中 |
| **未来数据约束** | 用 D-1 及更早判 ⇒ 符合 E1。**若用当日 limit_list_d 判当日选股 = 前视**，须禁 |
| **缺失处理** | 表无该日 ⇒ 该日**不出件**并标 MISSING_LIMIT_DATA（fail-closed）；票不在表 ⇒ 判**未命中**（非缺失） |
| **用户待确认** | ①「命中」与「封板」是否同义？②以**收盘封住**为准，还是**盘中触及**即可？ |

### 2.2 封板

| 维度 | 内容 |
|---|---|
| **类别** | 新设计候选 ＋ **已有数据可直接判** |
| **可判条件（候选）** | **S-a**：close = stk_limit.up_limit（**精确价**，无推算误差）<br>**S-b**：limit_list_d.first_time 非空（首次封板时刻）＋ open_times=0（未开板）<br>**S-c**：limit_list_ths.status = 一字板（最强形态） |
| **字段可得时点** | up_limit 为**盘前已知**（stk_limit 日频）；first_time／open_times／last_time **收盘后** |
| **未来数据约束** | up_limit 可盘前用（不涉未来）；first_time 等为**收盘后统计** ⇒ **仅 T+1 可用**，不得用于当日盘中决策 |
| **缺失处理** | up_limit 为 NULL（实测 stk_limit sample 中 pre_close 为 None 的情形存在）⇒ 该票**跳过并计数**，**不默认按 10% 推算** |
| **用户待确认** | ③是否要求**收盘仍封**（open_times=0），还是**曾封即算**？④「一字板／T字板／换手板」三态是否都要区分？ |

### 2.3 炸板回封

| 维度 | 内容 |
|---|---|
| **类别** | 新设计候选 ＋ **已有数据可直接判** |
| **可判条件（候选）** | **Z-a**：limit_list_d.open_times > 0（当日开板过）<br>**Z-b**：open_times > 0 **且** last_time 非空／晚于 first_time（回封）<br>**Z-c**：limit_list_ths.first_ld_time／last_ld_time 非空（打开时刻链） |
| **字段可得时点** | 全部**收盘后** |
| **未来数据约束** | 仅 T+1 可用。**「回封」本质是日内事件，日频字段只能表达「是否发生过」，不能表达「回封发生在第几根 bar」** |
| **缺失处理** | open_times 为 NULL ⇒ 视为**未知**（不判为 0）；first_ld_time 缺失但 open_times>0 ⇒ 判「有炸板、回封时点未知」 |
| **用户待确认** | ⑤「回封」是否要求**当日收盘前完成**？⑥回封后是否要求**封至收盘**？⑦只需日频「是否炸板」，还是需**盘中时点**？ |

### 2.4 连板高度（height）

| 维度 | 内容 |
|---|---|
| **类别** | 新设计候选 ＋ **已有数据可直接判（最成熟）** |
| **可判条件（候选）** | **H-a**：limit_step.nums（**现成高度值**，2..11+）<br>**H-b**：limit_list_ths.tag 解析（首板／2天2板／3天3板…）<br>**H-c**：limit_list_d.limit_times<br>**H-d**：自算——向前回溯连续涨停日数 |
| **字段可得时点** | 日频，**T+1 可得** |
| **未来数据约束** | 回溯只用历史 ⇒ 无前视。注意「连续」定义：是否允许中间停牌／一字未开板 |
| **缺失处理** | limit_step 覆盖**仅 2023-11-13 起**（14,297 行）⇒ **早于此无表**，须回退 H-c／H-d 自算并**标注口径切换** |
| **用户待确认** | ⑧「连板高度」= **连续涨停天数** 还是 **N 日内涨停次数**？⑨是否要求中间**不破板**？⑩高度是否**含当日**（首板=1 还是 0）？ |

## 三、语义—契约—消费影响对照（我方侧初稿，待与节点8 合并）

| 术语 | 语义（候选） | 对契约的影响 | 对消费方（Rust Holding）的影响 |
|---|---|---|---|
| 命中 | 当日是否涨停（布尔，可选附时点） | 若仅布尔 ⇒ 可沿用 candidates:[str]，**装载链零改造** | **零改造** |
| 封板 | 涨停的**强度形态**（时间／开板次数） | 需子字段 ⇒ **破坏 candidates:[str]** | 需同步改反序列化 |
| 炸板回封 | **日内事件**，日频只能近似 | 需 open_times／first_ld_time 子字段 | 需同步改 |
| 连板高度 | 整数 | 可作**并行 heights:[int]**，或与 code 配对 | 需同步改 |

> **关键分歧点（我方立场）**：C4 件契约**应由信号语义决定**；「改不改 Rust」是**下游同步工作**，不构成对契约设计的约束。
> 若 G2 裁定信号只需**布尔命中**，则**契约可零改造**——大幅降低成本，**建议 G2 优先考虑「最小语义」路线**。

## 五、缺失处理通则（四术语共用）

| 情形 | 处置 |
|---|---|
| 目标表无该交易日 | **不出件** + 标 MISSING_<TABLE>_DATA，**fail-closed** |
| 单票字段为 NULL | **不臆造**（不默认按 10% 推算、不默认 open_times=0）⇒ 计入 skipped 并在件内留痕 |
| 表覆盖早于起点 | limit_step（2023-11-13 起）、limit_list_ths（2023-11-01 起）⇒ **回测窗早于 2023-11 须回退自算并标注口径切换** |
| 空结果 | **合法空态**（同 fb L174-183 口径）⇒ 出 candidates: []，不报错 |
