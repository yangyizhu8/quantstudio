## 2 候选识别规则（**统一 · R8 核心**）

### 2.1 三级优先级（**P1 > P2 > P3，识别阶段先于解析**）

| 级 | 判据（**可机检**） | 语义 | 处理 |
|---|---|---|---|
| **P1 合法 ID 条目** | front-matter `id` **存在且匹配**族 `id_pattern` | 确定是条目件 | **进 `checked`、进条目校验、参与查重**；**无论文件名如何都不得被 skip 隐藏**；命名问题**只附标签** |
| **P2 族特征候选** | basename **以族前缀开头**（如 `OPS-`，前缀可由 `id_pattern` 字面推导）但 **P1 不成立**（`id` 缺失/非法/解析不出） | "像是条目件但坏了" | **进 `checked`、产出可见错误**（桶 `empty`/`fail` ＋ 标签）；**不得 skip** |
| **P3 非条目文档** | **P1、P2 均不成立**（无有效 id、basename 无族前缀，如 `README.md`／`NOTES.md`） | 族说明文档等 | **按定义 skip**（`non-entry-file`），不进解析、不产生桶/标签 |

### 2.2 优先关系闭合（**回答 R8 的"缺ID候选与非条目skip优先关系未闭"**）

> **冲突消解规则**：**P1、P2 一律优先于 P3**。
> 任何满足 P1 或 P2 的文件**不得**因"文件名/内容不像条目"而被 skip；
> 只有 P3 才走 skip 分支。

**现状实测（2026-11-15，沙箱）**：现状**并无显式识别阶段**，靠族 `entry_glob` 路由隐式决定——

| 输入 | 紧 glob `OPS-*.md` | 宽 glob `*.md`（含 README） | 结论 |
|---|---|---|---|
| `README.md`（无族前缀、无 id） | **不在输入内**（total=2） | **`[skip] non-entry-file`**（total=3） | **P3 已按定义 skip**，且**与调用方 glob 宽窄无关**（族路由按 `entry_glob`） |
| `OPS-2026-9005.md`（族前缀、**缺 id**） | `checked` ＋ `bad=[id 非法…：None]` | 同左 | **P2 已有可见错误**（粒度粗：仅 1 条） |
| `OPS-2026-9006.md`（族前缀、**损坏 front-matter**） | `checked` ＋ `bad=[id 非法…；六字段全空]` | 同左 | **P2 已有可见错误** |
| `OPS-2026-9009 副本.md`（**合法 id**、错文件名） | `checked` ＋ **`bad=0`**、`notes=[]` | 同左 | **P1 静默＝唯一真缺口** |

⇒ **v5 的实质增量**＝把上述**隐式行为写成显式规则**，并补 P1 的可见性缺口；**不改** P2/P3 的既有处置方向。

## 3 方案（三面说明）

### 3.1 正交模型：**互斥计数桶 ＋ 可叠加诊断标签**

| 类别 | 取值 | 语义 | 互斥性 | 计数 |
|---|---|---|---|---|
| **互斥计数桶** | `ok` / `empty` / `fail` | `ok`＝解析出非空记录**且契约校验无错误**；`empty`＝解析空/残 **或** 契约字段为空/非法；`fail`＝解析**抛异常** | 每件恰一 | 构成 `checked` |
| **独立集合** | `skipped` | 未进入解析（P3 非条目文档、not_found、no_family_match、glob_no_match） | 与 `checked` 互斥 | 构成 `total` 另一部分 |
| **可叠加诊断标签** | `name_not_canonical` / `name_id_conflict` / `id_missing` / `parse_empty` / `field_empty` / `dup_id` | 附加诊断事实 | 可与任一桶共存 | **否** |

**桶由契约决定，不由 id 决定**：合法 `id` **只意味着进入条目校验**（P1），**不意味着桶归 `ok`**；任一契约字段为空/非法（含 `id` 缺失/非法）⇒ 桶 = `empty`（并按既有契约进 `bad`）。**文件名问题只附标签**，不改桶。

### 3.2 三条守恒式（不变）

```
(1) total   = checked + len(skipped)
(2) checked = ok + empty + fail
(3) total   = expanded + glob_misses
```
- **(1) 已被现有测试锁定**：`tests/test_kb_hook_skipped.py` **L81／L92／L131** ⇒ **不得破坏**。
- **标签不进入任何等式**。

### 3.3 payload（机读面）

新增三键（**既有键的值与语义不变**；标签在 `parse_detail[].tags`，不新增计数字段）：

```json
{
  "total": 6, "checked": 5, "bad": [], "skipped": [], "families_used": ["ops"], "note": null,
  "parse_stats": { "ok": 3, "empty": 2, "fail": 0 },
  "parse_detail": [
    {"file": "knowledge/ops/OPS-2026-9009 副本.md", "status": "ok",
     "tags": ["name_not_canonical"], "id": "OPS-2026-9009", "level": "P1"},
    {"file": "knowledge/ops/OPS-2026-9005.md", "status": "empty",
     "tags": ["id_missing"], "id": null, "level": "P2"}
  ],
  "skip_detail": [{"file": "knowledge/ops/README.md", "reason": "non-entry-file", "id": null, "level": "P3"}]
}
```

- `level` 字段记录**候选级**（P1/P2/P3）⇒ 逐件可追"为何被处理/被跳过"。
