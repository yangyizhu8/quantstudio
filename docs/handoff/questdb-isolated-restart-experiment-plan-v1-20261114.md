## 第 1 条 隔离边界（与生产绝对隔离）

| 维度 | 生产（**禁止触碰**） | 隔离实例（本方案对象） |
|---|---|---|
| 二进制 | `D:\questdb\questdb.exe`（v9.3.5，现役） | **独立副本** `D:\questdb\_iso_restart\questdb.exe`（从同一安装复制，版本同源） |
| 数据根 | `D:\questdb\quest_database` | **全新** `D:\questdb\_iso_restart\db`（空目录创建，**不复制生产数据**） |
| HTTP | `127.0.0.1:9000` | **`127.0.0.1:29000`** |
| PGWire | `5432`/`8812` | **`28812`** |
| ILP/TCP | `9009` | **`29009`** |
| 其他 | `9003` 等 | 一律 `29xxx` 段，逐项错开 |

**硬隔离规则**：
1. **端口不重叠**：`29xxx` 全段与生产 `9xxx/8812` 无交集；启动后必须实测「生产端口监听数不变」。
2. **数据根不共享**：隔离根为全新空目录；**不 mount、不 junction、不复制**生产 `quest_database`。
3. **配置独立**：隔离实例用**独立 `server.conf`**（`cairo.commit.mode` 等可安全改动，因为不涉生产），但**不得**从生产配置继承任何指向生产路径的项。
4. **禁连生产**：实验脚本内**不出现** `9000` / `5432` / `8812` / `9009` 任一生产端口字面量；执行前用静态检查证明。
5. **进程归属**：见第 4 条，PID 必须能证明是隔离实例而非生产。

## 第 2 条 故障注入清单（逐项，非「随便重启一下」）

**重要定性**：本实验只能证明**进程边界**与**正常重开边界**下的行为，
**不能**证明断电/文件系统缓存/磁盘控制器写缓存/虚拟化层回滚下的行为（见第 6 条限制）。

| ID | 注入 | 具体动作 | 想证什么 | 覆盖边界 |
|---|---|---|---|---|
| **I-1** | 优雅停止→重启 | `SIGTERM`/正常 stop，等待退出，重启 | 事务号在**正常重启**后是否延续且不复用 | 进程边界 |
| **I-2** | 强杀→重启 | 强杀进程（`Stop-Process -Force`），重启 | **非优雅**退出后 WAL 恢复与事务号关系 | 进程边界（非断电） |
| **I-3** | 表重建 | `DROP TABLE` + 重建同名表，观察事务号 | 事务号在**表生命周期重置**后是否复用 | 逻辑边界 |
| **I-4** | `TRUNCATE` | 清空表，观察事务号 | 清空是否重置事务号 | 逻辑边界 |
| **I-5** | 隔离实例整体冷启 | 停全部 → 从空数据根重建 → 重放测试写入 | 空库起点的事务号基线 | 进程边界 |
| **I-6**（**可选，需单独批准**） | 断电模拟 | **不在本方案范围** | — | **超界：不得做** |

> **I-6 明确不做**。R32 已指出进程重启不能证明断电不回滚；本方案**不尝试**用 I-1~I-5 冒充断电证据。

## 第 4 条 进程归属（防误杀/误连）

1. 启动时记录 `PID` + **完整命令行**（含 `-d <隔离数据根>` 与 conf 路径）；
2. 归属判据 = 命令行含**隔离数据根路径**，且 PID 的 `StartTime` 与本次启动一致；
3. **任何** `Stop-Process` 前必须：先打印候选清单 → 核命令行含隔离路径 → 排除自身 `$PID` → 再动手；
4. 生产 daemon（`quantstudio.pipeline.daemon`）**全程不触碰**；实验不启停任何生产进程。

## 第 5 条 验收判据（逐项 pass/fail，不合并）

| 项 | 判据 | 说明 |
|---|---|---|
| V-1 | 隔离实例可启动并响应查询 | 基础可用性 |
| V-2 | I-1 后 `sequencerTxn` 严格大于重启前的值 | 支持「正常重启不重置」 |
| V-3 | I-2 后 `writerTxn <= sequencerTxn` 且恢复后查询可用 | WAL 恢复可用性 |
| V-4 | I-3（DROP+重建）后事务号行为记录（**无论重置与否都记录**） | **关键是记录事实，不是强行判"不复用"** |
| V-5 | I-4 后事务号行为记录 | 同上 |
| V-6 | 全程生产端口监听数、生产数据根 mtime 未变 | 隔离性 |
| V-7 | 清理后 29xxx 端口全释放、隔离目录已删除 | 收尾 |

> **V-4/V-5 的定性**：若观测到**重建后事务号重置**，则 P2「不复用」在本实验下**被部分否证**——
> 这是合法结果，必须如实写入证据，**不得**为了通过 P2 而挑选性报告。

## 第 6 条 证据效力与限制（写死，防上推）

| 前提 | 本实验能提供的证据 | **不能**提供的 | 限制条款 |
|---|---|---|---|
| **P1 覆盖性** | 隔离实例上「经 WAL 的写入确实推进 sequencerTxn」的**单点演示** | 生产全部写路径的覆盖清单 | 覆盖性靠**代码枚举**，不靠本实验；本实验**不能替代** P1 |
| **P2 不复用** | 进程重启（I-1/I-2）、表重建/清空（I-3/I-4）边界下的观测 | **断电**、文件系统缓存丢失、磁盘/RAID 写缓存、虚拟化回滚 | **进程边界 ≠ 断电边界**；不得据此宣称「断电下不回滚」 |
| **P3 版本绑定** | **无** | 读接口的版本钉定能力 | 本实验**完全不涉及** P3；P3 需读接口本身支持版本切入点 |

> **结论性警示**：即使 I-1~I-5 全部按预期通过，**也只能说「进程/逻辑边界下观测到不复用」**，
> 并按 P2=partial 记账（见契约 v2 `verify_p2_non_reuse` 的 `covers_powerloss=False` 分支）。
> **不得**因本实验而把 P2 提到 verified，更不得据此判 consistent。

## 第 7 条 退出与清理边界

**退出条件（任一触发即停并上报）**：

1. 资源低于第 3 条门槛；
2. 端口冲突无法在 `29xxx` 段内解决；
3. 发现任何操作可能触及生产数据根或生产端口；
4. 实验产生**与预期相反**的结果（如事务号重置）——**停，记录，上报，不掩盖**；
5. 超出批准范围（如需要断电模拟）。

**清理（无论成败都必须完成）**：

| 步 | 动作 | 验收 |
|---|---|---|
| 1 | 停止隔离实例（按第 4 条归属核验后） | 进程消失 |
| 2 | 释放 29xxx 端口 | 实测监听数 0 |
| 3 | 删除 `D:\questdb\_iso_restart\` 全目录 | 路径不存在 |
| 4 | 复核生产未受影响 | 生产端口监听数、数据根 mtime、daemon PID 与实验前快照一致 |
| 5 | 落盘实验记录（含失败项） | 证据件入库 |

**清理不成功 ⇒ 按事故上报，不得以「反正是隔离的」放过。**
