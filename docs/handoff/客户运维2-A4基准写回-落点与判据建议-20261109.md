## 一、问题定义（客户侧现象）

客户 11-05 报告：`A4 熔断：etf_daily 检出 987 个 repair/full 窗口 > 阈值 20（stale last_sync 积压征兆）`，并担心「若这条熔断在某条路径上真会 skip，就会表现为当日 ETF 日线缺失」。

**已定谳的三件事（我域 11-05 代码级核实）**：

| # | 结论 | 依据 |
|---|---|---|
| 1 | **缺行不会造成跳过**——`last_sync` 为空时只打 INFO「A4 跳过检测」并 `return 0`，不熔断、不阻塞 | `daemon.py:3048-3052`（读 + 缺位分支） |
| 2 | **熔断不跳主增量**——`return -1` 发生在逐日循环之前，只跳「云端 repair/full 的局部逐日重拉」；且 `a4_verdict != 0 ⇒ 恒 skip=False` | `daemon.py:3069`（熔断判定）、`daemon.py:4325`（消费点） |
| 3 | **「缺位」与「熔断」互斥**——打出熔断必须先读到非空基准 ⇒ 客户看到「缺位」的那份库**不是采集实际写入的库**（本仓已知多库/配置目录陷阱） | 同上 1、2 |

**真正的病根**：**基准写回被「任务成败」绑架** —— 基准只在增量任务**完整成功**时才写；任务失败（写冲突/窗口 poison）就永不推进；且**写回异常被静默吞**（`except Exception: pass`）。

**我方本机实证（11-01~11-05）**：`etf_daily` 连续 5 天 FAILED ⇒ 基准冻结 ⇒ 11-04 夜间云端一次性批量 repair 被一次捕获 ⇒ 987 > 20。

**与既定设计的落差**：设计文档要求「增量主体成功（即使 A4 子项失败）即推进 last_sync 至本次同步水位」，实现是「整批成功才推进」⇒ **实现窄于设计**。

## 二、落点清单（按优先级）

### P0-1 基准写回与任务成败解耦（纯恢复型）

| 项 | 内容 |
|---|---|
| 落点① | `quantstudio/pipeline/daemon.py:1432-1433`（非流式路径：`from .update_detector import save_last_sync` / `save_last_sync(self.writer.shared_conn(), table)`） |
| 落点② | `quantstudio/pipeline/daemon.py:1681-1682`（流式路径 `_run_with_source_streaming`，同构） |
| 改法 | 把 `save_last_sync` 从「批次成功返回前」移到「**水位推进成功之后**」，且**不再依赖 A4 子段成败**（对齐设计意图） |
| 影响面 | 仅 `_a4_last_sync` 表一行/表；**不改**取数/校验/水位语义 |
| 判型 | **纯恢复型**（回到设计原态） |

### P0-2 写回异常不得静默（新增检测型）

| 项 | 内容 |
|---|---|
| 落点 | 同上两处的 `except Exception: pass`（紧邻 1433 / 1682 的 `try` 块） |
| 改法 | 改 `logger.warning`，含 `table` + 异常类型 + 摘要 |
| 判型 | **新增检测型**（开始报告真相，须与 P0-1 分开验收，不得混办） |

### P1 计数口径与可配（判断类，需单独声明影响面）

| 项 | 落点 | 改法 |
|---|---|---|
| 去重 | `daemon.py:3059-3062`（`repull_dates` 累加） | 按 `trade_date` **去重**后再计数（同一交易日多条 repair 只计 1） |
| 阈值可配 | `daemon.py:3032`（`_A4_MAX_WINDOWS = 20` 硬编码） | 新增 `QS_A4_MAX_WINDOWS`，**默认仍 20**（保持既有行为逐位不变） |

> ⚠️ 去重会**改变熔断触发阈值语义**（987 未去重 ≠ 987 交易日）⇒ 属**行为变更型**，须显式声明影响面、不可与 P0 混办。

### P2 缺位显式化 + 建表收口（纯增益）

| 项 | 落点 | 改法 |
|---|---|---|
| 缺位升告警 | `daemon.py:3052`（INFO「A4 跳过检测」） | 升 `WARNING`，文案写明「本表 repair 检测未启用」 |
| 建表收口 | `update_detector.py:65`（`ensure_last_sync_table`，现为懒执行，仅被 `load/save` 内部调用） | writer init 处无条件幂等调用一次；新增「表存在但某表无行」体检告警 |
