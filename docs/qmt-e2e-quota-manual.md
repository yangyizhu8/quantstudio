# QMT 端测配额手册（D-33 件 E，2026-10-16 落位）

- **性质**：QMT 侧端测**配额规则**＋**黄金 fixture 库**规则——把「每次改动全量真机端测」降为「按边界必测／其余以契约门替代」
- **裁定依据**：D-33 终裁②**照准**（必端测三边界＝新 API 面首用／新数据面接入／撮合口径变更；行为不变类＝契约门＋黄金 fixture）
- **时点纪律底座**：主库「端测纪律-QMT端测须盘后同窗同源黄金对照」——**判据取证须盘后（≥15:30）数据静止窗**，盘中跑仅算冒烟轮、不入判据

---

## 一、配额分级（三档）

| 档 | 触发条件（任一） | 要求 | 理由 |
| --- | --- | --- | --- |
| **A · 必端测**（真机） | ①**新 API 面首用**（wrapper 首次消费某 innerApi 能力）②**新数据面接入**（新表/新字段族进入取数链，如 `profit_ability` 修① 后首跑）③**撮合口径变更**（QMCH 系：撮合价/涨跌停/费用/滑点） | **盘后同窗**真机端测一轮，读判据行并归档 | 这三类的正确性**无法由本地契约门覆盖**（形态与引擎行为只在真机显形） |
| **B · 契约门替代** | 行为不变类：wrapper 内部重构／性能型／纯文档／审计行增删／预检脚本 | **不端测**；以「契约门＋黄金 fixture 比对」替代：邻接套件＋六策略重转 ALL PASS＋矩阵哈希＋黄金读数比对 | 可观察结果应逐位不变 ⇒ 本地门禁即可判定（与判据型「纯性能型/纯恢复型」对齐） |
| **C · 免测** | 纯知识库/台账/文档（如 D-33 件 A/B/C 本身） | 无 | 无运行面 |

**灰区判据（供 A/B 划界）**：改动是否可能改变**产物行为或真机读数**？会 ⇒ A；不会（仅内部实现/文档/审计）⇒ B。**拿不准按 A**（宁多测一轮，不放过形态坑）。

## 二、黄金 fixture 库规则

1. **归档对象**：A/B 对件（产物）＋两轮读数（审计行＋漏斗/指标）＋件指纹（sha16/sha256）＋窗口时点。
2. **归档位置**：`docs/evidence/<task>-pair-<YYYYMMDD>/`（对件＋`SHA256SUMS.txt`）＋读数并入对应 `*-e2e-run-*.md`。
3. **复用条件**：比对类判据（行为不变类）**可直接复用**既有黄金读数——须同窗（同日盘后）且件指纹一致；跨日复用须先证「无供应商推送」（L1/L2 与 HISTDBG3 六项读数逐位相同）。
4. **首批黄金（D-28 落位）**：`docs/evidence/d28-e2e-pair-20261015/`（A `9d00de2fc2d58d4a`／B `9d54605aeb83d556`）＋四轮读数（盘中×2＋盘后×2）见 `docs/evidence/d28-e2e-run-20261015.md`。
5. **失效**：wrapper 渲染常量（`_QMT_HASH_SCOPE`）变更 ⇒ 旧对件**作废**，须重出对件（对件是时点性产物）。

## 三、端测执行 SOP（用户侧）

1. 确认**盘后**（≥15:30）＋QMT 空闲＋两轮同区间同参数同设备；
2. 粘贴 A → 运行到底 → 回抄（审计行／`QS_QMT_PROGRESS` 处理段／14 项漏斗与指标）；
3. 粘贴 B → 同区间同参数 → 回抄；
4. 两轮间隔尽量短（先例 <17 min）；中间不跨供应商推送窗；
5. DSH 侧汇总判据＋归档＋台账（`qmt-pipeline-convergence.md` 回归门禁列引用）。

## 四、与收敛台账的挂钩

- 端测发现的**新缺陷** → 计 N_i；命中回哺载体清单的**复发** → 计 R_i（见 `docs/evidence/qmt-pipeline-convergence.md`）；
- 端测**读数归档**是台账「回归门禁结果」列的取证来源（如 batch3 行引用的四轮交叉一致）；
- 端测配额**不得**成为漏测借口：A 档未跑即视为该轮验收未完成（与「六步④验收」同强度）。
