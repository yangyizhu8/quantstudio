## 修法：两段式「快路径 + 慢路径兜底」（落点 duckdb_data_access.py `_query_bars_window_sql` 单函数）

- **快路径**：原 SQL 增加 `AND time >= ?`（下界 = before_ms − W_days×24h，W_days 写死见 C-6）；
- **慢路径兜底（C-2 硬命门）**：快路径结果中**返回行数 < count 的码**（长期停牌横跨下界/次新/退市/当日无 bar）⇒ 对该码子集**回退执行原无下界查询**补齐；
- **等价性证明**：原查询 = 每码全历史最近 count 根；新 = 窗口内最近 count 根，**不足码走原路径** ⇒ 每码结果恒等（快路径足 count 时其最近 count 根 ⊆ 窗口内；不足时结果=原路径结果）⇒ **结果集逐位相等**；
- **设计要点**：兜底存在 ⇒ **W 无正确性职责、只有性能职责**（hot case 覆盖率）——停牌等 pathological 码走慢路径（数量少、可接受）。

## C-1 W 确定方式 + 每码至少 count 根论证
**W_days = 430（唯一权威值，R-PERF-09 定值：ceil(260×1.6)+10=426 取整至 430，保守整数，余量 ~13%）**。count≤260（history 请求上限，QS_HISTORY_WINDOW 审计印证）⇒ 所需自然日 ≈ 260÷0.685 ≈ 380 < 430。快路径在此窗内覆盖「正常连续交易码」的 count 根（每交易日 1 根日线 ⇒ count 根需 count 交易日 ≤ W_days×0.685 恒成立）。**代码具名常量 `_WINDOW_SQL_FAST_PATH_DAYS = 430`，注释含公式与定值理由；验收含「常量 == 文档值 430」核对项。**

## C-2 兜底回退（硬命门）
如上：行数<count 的码集 → 原无下界 SQL 精确补齐（逐码路径不变）；**不存在任何「跳过/降级」**——数据完整性三条中的①可观测计数=慢路径触发次数打点（QS_DIAG event）②无需开关（零行为差）③验收证明不丢数据=对拍逐位。

## C-3 边界用例（实施轮固件）
长期停牌（横跨 W_days 下界）/ 次新（上市不足 count 根）/ 退市码（末日型 time 远早于下界）/ 当日无 bar（count 跨日取更早）——四类全部由 C-2 慢路径覆盖，断言与原查询逐位相等。

## C-4 EXPLAIN/扫描行数对比（实施轮产出承诺）
修前修后各取 EXPLAIN（或 `SET profiling`）对比扫描行数与耗时：预期快路径扫描量从「每码全历史（数千行）」降至「W_days 窗口内（≤count+ε 行）」；实测冷态耗时 28.6s→<1s（79 码）。
