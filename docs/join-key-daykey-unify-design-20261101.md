# 一、问题定义（同一根因的两个表现）

**根因：跨表/跨端的「口径」被各处本地各写一份，未归一。**

| # | 表现 | 实证 |
| --- | --- | --- |
| 1 | **联接键后缀不归一** | `stock_daily.code`＝`600556`（无后缀）；`trades.csv.code`＝`600556.SH`（带后缀）⇒ 2026-11-01 A5 联接 6/6 失败；同族历史：`.SS/.SZ` 致逐笔对比共同恒 0、`five` 判定恒假 |
| 2 | **日键各处自写** | 日键 `(time+28800000)//86400000`、UTC/CST 偏移、浮点除法（DuckDB `/` 非整除）多次引发假交易日/错位；2026-11-01 我第三次因本地另写而误判根因 |

**共同性质**：口径不归一时，**错误是静默的**——不报错、只给错结果（空集、错位、假零），因此极难在产出侧发现，必须在**写入侧统一 + 检测侧拦截**。

# 二、改动范围与落点（框架层，策略源码零改动）

| # | 落点 | 改动 |
| --- | --- | --- |
| 1 | `quantstudio/backtest/libs/`（现有约定模块） | 新增 `code_key(code)`：归一为 6 位裸码（去 `.SH/.SZ/.SS/.BJ` 等后缀；非法输入显式报错，禁静默返回原值） |
| 2 | 同上 | 新增 `day_key(ts_ms)` 与 `day_key_from_date(date_str)`：**唯一实现**，等价于 `(time + 28800000) // 86400000` |
| 3 | `scripts/check_key_normalization.py`（新） | 审计脚本：扫描仓库内「本地自写日键表达式」与「字符串直连 code 后缀」的模式，输出清单（BLOCK/WARN 分级） |
| 4 | `.githooks/pre-push`（可选，需评估） | 挂 WARN 级（先观察，不阻断） |

> 策略源码零改动（`output/generated_strategies/**`、`quantstudio/backtest/strategies/**` 不动）。

# 三、判据（三条）

| # | 判据 | 期望行为 |
| --- | --- | --- |
| ① | 任何跨表 code 联接 | **必须**经 `code_key()` 归一；出现「一侧带后缀一侧不带」即为缺陷 |
| ② | 任何日/交易日换算 | **必须**调 `day_key*`；禁在业务代码内出现 `86400000` / `28800000` 字面量 |
| ③ | 审计脚本 | 检出上述模式 ⇒ 输出文件:行 + 建议替换；新代码 BLOCK、存量 WARN |

# 四、影响面与纯增益判定（铁律 18）

- 型别：**新增检测型**（新增能力开始报告真相：口径缺陷从「静默」变「可检出」）。
- 不改变任何既有回测数值（只统一辅助函数 + 增扫描；既有调用点迁移属**纯恢复型**，须逐位一致）。
- **黄金结果逐位一致**为硬门。

# 五、验收标准

| # | 项 | 标准 |
| --- | --- | --- |
| 1 | `code_key` / `day_key*` 单测 | 含边界（非法后缀、空串、跨年日期、CST 零点前后） |
| 2 | 迁移后黄金一致 | 既有回测结果 sha256 与迁移前一致（至少 1 个日线 + 1 个分钟窗口） |
| 3 | 审计脚本 | 对存量代码报出**已知**历史坑点（含本次 A5 场景）；无误报验证 |
| 4 | 回归 | 既有测试全绿 |

# 六、回退条件

- 迁移引起任何数值漂移 ⇒ 立即回退迁移、仅保留新函数与审计脚本（原调用点不改）。
- 审计脚本误报率过高 ⇒ 降为纯报告（不挂 pre-push）。
- 验收不过 ⇒ 整体回退，不留半挂。

# 七、未决与风险

| # | 风险 | 处置 |
| --- | --- | --- |
| 1 | 存量调用点极多，一次性迁移风险高 | **分两步**：先出函数+审计（只读），再按目录分批迁移，每批黄金对比 |
| 2 | 部分模块的 code 形态来自外部（如 CSV 导出） | 归一在**入口**做一次，内部一律裸码 |
| 3 | 与 RC-001a（CLI 防护）同族（都是「让隐含状态可见」） | 建议 11-04 同批呈批，实施顺序 RC-001a 先（面小） |
