## 1. 三起事故的因果链（trae 归因，已核实）

### 事故 1：07-01 分钟因子污染（234 code adj=1.0）
- 07-01 ETL 进程死亡（巡检 10:27：老表+18 新 PID 39724 已死亡）→ 07-02 凌晨回填 `backfill_minutes_20260701.py` → `fetch_one()` 复权因子拉取失败时**静默降级 adj_factor=1.0**（价格未缩放）→ 1597 code / 384,877 行污染；
- 独立因子表 `etf_adj_factor` 干净（520810=1.0076/159909=9.792/515050=3.0/159220=2.0388）→ 污染来自**回填脚本降级分支**，非数据源；
- 巡检盲区：`check_etl_integrity.py` 维度 6 只查 stock_daily QFQ 边界、维度 9 只查分钟 bar 数 → **不查分钟表因子列连续性** → 07-01 因子=1.0 但 bar 数正常 → 巡检 PASS。

### 事故 2：08-14 本地 etf_daily 缺失（=0 code）
- 08-14 16:11 ETL 启动 → stock_daily 阶段 17:23~21:29（**耗时 4 小时**）→ 21:30 后日志无新内容 → **etf_daily 阶段未执行** → 22:01 巡检 FAIL（已过修复窗口）；
- **定性修正（v1.3）**：云端 08-11~13 实际有数据（审计工件为 08-11 前旧导出 → "云端缺 08-11~13"是审计误判）；**真缺口 = 08-14 本地源头缺 + 云端镜像缺**（同步读 since=08-13 → 0 rows）。

### 事故 3：08-15 同步崩溃（云端滞后 08-14）
- 08-15 03:00 增量同步 `ImportError: cannot import name 'QuestDBClient' from 'questdb'`（venv_miniQMT questdb 包只有 ingress）→ 同步静默中断 → 云端无 08-14。

### 根本性缺陷（为什么"反复"）

| # | 缺陷 | 后果 |
|---|---|---|
| D1 | 巡检盲区：QFQ 边界检查只覆盖 stock_daily；分钟表因子连续性/回填降级无检查 | 07-01 污染静默通过巡检 |
| D2 | 回填/修复脚本静默降级（`else: adj_factor=1.0`）无告警、无 repair_log | 污染无痕迹写入 |
| D3 | 巡检时机滞后（ETL 5.5h，巡检 22:00 才 FAIL，无修复窗口） | 当天缺口无法当天发现/修复 |
| D4 | 同步环境脆弱（QuestDBClient 依赖缺失静默中断） | 云端滞后无人感知 |
| D5 | 无"源头+镜像"联动校验（本地错→云端错，无双向对账告警） | 问题在本地复发即全链路污染 |

## 2. 修复分组（P0 机制防复发 + P1 存量修复）

### P0 机制修复（阻止复发，trae 侧）

| # | 内容 | 验收 |
|---|---|---|
| M1 | **巡检新增分钟表因子连续性检查**：`check_etl_integrity.py` 新增——每 code 每日 `etf_minutes`/`stock_minutes` 内嵌 adj_factor 与 `etf_adj_factor` 独立表**交叉比对**，不一致即 FAIL | 构造污染样例 → 巡检 FAIL；正常数据 PASS |
| M2 | **回填/修复脚本硬性约束**：复权因子缺失 → **报错中止**（禁止静默 `adj_factor=1.0`）+ 写 `local_repair_log` | 回填脚本缺因子场景 → 中止 + 告警（不写入） |
| M3 | **巡检提前 / ETL 提速**：表级写入进度检查提前（如 stock_daily 完成即触发部分巡检）或定位 stock_daily 4 小时根因缩短耗时 | 缺口在当日可发现/修复（修复窗口 ≥ 2h） |
| M4 | **同步任务健康检查**：同步失败（ImportError 等）→ 飞书告警；次日巡检纳入"**云端水位 vs 本地水位**"对账 | 同步失败当日告警；对账 FAIL 可检出 |
| M5 | **双向对账告警**（D5 收口）：本地 ↔ 云端逐表水位/计数对账进巡检 | 本地错 → 云端同步前拦截或告警 |

## 4. 实施边界（trae 执行约束）

1. 只改 QuestDB/ETL/巡检/同步脚本 + 云端同步；**不改 QuantStudio 代码**（mcp_adapter 线1 无需调整）；
2. 写操作前预告窗口（避免与 QuantStudio 生产 daemon 拉取冲突）；
3. 每步备份可回滚；不扩展范围（新问题只记录）；
4. M1-M5 机制修复先落地（防存量修复过程再次污染）；
5. 每 P 组完成自验 + 汇报；复审计报告落盘 `docs/evidence/cloud-source-repair-verification-20260817.md`。
