## 一、关键偏差 3 项（建议必须改写正文）

### P1 · 写目标：主库 → **包文件（package-first）**

| 项 | 内容 |
|---|---|
| 现状 | 方案通篇按「回填写主库 duckdb」叙述（§三 写面 / §六 时序 / §八 锁探测）|
| **实测** | 主库被研究进程（`run_r5.py`）与 `pytest` 持有 → duckdb 单写者=**排他**（任何持有者含只读都阻断 RW 打开）→ **回填根本无法启动**。实际改为 **package-first**：写独立包文件，**主库零写入零锁占用** |
| 影响 | 串行纪律（§八-3）**不再必要**；「必须排在阶段 2 之后」的前提消失 |
| **建议裁定** | **采纳**：v1.5 正文改为「写入目标 = 独立包文件 `quantstudio_data_package_<date>.db`」；主库 64 表补全（ATTACH 反向拷贝）降为**维护窗可选项**（已裁定另排）|

### P2 · 吞吐：46-69h → **1.86h**（提速 25×）

| 项 | 内容 |
|---|---|
| 现状 | §九 B1 订正为 728-1,093 行/s → 全史 **46-69h**；§六 原估 3-10h |
| **实测** | **chain 30 天/片：27,393 行/s；64 表 1.83 亿行 = 1.86h（6,681.7s）** |
| 根因 | 原基线取自**云链**（MCP export 分片端到端，含云端 job/落盘/流式/A4 gate）；本方案是**本地 PG wire 读 + 本地 duckdb 写**，无网络往返、无云端分片 |
| **建议裁定** | **采纳**：吞吐基线须**注明测量域**（云链 vs 本地 PG wire+duckdb）；本地域才是本方案真实成本。T1 读数口径（§12.5）同步补注 |

### P3 · 「质量等同云端」口径：逐位全等 → **同源同形 + 差异逐表声明**

| 项 | 内容 |
|---|---|
| 现状 | 用户裁定原文「质量等同云端」；§12.2 表述为「与 daemon 拉这些表一字不差」|
| **实测** | V2（B3 口径，64 表全覆盖）：**52 PASS / 5 DIFF / 7 EMPTY**。5 表 DIFF 均为**源侧既有差异**（本地漏行 / 文本转义 / 文本列），非回填缺陷 |
| 结论 | 若按**逐位全等**解释 → **不成立** |
| **建议裁定** | **采纳改写**为：「与云端**同源同形** = 62/64 逐行精确 + 5 表差异逐项归因 + 2 表实时 feed 时点差」，差异**随包 manifest 逐表声明**（已按此落地）|

## 二、修订建议 8 项（可操作，建议入 v1.5）

| # | 项 | 现状 | 建议裁定 |
|---|---|---|---|
| **P4** | §2.1「按 collector_tasks schema 做列映射/类型/单位校验/清洗」 | 与代码现实不符：`alignment_rules.json` 仅 **23** 契约 → 对 64 表 **0/64 覆盖**；`validator.validate` 首行 `schema = self.schemas[table]` → **必 KeyError** | 显式标注为「**不适用（B 类走 passthrough）**」，并引用该代码事实作为 v1.4 改判依据 |
| **P5** | §八-3 锁探测 | 仅覆盖「主库模式」 | 保留，但**升格说明 package-first 是消除该约束的架构解**（与 P1 配套）|
| **P6** | S4 契约扫描 | 仅第 1 步=表存在性 | 增列 **第 2 步=窗口基准列可用性校验**（非空计数 > 0 + 值域与窗口有交集）。实测 4 表基准列全 NULL → T2 首轮 **rows=0 静默空表** |
| **P7** | V2 对照域界定 | 界定正确（只验源忠实性）| 补两条实现口径：**排除本地生成元数据列**（`ingest_time`/`created_at`/`fetch_time` 等；实测 `index_classify` 伪差异，排除后 DIFF **23→6**）；**键不完整时改键无关多重集比对**（`etf_sentiment_daily` 键退化为 `[trade_date]` 致误判）|
| **P8** | 抽样代表性 | B3：64 表 ≥1 日期 + 高风险 ≥3 日期 | 补：高风险 3 日期应**跨批次边界**（最新+月末+季末），非仅取最新连续 3 日；**须显式声明抽样率**（云端 limit 硬上限 10,000 → `cyq_chips` 日均 55.8 万 = **≈1.8%**），其余行由 V4 兜底 |
| **P9** | 双重清洗语义（§12.2）| 称「B 类清洗已在 QuestDB 上游完成（ETL 终态）」 | **与实锤矛盾** → 改为「沿用上游 ETL 终态为**权威口径**；与云端差异属**已归因源侧差异**，不追求逐位全等」|
| **P10** | 磁盘硬前置（§三）| 仅估「+20~40GB」 | 改为**显式门槛**（如 ≥15% 且 ≥60 GB）并纳入 S1（当前 S1 无磁盘项）。实测：合并包 **38.65 GB**｜主库 35.31 GB｜D 盘余 310.9 GB |
| **P11** | V6 逐值口径 | 「逐位不变」| **必须区分业务字段与元数据列**（否则 upsert 后恒判失败）。精确化为「**指纹 = 业务字段 + 源标识列；排除 upsert 记账列**」+ 要求**算法口径复现校验**（B 任务已验证：三方逐位一致）|
