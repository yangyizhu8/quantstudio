## 一、问题定义

### 1.1 现象（已复现 ✓，2 次独立探针）

`get_history(codes, count=1, unit='1m', fields=['close','volume','time'], ...)` **批量 ≥16 只** 时，
返回的每个 code 帧中 **`close` 值为 NaN**（经 `_scalar` 转 `None`）；**`volume` 正常**；**item 全部存在**。

### 1.2 阈值梯度（实测 ✓，池内真实码）

| n | keys | close=None | volume=None | item=None |
| --- | --- | --- | --- | --- |
| 1 | 1 | 0 | 0 | 0 |
| 8 | 8 | 0 | 0 | 0 |
| **16** | 16 | **15** | 0 | 0 |
| 24 | 24 | 23 | 0 | 0 |
| 32 | 32 | 29 | 0 | 0 |
| 48 | 48 | 45 | 0 | 0 |
| 64 | 64 | 59 | 0 | 0 |

**阈值区间：8 < n ≤ 16**。⚠ 注意 n=16 时 15/16 为 None（非全灭）——存在 1 只正常，
提示**不是「整批换路径」，而是「逐码计算中某字段在批处理下退化」**。

### 1.3 下游后果（已确证 ✓）

1. 策略 `_load_auction_bars(held+pool)` 批量取竞价 bar → `close=None`
2. `_scalar(ai,'close',-1)` 返回 `None`（`np.isfinite(NaN)==False`）
3. `get_buy` L207 `if auction_close is None: continue` → **全部候选被淘汰**
4. 结果：**`selected=0 / buy_submitted=0`**（01-06 实测 ✓，尽管 7 条件全 PASS）

### 1.4 与聚宽差异的关系（诚实边界 ⚠）

- 本缺陷**能解释**「池够大却零买入」的日（如 01-06 池=64 ✗）✓
- 但**不能解释全部**：仅新版买入日（21 日）中含池=100/56/46 的大池日 ✗、漏买日含池=32/37 的小池日 ✗
- ⇒ **本缺陷是主因之一，不是唯一原因** ✓；两类占比须按交叉表重算（见 §六）

**定判：API 契约恢复型 + 数据修正型复合**（请②审定）

- **恢复型**部分：`close` 应恒为有效价（当前返回 NaN 属契约破损）⇒ 修复即回到契约原态
- **数据修正型**部分：修复后下游回测结果**必然变化**（买入日/成交/净值）⇒ 须显式声明影响面
- ⚠ 与「纯增益」的关系：**不是纯性能优化**（会改变可观察结果 ✗）⇒ 按**正确性修复**走六步，
  并行铁律「修复三型判定」中的数据修正型要求：**diff 只能归因于修正行集 + 准确度只升不降**

## 六、两类占比量化（影响面证据，部分完成 ⚠）

### 6.1 已知数据（聚宽真值 30 买入日 vs 新版 37 买入日，重合 16）

| 类别 | 日数 | 池规模分布（已知） | 与缺陷关系 |

| 仅新版（聚宽未买） | 21 | 20~100（含 20/22/35/37/39/40/42/46/56/100） | **不完全由池大解释** ✗（大池日亦触发但聚宽未买）⇒ 还有其他差异源 ⚠ |

### 6.2 待补（实施前）

- 逐日交叉表：`池规模 × (是否买入) × (聚宽是否买入) × (close=None 比例)`
- 判据：若「漏买 14 日」的 close=None 比例均 >0 ⇒ 缺陷解释成立；
  若「多买 21 日」中也有高 None 比例却仍买入 ⇒ 说明该日池实际被**分段**调用（held+pool 或分片）⚠ 须查证
