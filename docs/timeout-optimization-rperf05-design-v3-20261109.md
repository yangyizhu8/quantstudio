## 三、v3 修订：落点改到分钟 count 批量（`query_minute_bars_by_count_batch` L1436-1441）

### 3.1 修法

SQL 增加 `time >= ?` 下界（其余 SQL/列集/排序/分片/超时预算/表路由/三分类 freq 预检**一字不改**）：
```sql
SELECT * FROM (SELECT code, time, freq, open, ..., close_back FROM {table}
  WHERE freq = ? AND time >= ? AND time <= ? AND code IN (...)
  QUALIFY ROW_NUMBER() OVER (PARTITION BY code ORDER BY time DESC) <= {count})
ORDER BY code, time
```
**慢路径兜底（EC-1 集合差，语义同 v2）**：请求码集 − 结果码集（窗口内 0 根的码：停牌/次新/退市/当日无 bar）
∪ 结果行数 < count 的码 ⇒ 这些码用**原无下界 SQL** 重查并覆盖（慢路径权威）。

### 3.2 下界口径（分钟专属，替代 v2 的 430 自然日）

每日根密度 per_day = 240 / freq 分钟数（1min⇒240 / 5min⇒48 / 30min⇒8）；
下界天数 = **max(2, ceil(count / per_day) + 1)**；freq 未知时按最稀疏 30min（per_day=8）取保守值。
⇒ count=1 → 2 天；count=120 → 16 天；count=240 → 31 天。
**窗口内 ≥count 根 ⇒ 该码「最近 count 根」全在窗口内 ⇒ 与原查询逐位相同**；不足 ⇒ 慢路径兜底。
⇒ 正确性不依赖下界宽度（只依赖慢路径存在），下界只决定性能。

### 3.3 预期收益（扫描量口径）

count=1 的典型场景（竞价 bar）：103 码 × 2 天 × 240 根 ≈ **4.9 万行**（原 ~3,200 万行）⇒ **~65 倍扫描削减**；
30s 超时预算下应从「双超时 60s+」降到亚秒级。
**该预期为量级推算，须由 EXPLAIN + 实跑证**（实施轮产出，不得当结论报）。

### 3.4 判型与未验证范围

- 判型：**纯性能型**（结果集逐位相同；无跳过/无降级/无默认行为变化；开关默认无）；
- 未验证范围：R-8 两行定谳不变（选股层已证 / **提交层 buy_submitted 仍未验证**）——
  本次修复只改「取数是否扫全历史」，不改取数结果，故不提供提交层证据；
  若修复后提交层出现差异（因降级消失），须按铁律 18 复评判型。
