5. **意图表实测（111 行）**：superseded **99** / pending **9** / committed **3** ⇒ 清障机制工作正常（非堆积失控）；committed=3 证明 gate 偶尔能通过。

## 二、影响面（要件③ 成本量化）

**每轮**（每次 daemon 增量周期）对四价格表重复拉取「水位+1 → 今日」窗口：

| 表 | 每轮重拉窗口 | 直接实测依据 |
|---|---|---|
| etf_minutes | 2026-09-11 → 今日（≈23 天） | 本轮**全量**（2026-01-01→10-03，≈10 个月）**已耗 ≥5h10m 且仍在跑**（10-03 18:59 起）⇒ 23 天窗口约当其 8%，粗估 **≥25 分钟/轮**（估算非实测） |
| stock_minutes | 2026-09-05 → 今日（≈29 天） | 表 204,686,736 行；本轮尚未跑到，全量代价未观察（待测） |
| stock_daily | 2026-09-04 → 今日（≈30 天） | 日线量级小，成本低但同样每轮重复 |

⇒ **代价性质**：非一次性，而是每轮持续；且因周期反复中断，**长期无法自愈**（自愈前提是周期完整走到 finalize，而换代际即中断）。

## 三、根因（一句话）

**「中断即放弃水位推进、依赖下轮幂等重拉」的设计权衡，其代价对大表未量化，且与「daemon 频繁换代际」的真实运行模式叠加 ⇒ 水位长期不可提交，代价持续累积。**
（非崩溃类缺陷；属设计假设与运行现实不匹配 + 可观测性缺口）

## 四、改动范围（五子件，全部待审）

### W1｜意图提交/清障路径（要件①）——核心，含语义变更
**现状**：终结周期的 pending 意图一律 superseded（清障但不提交）。
**候选 A（呈审）**：新增**安全补提交**——对已终结周期遗留的 pending 意图，**当且仅当** `candidate_watermark ≤ 该表当前实际 MAX(time)` 时提交；否则维持 superseded。
- **安全论证**：水位语义 = 已拉取到该日期。若候选 ≤ 表内实际最大日期，则数据**确已入库** ⇒ 推进水位**不可能导致漏数据**；且 `daemon.py:2665 _get_safe_watermark` 已内置「水位领先实际则回退到 actual」保护。
- **风险/反例（须审）**：① candidate 若由部分写入产生则不完整 ⇒ 但以「表内实际 MAX」为硬上限即已覆盖；② **触碰 QFQ 语义不变式**（意图只经 gate 提交）⇒ 见 W4，须总调度裁定。
**候选 B（保守，不改不变式）**：不改提交路径，改为**周期自动恢复判据**——检测「连续 N 轮无 committed」或「pending 超阈/最老意图超时」⇒ 自动发起一次完整 finalize 周期（让 gate 走完）。

### W2｜周期中断韧性（要件②）
- 中断时**显式记录**「已产出候选 vs 已提交」差额（现 interrupted 已记 error 文本，但未量化水位损失）；
- 新增**积压告警**：pending 数 > 阈 或 最老 pending 时长 > 阈 ⇒ WARNING（当前**无任何告警**，故 29 天无人察觉）；
- 若采纳 W1-B：新增周期自动恢复触发与判据。

### W3｜幂等重拉成本量化（要件③）
方案内已量化（§2）；**实施项**：把「本轮重拉窗口天数 × 表行数」计入 cycle 报告/审计，使代价可见（当前仅自述安全，无成本数字）。

### W4｜QFQ 协调器语义不变式（要件④）
现有不变式（实施前后逐条断言）：
1. **水位不回退**（_get_safe_watermark 的 actual 回退是纠正领先，非回退数据边界）；
2. **意图只经 gate 提交**；← **W1-A 将修改此条**（改为 gate 提交 ∪ 安全补提交），**须显式呈裁**；
3. **中断幂等**（已 committed 单元保留、未提交 trigger 保持 pending、下轮清障重算）；
4. 世代审计列（source_generation/cutover_id）恒由 pre_cutover_generation 提供非 NULL 哨兵。
