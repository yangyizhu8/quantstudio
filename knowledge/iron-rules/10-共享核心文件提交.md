## 【铁律】共享核心文件提交纪律（2026-09-03 追加·多会话写前快照案例固化）

1. 涉及 `quantstudio/strategy_compiler/source_import.py`、`quantstudio/backtest/ptrade_api.py`、
   `quantstudio/backtest/backtest_engine.py` 等**共享核心文件**的改动，提交前必须：
   ① 按铁律「写前快照」四步配方建立零副作用回退点（`git add -A -- <本会话涉及路径>` →
      `git stash create -m` → `git stash store <hash>` → `git reset`；2026-10-14 定 scope 修订版——
      `create` 不接受 `-u`，未跟踪新建文件须先入暂存才被捕获）；
   ② `git status --porcelain` 核对待提交**精确文件清单**只含本会话改动；
   ③ **提交信息自查不含他人改动内容**（2026-09-03 事故：本会话 source_import 吸收规则
   改动被其他会话整体提交卷入 commit 0321364 推送，事后追认——禁止重演）。
2. 禁止 `git add -A` / `git add .` 全量提交共享工作区（他人未提交改动会一并卷入）；
   一律用精确文件清单 add。
3. 批提交/推送后必须核对**双远程 HEAD 逐位一致**（多 push URL 双仓库，2026-08-12 起）。
4. 涉及共享核心文件的代码先行会话，若检测到他人未提交改动叠加（git status 该文件已 M），
   须在提交信息与设计文档中显式记录叠加事实，不得静默带过。
5. **共享核心文件每次 edit 后必须即时 `git diff <file>` 自检**（2026-09-06 daemon.py
   通道声明注释被并行提交覆盖事故固化，本周期第 2 次——探针 v1 c9a20ab 吞没同族）：
   edit 返回成功 ≠ 改动仍在——并行会话的提交可能整体覆盖该文件使改动无声丢失；
   自检发现改动丢失 → 立即重落并按形态②（并行提交覆盖）记录事故。
6. **矩阵哈希追认同批纪律（2026-09-06 固化·本周期两次 CI 红后置教训）**：凡改动
   `quantstudio/strategy_compiler/source_import.py` 的 **wrapper 模板串内容**
   （`_QS_FUNDAMENTALS_EXT`/`_QS_ORDER_SPLIT_EXT`/`_QS_POSITION_VIEW_EXT` 等
   注入模板——任何会改变 wrapper 渲染内容的增删改），**同一 commit 内必须包含**
   `scripts/check_fund_matrix.py --check --reverify` 产出的矩阵 yaml/md 哈希更新
   （`docs/evidence/fundamentals-contract-matrix.{yaml,md}`）。
   - 机理：contract-gate CI（push main 触发）按矩阵 yaml 记录哈希比对 wrapper
     实际内容——哈希落后即 CI FAIL + GitHub 失败邮件（本周期两例：探针 v2 b33ba1f
     漏追、任务一 gap 上移 bf3ccba 漏追，均后置补 d828781）；
   - 操作：模板改动 commit 前 `python scripts/check_fund_matrix.py --check
     --reverify` → yaml/md 哈希同步 → 与代码同 commit 提交（禁止哈希追认后置单拆）；
   - 若 CI 已红：补 reverify + 单独 chore(matrix) commit 追认（如 d828781 先例），
     并在本条登记案例。
    - **QMT 侧同等适用（M5.2 件1，2026-10-12 扩展）**：凡改动
      `quantstudio/strategy_compiler/source_import_qmt.py` 的 **wrapper 渲染常量**
      （`_QMT_HASH_SCOPE` 清单 20 常量：12 个三引号模板 + 枚举/map——
      `_QS_QMT_FUNDAMENTALS_EXT`/`_QS_QMT_STOCK_INFO_EXT`/`_QS_QMT_FQ_MAP` 等），
      同一 commit 内必须包含 `--check --reverify` 产出的 `qmt_wrapper_hash` 更新
      （yaml `meta.qmt_wrapper_hash`，与 PTrade `wrapper_hash` 分立隔离防串）；
      未追认推送 → CI contract-gate FAIL。负向行为测试：
      `tests/test_fund_matrix_qmt_gate.py`（5 用例）。
