## 【铁律】策略生成与转换全链路修复：仅限框架层·纯增益·不遗留策略层

本铁律约束 QuantStudio 项目中「策略代码生成 skill → 本地回测策略 → 转换管线 → PTrade 策略」全链路上遇到的**所有阻断点或问题**的修复工作（含框架引擎、注入 API、数据访问层、数据源、策略生成 skill、转换管线、校验器、保真配置等通用框架层面）。**所需修复必须全部落实于通用框架层，禁止修改任何具体策略源码强行修复，且不得将问题遗留至具体策略层。**

1. **修复范围仅限框架层，策略源码零改动**：所有阻断点/问题的修复落点必须是框架引擎、API 函数、数据访问层、数据源管线、策略生成 skill、转换管线、校验器、保真配置等通用层面。**禁止**通过修改某个具体策略的选股逻辑、止损阈值、调仓节奏、仓位权重、代码路径来强行修复——具体策略源码（含 skill 生成的本地策略与转换产物）必须保持**零改动**；修复通过重新生成/重新转换（重转）产物生效。
2. **通用手段（不遗留策略层）**：框架层可通过注入/包装 API（如持仓视图归一、订单语义修复）、数据访问层容错（如撮合价窗口匹配）、转换管线模板与门控注入、保真开关（默认关）、审计行/诊断日志、参数链（CLI 旗标）等通用手段解决，禁止把问题下推给具体策略代码。
3. **通用性与鲁棒性**：修复必须具备通用性（多策略可覆盖，不得只对单一策略生效）与鲁棒性；若某修复只对单一策略生效而无法覆盖其他策略，说明落点不是通用框架层。
4. **纯增益修复**：修复必须为纯增益——不得引入新问题、不得破坏现有正常功能、不得出现「修一送一」。验收必须证明修复前后既有功能零衰减（相关测试套件 + 既有功能回归全绿）。
5. **通用性验收（多策略横验证）**：涉及策略产物时以多策略横验证为验收门槛——6 策略（CANSLIM / fall_reversal / tech_etf_mvo_rotation / vol_regime_mom_rev / weekly_smallcap_growth / 周频小市值成长动量（三层止损））重转 api_portability 全 PASS + 相关测试套件全绿 + 既有功能回归全绿。
6. **改动层级判定**：判定修复层面的标准——(a) 改动文件是否为框架模块（引擎/数据访问/管线/校验器/模板/skill），(b) 策略 `.py` 文件是否被编辑（禁止），(c) 修复是否通过重转/引擎容错/保真开关生效（而非改策略）。
7. **配套纪律（六步流水线协同）**：框架修复同样必须走 方案→审计→实施→验收→用户确认→双仓库推送；与「框架层改动六步流水线」协同执行；与「性能优化不得改变引擎行为」界定一致（正确性修复不等于性能优化）；与「框架问题立即解决」衔接（发现阻断点默认立即推进修复，禁止以登记挂账替代）；与「策略生成默认通过 skill 开发，仅本地 QuantStudio」衔接（skill 产出本地代码、转换管线承接 PTrade，全链路的阻断点修复即本铁律范围）。
8. **例外与登记**：确需策略层配合的场景（如未来经用户批准修改策略模板/新策略生成标准）必须显式立项、走六步流水线、并在引用文档更新后由用户确认——禁止默认以策略层改动作修复手段。
9. 本铁律长期有效，**跨会话、跨项目、跨智能体（dsh/CodeBuddy/workbuddy/ZCode 等）必须共同遵守**，除非用户明确要求修改或撤销。

> 用户原话要求：QuantStudio 项目中策略代码生成 skill 生成本地回测策略、以及转换管线转换为 PTrade 策略时遇到的所有阻断点或问题，所需修复必须全部落实于通用框架层（框架引擎/数据访问层/转换管线/校验器/保真配置/策略生成 skill）；禁止修改任何具体策略源码强行修复；修复须具备通用性与鲁棒性、须为纯增益（不引入新问题、不破坏现有正常功能、不修一送一）；修复完成必须执行六步流水线协同；作为跨会话和项目必须遵守的铁律。
