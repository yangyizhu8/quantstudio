## 【铁律】客户仓库交付密钥对标准流程（quantstudio-plus 只读分发，2026-09-06 用户确立）

### 适用范围
向客户分发 GitHub 私有仓库 https://github.com/yangyizhu8/quantstudio-plus 的只读拉取权限（新客户开通/密钥生成/交付/撤销），
跨会话、跨项目、跨智能体（dsh/CodeBuddy/workbuddy/ZCode 等）共同遵守。

### 标准流程（每客户一套，互不影响；采用方案 A 零配置）
1. **生成密钥对**（每客户独立，禁止复用/共享）：
   `ssh-keygen -q -t ed25519 -N "" -f "D:\miniQMT策略实盘\私募工作文件\客户密钥对\<客户名>\id_ed25519" -C "<客户名>"`
   - 私钥统一命名 `id_ed25519`（无任何后缀），公钥为同目录 `id_ed25519.pub`；
   - key comment（-C）与目录名均使用客户名（如 Jun、邓老师）；
   - 落坑记录（2026-09-06 立档；2026-09-19 审核修订）：本机 pwsh 对原生命令传空参 `-N ''` 会被丢弃、
     致 `Too many arguments`；**主径为 `-N '""'`（pwsh 直跑；2026-09-19 实测：生成 + 空口令校验双 PASS）**，
     `cmd /c "... -N \"\" ..."` 包装降为 dsh 备选（⚠ Trae 等工具链安全门禁会硬拦 `cmd /c` 字样，勿在该类环境用）；Git Bash 下 `-N ''` 正常。
2. **公钥加入仓库**（用户人工执行）：GitHub → yangyizhu8/quantstudio-plus → Settings → Deploy keys →
   Add deploy key，**必须勾选 Read-only**。
3. **交付客户**：私钥 `id_ed25519` + 随附《客户使用说明.md》（方案 A 零配置）：
   ① 进入 `C:\Users\<用户名>\`，新建 `.ssh` 文件夹（已有则跳过）；
   ② 私钥放入 `.ssh`（保持文件名 `id_ed25519`，提醒客户开启「文件扩展名」显示防止变成 id_ed25519.txt）；
   ③ 打开 Git Bash 直接 `git clone git@github.com:yangyizhu8/quantstudio-plus.git`（首次连接提示指纹输 yes）。
4. **撤销权限**：仓库 Settings → Deploy keys 删除对应 key，秒级生效，无需客户配合。
5. **安全红线**：目录 `客户密钥对\<客户名>\` 即该客户交付档案（私钥+公钥+说明）；
   禁止把私钥提交进任何 git 仓库；禁止在聊天中输出私钥内容；禁止交付可写 deploy key。
6. 迁移与远端切换（quantstudio-plus 与 quantstudio-trading 合并时执行）：两私有仓合并执行时，须一并处置老客户的本地远端——对已 clone quantstudio-plus 的客户出具更新通知，明确「换远端／重新 pull」的操作步骤与验证清单（通知格式沿用本铁律第 4 条与《客户长期运维》⑤）；deploy key 的延续或重建按本铁律第 4 条评估后决定；未完成远端切换的客户，其本地副本将停在合并前状态（须在通知中明示）。

> 用户原话要求（2026-09-06）：客户拉取方案 A 落地流程作为铁律写入跨会话、项目、跨智能体的记忆，
> 长期有效，除非用户明确要求修改或撤销。
