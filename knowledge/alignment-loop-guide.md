# 对齐闭环管线指导文件（Alignment Loop Guide）

> 性质：双端对齐工作的**常态化总指导**（用户裁定 2026-10-06 建库时确立）。
> 目标：终结「新策略→新差异→点状修复→再新差异」的循环怪圈，实现**注册表驱动的单调收敛**。

## 一、怪圈根因（为什么之前不收敛）

1. 验证被动：用例=新策略自然序列（demand-driven），非覆盖矩阵（coverage-driven）；
2. 修复点状：修一字段不排同类（whack-a-mole）；
3. 黄金自洽：本地黄金由本地引擎生成，口径错则黄金跟着错，本地测试永远绿；
4. 无洞账本：对齐面基数未知 → 不可度量 → 不可收敛；
5. 显现贴线：口径差存在 ≠ 行为差显现（需现价落入双口径判定异号窄带）。

## 二、五设计闭环（本指导的核心）

```
注册表(账本) → 探针矩阵(主动踩面) → 双端diff → 三态仲裁 → 框架修复(六步) 
    ↑                                              ↓
    ←←← 类例放大(修一洞·排一类·立一墙) ←←← 契约测试固化(平台实证黄金)
                                    用户平台日志例行回灌 ↗
```

### 设计 1 · 对齐面注册表 = 洞的总账本
[registry.md](registry.md)。对齐面**有限枚举**（~100-150 条：POS 18/API/撮合/生命周期/费用/数据/指标）。
条目四态：`已锚定(平台证据+契约测试) / 已排查(无分歧) / 未验证 / 已知分歧(修复中)`。
**收敛度量 = 未验证数单调下降**。

### 设计 2 · 契约测试金字塔 + 黄金分级
黄金权威三级：**平台实证黄金 > 平台文档契约 > 本地自产黄金（仅防回归）**。
每个已锚定条目必有契约测试，黄金值取平台实证（例：cost_basis 摊薄 0.973 系列）。

### 设计 3 · 探针策略矩阵（主动踩面）
[probes/README.md](probes/README.md)。专门设计的探针策略系统性消费每类面，双端跑逐笔 diff。
**新策略放行门禁前移：探针矩阵 diff=0 方可出管线**。

### 设计 4 · 修复类例放大纪律（治点状）
每个洞修复强制三步：
①**同类排查**（修 POS-01 cost_basis 必查全部 POS 条目）；
②**账本更新**（本条→已锚定，同类→已排查/已知分歧）；
③**契约测试固化**（平台实证黄金）。
一句话：**修一个洞，排一类洞，立一道墙**——每个洞一生只出现一次。

### 设计 5 · 平台日志回灌 + 差异三态仲裁
用户人工跑平台回测 → 日志归档 → 例行 diff。差异三态：
**可归因（锚定契约边界）→ 修 ｜ 不可归因 → 深挖 ｜ 平台自身问题 → 登记豁免**。
SOP 见 [playbooks/diff-triage.md](playbooks/diff-triage.md)。禁止修完就忘。

## 三、与六步流水线的衔接（对齐修复专用条款）

| 六步 | 对齐工作附加义务 |
|---|---|
| ①方案 | 方案件**必须引用 registry 条目编号**（如"本件修 POS-01"）；同类排查结论随方案呈审 |
| ②审计 | 审计方核对方案是否完成类例排查 + registry 状态引用 |
| ③实施 | 写前快照；改动封闭于框架层（策略源码零改动） |
| ④验收 | 验收 = V 判据全过 **+ 契约测试固化 + registry/contracts/playbook 同步落档**（knowledge 落档是验收的一部分，不做不算验收完成） |
| ⑤确认 | 汇报附 registry 前后状态 diff（修了几条、升了几级） |
| ⑥推送 | knowledge/ 随代码同 commit 推送双仓；同步门照常 |

## 四、收敛判据（诚实版）

- ✅ 可承诺：发现从"用户撞上"变"探针扫出"；每洞一生一次；账本可见收敛；新策略门禁前置；
- ❌ 不承诺"永无新洞"：平台升级/新 API/极端边界仍可能出新——但新差异必落入新边界条目，
  账本有限增长且增速递减；
- **收敛标志**：registry 全条目 = 已锚定/已排查 ⇒ 新策略双端 diff 预期为零。

## 五、铁律条文（跨会话/跨智能体/跨项目）

1. registry 为唯一洞账本，状态实时更新，禁止陈旧；
2. 新策略双端验证前先过探针矩阵，diff=0 放行；
3. 任何对齐修复强制类例放大三步（同类排查+账本更新+契约固化）；
4. 关键口径字段黄金必须平台实证锚定，本地黄金仅防回归；
5. 平台回测日志例行归档 diff，差异三态仲裁入账本；
6. 每轮修复的方案/证据件必须引用 registry 条目编号；
7. knowledge/ 为双端对齐唯一知识库，六步④验收时同步落档，接手必读其 README。
