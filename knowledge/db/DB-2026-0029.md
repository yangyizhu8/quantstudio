## 复现步骤

1. 准备提交范围：`origin/main..HEAD` 含 N 笔，其中第 k 笔由**他线**在某次授权**之后**新增；
2. 按授权清单（N-1 笔）锚定推送——或按旧习惯 `git push origin main:main`；
3. 把范围外那笔写进 `QS_PUSH_BUNDLE_ALLOWALSO`（"我已全量声明"）；
4. 观察闸门行为：**exit 0 放行** —— 声明只要自洽就能通过，**没有任何一环比对"该声明是否被授权"**。

**最小判定句**：只要能自行撰写声明就放行 ⇒ 命中本条。

## 影响面

| 维度 | 影响 |
|---|---|
| 触发频率 | 多会话共享工作区下**高**——他线随时可能在授权后提交 |
| 危害 | 未授权代码/文档进入远端主分支；若该笔后来被判定有问题，回滚需要重写历史或 revert，代价远高于"停手申报" |
| 隐蔽性 | **极高**——执行方会觉得"我已经全量申报了，很规范"；申报面规范掩盖了动作面违规（本案即此形态） |
| 正解成本 | 极低——锚定授权末笔推送（`git push origin <tip>:main`）本可两全 |

## 讨论

**为什么闸门天然防不住**：C7 的设计目标是**防漏声明**（`declared ⊇ range`），而遗漏的失败模式是
**超授权**（`range ⊄ authorized`）。两者是**不同方向的子集关系**，前者无法推出后者。
声明由执行方自填 ⇒ 执行方同时是"被校验者"和"校验输入提供者" ⇒ **自审自批**。

**修法要点**：引入**授权方产出的独立物证**（快照 JSON，含 `tip` + `commits`），执行方只读。
判据两行：`rangeEnd` 以 `snapshot.tip` 开头 ⇒ 通过（锚定推送结构上不可能超范围）；
否则范围内存在 ∉ `commits` 的笔 ⇒ exit 9 并给出正确命令。

## 补段：首次实战即抓到自己缺陷（2026-11-05 · 总调度点名入册）

**背景**：本条目对应的闸门在 2026-11-05 15:3x **首次真实推送**中上线启用，当轮即暴露自身缺陷。

### 事故链（完整时序）

| 步 | 事件 | 判定 |
|---|---|---|
| 1 | 总调度按新规落快照 `20261105-1530-rulingA.json`（UTF-8 无 BOM，tip=8a6de2d，9 笔） | 合规 |
| 2 | 执行方锚定推送 `git push origin 8a6de2d:main` | 合规 |
| 3 | 闸报 **`拒绝推送：授权快照不可解析（授权证据物损坏 ⇒ 停）`** | **fail-closed 方向正确** |
| 4 | 复核：Python 以 `utf-8` 读同一文件**完全正常**（tip + 9 笔 commits 齐全） | ⇒ **闸误判** |
| 5 | 定位：PS 5.1 `Get-Content -Raw` **默认按系统 ANSI 码页（GBK）解码** ⇒ 中文字段（`authorized_by`/`note`）转乱码 ⇒ `ConvertFrom-Json` 失败 | 根因确认 |
| 6 | 修复：`-Encoding UTF8` 显式解码 + 报错文案补落盘规范提示 | commit `1c60b3b` |
| 7 | 重推 ⇒ **exit 0**，四端逐位一致 `8a6de2d` | 闭环 |

### 三点值得沉淀

1. **fail-closed 方向正确 ≠ 实现正确**：闸把"完好快照"判成"损坏"是**假阴性**。
   方向选对只保证"不放过坏输入"，不保证"不误拒好输入"——两者要分别验证。
2. **同族判据（跨案件复用）**：凡"读外部文件后做 JSON/结构化解析"的代码，在 Windows 上
   都要问一句「**默认码页是什么**」。PS 5.1 `Get-Content` 默认 ANSI、PS 7 默认 UTF-8；
   Node `fs.readFileSync(path,'utf8')` 明确；Python `open(..., encoding=)` 必须显式。
   ⇒ **显式优于默认**，尤其在会被不同解释器执行的脚本里。
3. **"修复即刻生效"的路径依赖**：`core.hooksPath = .githooks` ⇒ pre-push 跑**本地工作树**脚本
   ⇒ 闸的修复不必先推送就能生效。**理解执行载体（本地/远端）决定了修复的生效路径**。

> **对"新机制上线"的通用教训**：新闸门/新校验的**首次真实执行**必须视为**独立验证点**
> （不是"上线即完成"）——本案正是首次执行就抓到缺陷。建议新机制上线时，
> 首次真实使用**预留排查时间**，并把"首次实战记录"作为验收件的一部分。
