### D1（2026-11-10 · 判据）按代码推断行为，**必须读到关键分支出处**，不能只看调用点

**事由（我方两次误判，均在同一轮内被自己推翻）**：

| 序 | 我方判定 | 推翻方式 | 真实原因 |
|---|---|---|---|
| 1 | 「`portfolio.cash` 是总现金，不是可用资金」 | ②审 zcode 指出 + 我方查 Context7 逐字：「Current available funds」 | 未先查平台文档语义就按实跑读数反推 |
| 2 | 「**G1（P0）**：`order_value` 卖出会经 `_qs_cash_budget` ⇒ fail-closed 返 0 ⇒ **阻断卖出**」 | 我方预研读 `_qs_split_order` **首行**：`if … or value <= 0: return [], 0` ⇒ 卖出压根不进拆单/预算链路 | 只看了 `order_value` 的**调用点**（L1485）与 `if not orders:` 分支，**没读被调函数的首个 return 条件** |

**判据（可复用）**：

1. 凡断言「A 会因 B 而被阻断/钳制/跳过」时，**必须沿调用链读到被调函数的第一个决定分支**（首行 return / 首个 if），而不是停在调用点；
2. 特别地，**早退（early-return）与哨兵值（`<=0`、`None`、`[]`）是第一优先级审查对象**——它们往往使后续全部逻辑对其输入类别不生效；
3. 断言「会阻断」之前，先写出**该输入类别在链路首个分支出处的结果**（本例：`value=-3200 → _qs_split_order 返回 [] → 走 value_orig → 卖出正常`）；
4. 定性分级（P0/P1/P2）**须在 1–3 完成之后**再给——本次先给了 P0「安全底线」，读码后降为 P2「告警噪声」，属**定级早于取证**；
5. 反向教训：zcode 给的原则（「零预算只阻断买入、不阻断卖出」）**本身正确**，我方将其**过度解读为「必须改码」**——原则→实现的映射仍需读码落实。

**落点**：本条同时适用于 PD 族其他条目的事故归因；与「桩/沙箱验证必须带依赖直读自检」同族（都是「**观测点选错导致假结论**」）。

### D3（2026-11-12 · 框架约束）`_QS_*_EXT` 模板串**禁止花括号字面量**

**事由**：甲-order 第一步实现时用 dict 字面量 `info = {'applied': ...}` 存入 `_QS_ORDER_SPLIT_EXT`，
而该模板经 `.format(marker="")` 渲染 ⇒ 花括号被当作格式占位符 ⇒
`KeyError: "'applied'"`，**同一提交内 18 个测试失败**。

**约束**：
1. `_QS_ORDER_SPLIT_EXT` / `_QS_FUNDAMENTALS_EXT` / `_QS_INDUSTRY_EXT` 等**凡经 `.format()` 渲染的模板串**，
   内部代码**禁止出现单花括号**（dict/set 字面量、f-string、装饰器参数等）；需要结构化返回时**改用 tuple/list**。
2. 若确需花括号，必须写成 `{{` / `}}` 转义——但**不推荐**（可读性差、后续维护易漏）。
3. **改模板串后必做 `.format(marker="")` 冒烟**（一条命令即可），否则要到跑测试才发现。

**自检命令**：`python -c "import quantstudio.strategy_compiler.source_import as si; si._QS_ORDER_SPLIT_EXT.format(marker='')"`

### D4（2026-11-12 · 框架约束）`_QS_ISO_` 是**保留命名空间**

**事由**：同上轮，我给 B2 计数器起名 `_QS_ISO_UNARMED_COUNT`（放在**非隔离通用**代码里）⇒
`P4_equiv` FAIL：*「ISO 命名空间被源策略占用（检出 `_QS_ISO_UNARMED_COUNT` 但无 `_QS_ISO_ENABLED` 开关）
——按保留命名空间约定应改用其他名，未静默剔除」*。

**约束**：
1. `_QS_ISO_` 前缀**专属隔离层**（`isolation_template.py` 的 HEAD/TAIL 注入块）；非隔离通用代码
   （第一跳 `source_import.py` 的通用注入块）一律**不得使用**该前缀。
2. 通用侧需要同类计数器时用 `_QS_CLAMP_` / `_QS_CASH_` / `_QS_LEDGER_` 等语义前缀
   （本轮最终命名：`_QS_CLAMP_UNARMED_COUNT`）。
3. 日志码同理：通用侧不要写 `QS_ISO_*`，用 `QS_CLAMP_ORDER*` 等。
4. **该检查是 equiv 的 fail-loud 能力，不是误报**——它正是为了阻止「隔离命名混入非隔离产物」。

### D5（2026-11-12 · 平台约束＋验收纪律）变量持函数引用后调用必被白名单拦；旧产物 PASS 是假绿

**A. 平台约束（第二次踩，2026-08-22 已实证）**

`_QSOrderRefState` 的 docstring 就写着：「class 属性承载——平台静态白名单识别 class 语句，
**变量持函数引用后调用会被 LOCAL-API-WHITELIST BLOCK**」。本次 a-2/B3 实现仍写成：

```python
_get_avail = globals().get('_qs_iso_cash_avail'); _get_avail()   # ← [BLOCK] calls unknown API
_iso_fill  = globals().get('_qs_iso_record_fill'); _iso_fill()   # ← 同上
```

⇒ 补转产物出现 2 条 `[BLOCK] LOCAL-API-WHITELIST`，`api_portability=BLOCKED`。

**硬动作**：
1. 凡「可能需要但静态不存在」的函数（隔离层函数、可选注入 API），一律用 **class 属性承载**：
   `class _QSClampHooks: iso_avail = None` → 调用侧 `if _QSClampHooks.iso_avail is not None: _QSClampHooks.iso_avail()`。
2. **禁止** `globals().get('name')` 取函数后调用；`globals().get()` **只可用于取布尔/标量**
   （如 `_QS_ISO_ENABLED`，它不构成调用面，不会被拦）。
3. 新增同类挂载点时，**先想「平台能不能静态看到这个名字的调用」**，而不是「Python 能不能跑到」。

**B. 验收纪律：旧产物 PASS 是假绿**

机制：`source_import.py` 是共享模板，改动后**旧产物不含新代码** ⇒ 校验仍然 PASS ⇒
若据此宣称「回归通过」，等于**用旧代码的绿灯为新代码作证**。

**硬动作**：
1. 任何改 `source_import.py` / `transformer.py` / 模板串的批次，**验收必须重转产物**，
   不得引用既有 `output/ptrade_export/**` 的历史 PASS。
2. 重转后以 `run_card.json` 的 `validation.api_portability` 为唯一判据（并区分
   `PARTIAL`（`--no-smoke` 跳过回测 ≠ 失败）与 `BLOCKED`）。
3. **BLOCK 条数与 WARN 条数分开统计**——`PORTABILITY-DYNAMIC-CALL` 属 WARN 嫌疑提示，
   不是 BLOCK（本轮实测 4 条 WARN 存在时 `ok=True` 正确）。
