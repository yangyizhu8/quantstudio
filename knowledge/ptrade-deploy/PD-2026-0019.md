## 现象

PD-0018 修复批（commit 39d325d，改 `guards_template.py` 与 `source_import.py`）落地后，按常规跑「三策略重转」：

```
python -m quantstudio.strategy_compiler.cli deploy output/.qs-deploy-quick/<id>.yaml
⇒ ETF_f926a7 / F-Score_RSRS_149655 / strat_0c202b 三策略 P0..P6 全 PASS，EXIT=0
```

但核验交付产物：`_qs_idempotent_admit`、`QS_CASH_BUDGET`、`_qs_report_acceptance`、`QS_SPLIT_MISS`、
`_QS_SPLIT_DEPTH`、`_qs_check_order_state` **六项全缺**，`_qs_reserve_cash` 出现 **0 处** ⇒ 本批修复一个字都没进产物。

## 根因

| 项 | 读数 |
|---|---|
| 第一跳产物 mtime | `output/ptrade_export/…/<name>_ptrade.py` = **11-03 09:23** |
| `source_import.py` mtime | **11-06 22:14**（本批修改） |
| deploy.yaml `source:` | 指向上述**过期**第一跳产物 |
| 第二跳做了什么 | 只把 GUARD/PERSIST/MOUNT 重新注入旧产物 |

⇒ 产物比源码旧 3 天 = **假重转**。P0–P6 全 PASS 只证明「第二跳渲染正确」，不证明「底材新鲜」。

## 判别与闸门

- **判据**：deploy.yaml 的 `source` 文件 mtime < 第一跳源文件 mtime ⇒ 产物必然不含第一跳改动；
- **闸门**：`IMPORT-FRESHNESS` 挂 deploy **P0 之前**（fail-closed），不新鲜即拒绝部署并提示重跑 import；
- **时序自证**：产物写入生成时刻戳（或核验产物 mtime > 第一跳源文件 mtime），证明是真重转；
- **镜像关系**：本条目（生产面）与 PD-2026-0018（固件面，`test_two_hop_fixture_policy.py`）
  是**同一盲区的两个面**——一个拦「测试漏检第一跳」，一个拦「生产用了旧料」。

## 讨论节

- **与 PD-2026-0018 的分工**：0018 是「固件只测第二跳 ⇒ 测不到」；0019 是「重转只跑第二跳 ⇒ 转不到」。
  两者根因同源（两跳链路未在工具层被显式表达），但危害面不同：前者漏检，后者**产出看似全新、内核陈旧**，
  且 P0–P6 全绿 ⇒ 最难被表面读数发现。
- **假信号教训（本轮自曝）**：首轮把「第一跳产物体积」与「交付产物体积」混为一谈，
  误报「F-Score 体积减少 20,835 B」⇒ 实为**两类产物口径混用**。更正后实测：第一跳 +13,913 B、
  交付 +10,480 B，三策略**逐位相同** ⇒ 策略无关的固定增量，无内容删除。
  **判据**：体积比对必须先声明「比的是哪一类产物」，且同类相比。
