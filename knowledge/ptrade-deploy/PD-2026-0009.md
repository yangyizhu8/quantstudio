## 现象与判定

- 现象：`read_vault()` 实测仅返回 PD-2026-0006/0007/0008 三条；0001..0005 缺席，`warnings` 为空。
- 判定：**纯恢复型**缺陷——回哺链路「形式上存在、实质上失效」，且无任何可见信号（最危险的一类：
  比直接报错更隐蔽，会让「已回哺」成为假的安心）。

## 关键证据（2026-10-20）

| 项 | 值 |
|---|---|
| BOM 实测 | 0001..0005 首 3 字节 = 239,187,191（EF BB BF）；0006..0008 = 45,45,45（`---`） |
| 解析口径 | `_parse_frontmatter`: `if not lines or lines[0].strip() != "---": return {}` |
| Python 行为 | `'\ufeff'.isspace()` 为 False → `strip()` 不去 BOM → 判非 frontmatter |
| 修复后 | entries=8；ids 连续 0001..0008；degraded=False；warnings=[] |

## 回哺触发点（防复发）

1. **写 vault 条目一律用 UTF-8 无 BOM**（本仓工具链：PowerShell 的 `Out-File -Encoding utf8`
   在 PS 5.1 下会写 BOM；用 .NET `UTF8Encoding($false)` 或 Python `encoding='utf-8'`）。
2. **同类「静默跳过」审计**：任何按「首行/起始标记」起判的解析器，都要问「标记带 BOM/空白时
   会怎样」；没有告警的 `continue` 是断链温床。
3. 与 `PD-2026-0008`（P5 误报）同源：都是**口径与真实数据形态不一致**导致的静默偏差——
   一个表现为噪音，一个表现为沉默。
