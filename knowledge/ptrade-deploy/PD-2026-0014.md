## 复现步骤

1. 打开 PyQt「转模拟盘/实盘」页（快捷模式或高级模式）；
2. 执行一次转换（转换成功）；
3. 观察：页面只有「一键转换 / 开始转换」与只读报告区，**无「打开输出目录」入口**——
   产物目录需手工开资源管理器逐级定位 `Demo_account_Real_account/<策略名>/`。

## 影响面

- 纯使用体验缺口（不影响转换正确性）；产物路径已在报告区以 `[artifact:product]` 文本给出，
  但需手工复制→定位，两步操作；
- 参考先例存在：「导出 PTrade」页已有同名按钮（`ptrade_export_tab.py:201`），本页缺失属功能不对等。

## 讨论

- **移植而非新造**：逐条对齐参考实现三态（无目录 `InfoBar.info` / 目录不存在 `InfoBar.error` /
  `os.startfile` + `OSError` 反馈），保持两页交互一致；
- **目录来源零内核改动**：内核 `artifacts["product"]` 已给绝对路径，GUI 只取 `.parent`；
  失败链（P6 SKIPPED）无 artifacts ⇒ 不更新缓存 ⇒ 按钮走「无输出目录」提示；
- **双端对等条款不适用**（②审照准）：本功能为 GUI 壳便利动作（打开资源管理器），
  无 CLI 等价工件、不影响产物 SHA —— 铁律第 3 条反例；
- **测试环境坑（已沉淀）**：qfluentwidgets 的 QConfig 是 QObject 单例，
  QApplication 必须**模块级持有**，否则 app 回收后 C++ 侧悬空 → 后续 Qt 用例
  `RuntimeError: wrapped C/C++ object of type QConfig has been deleted`
  （与 `tests/test_deploy_gui.py` 同一坑，已对齐其写法）。
