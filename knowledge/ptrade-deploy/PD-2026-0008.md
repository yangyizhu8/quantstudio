## 现象与判定

- 现象：`history.keys()`（history 为函数参数）、`ch.isdigit()`（ch 为 for 目标）在 P5 门禁被列为
  「契约表外 API，需人工确认」——`unknown_apis` 只是警告（不影响 PASS/FAIL），但污染报告噪音，
  且会让人工确认面失真。
- 判定：**纯恢复型修复**（警告集合收窄，verdict 不变）。属于「门禁噪音域」，不属转换正确性域。

## 关键证据（2026-10-20）

| 项 | 值 |
|---|---|
| 根因链 | `call_name(X.m()) == "X"` → `X ∉ {契约表, BUILTIN, 模块豁免, local_names}` → 报 |
| 旧绑定面缺口 | 参数 / for 目标 / with as / except 名 / walrus / 推导式 / 解包（7 类） |
| 修复后 | 负例 6 类全不报；正例 3 类照报（含「本地函数豁免但另一未知仍抓」的不过宽锁定） |
| 套件 | deploy 73/73（49 既有 + 9 P5 + 15 快捷模式） |

## 回哺触发点

- 后续新增门禁规则时：先问「被判定对象的**绑定可达性**」（
  `knowleage_base/11-方法论与工程体系/审计方法论-先证可达性…`）——误报多源于只核敏感性未证可达性；
- 新增平台 API 白名单时：`ENGINE_GLOBALS` 与 `MODULE_NAME_EXEMPTIONS` 是两个不同口径
  （引擎提供 vs import 引入），勿混用。
