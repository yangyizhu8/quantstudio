# 诊断剧本 · 差异三态仲裁总纲（Diff Triage Playbook）

> 每次双端 diff 的标准处置流程。配合 [../registry.md](../registry.md) 与 [../alignment-loop-guide.md](../alignment-loop-guide.md)。

## 0. 前提纪律

- **根因未证实不得修**（AGENTS.md 框架问题立即解决铁律 §3）：现象可被多种解释覆盖时，先最小复现/插桩取证；
- 先查知识库：症状命中既有 playbook → 直接按类剧本走（如 [cost-basis-class.md](cost-basis-class.md)）；
- 证据链要求：双端**同基准同区间**先确认（基准一致 ⇒ 排除数据源分歧，聚焦引擎行为）。

## 1. 定位首笔分歧（第一分歧点法）

1. 双端交易/委托序列逐笔对齐比对（方向/标的/数量/价格）；
2. 找到**首个不一致笔**——此后所有分歧都是它的下游（机械结果），不要在下游浪费分析；
3. 若前段完全一致：分歧必在「触发条件」层（成本口径/阈值/风控状态机/生命周期时点），而非数据或调仓逻辑。

## 2. 反推触发链

首笔分歧日 → 该日策略决策的输入是什么（价格/成本/持仓字段/状态变量）→ 逐项双端对账
（平台日志盘后行 vs 本地 daily_stats/trades）→ 找到**判定异号的输入变量**（如成本 0.973 vs 1.0455）。

## 3. 三态仲裁

| 态 | 判据 | 处置 |
|---|---|---|
| **可归因** | 落在既有锚定契约的边界条件内（如本已锚定口径的新场景） | 直接修（六步流水线）；playbook 类剧本更新边界场景 |
| **不可归因** | 无既有契约可解释 | 深挖：按本文 §1-2 全链取证 → 实证根因 → 立**新**契约条目（registry 增条 + contracts 建档 + 契约测试固化）→ 类例放大排查 |
| **平台自身问题** | 平台日志/行为自相矛盾或文档明确但实现不符 | 登记**豁免**（registry 条目注明豁免依据），不修本地去迎合 |

## 4. 修复后固化（不可跳过）

1. registry 条目状态翻转（已知分歧→已锚定）+ contracts 建档（含平台实证黄金序列）；
2. 契约测试落盘（黄金值 = 平台实证，不是本地自产）；
3. 类例放大：同类条目全排查（修一洞·排一类·立一墙）；
4. 六步④验收 = 判据全过 + 上述 1-3 完成；
5. archive-index 登记本案例。

## 5. 常见根因速查（按历史频率）

1. **字段口径差**（cost_basis 类）——隐性强，显现靠贴线，优先排查；
2. 生命周期时点（盘后/盘前/盘中执行序）；
3. 数据边界（include/复权日/停牌）；
4. 费用/滑点默认值；
5. 状态机分叉（风控锁定/恢复条件）。
