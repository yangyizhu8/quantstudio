# 平台文档库 · 写入规则 · **v1.0**

> **性质**：本库的准入与写入规则（harness 层）。任何会话、任何智能体写入本库前先读本文件。
> **上位约束**：不覆盖本项目 `AGENTS.md` 铁律、`docs/migration-ledger.md`、`review-kb/harness/write-rules.md` 与主库（`knowleage_base`）的协议与纪律。

---

## 一、目录职责

| 目录／文件 | 职责 | 准入 |
| --- | --- | --- |
| `index.md` | MOC 入口（平台分域清单） | 入库 |
| `README.md` | 本库定位 ＋ **来源与许可声明** ＋ 元数据约定 | 入库（**改动须走沿革**） |
| `标签索引.md` | 受控词表 → 文档反查 | 入库 |
| `harness/` | 写入规则（本文件） | 入库 |
| `<平台>/` | 该平台正文（`tdx/` `qmt/` `ptrade/`） | 入库 |
| `<平台>/_meta/` | 抓取清单 ＋ 源 URL 对照 | 入库 |
| `_notes/` | 人工批注（与原文分离） | 入库 |
| `platform-docs/.obsidian/` | Obsidian 本地配置 | **不入库**（`.gitignore`） |

## 二、谁可写（写入主体）

| 主体 | 可写范围 | 前置条件 |
| --- | --- | --- |
| **抓取脚本（批次入库）** | `<平台>/**` ＋ `<平台>/_meta/**` | 抓取前先读本文件；**必须产出三标记**（抓取时点／源 URL／版本线索） |
| dsh（人工会话） | 全部 | 遵守本节三、四 |
| 用户 | 全部 | — |
| 其他会话／智能体 | 仅 `<平台>/**` 新增 ＋ `_meta/**` 登记 | **须先读本文件**；不得改 `README.md`／`harness/` |

## 三、必写（缺项即视为不合格）

1. **每页 frontmatter**：`title`／`source_url`／`crawled_at`／`platform`／`tags`（tags 须与 `标签索引.md` 双向一致）；
2. **正文与原文一致**：不改写、不删减、不"优化"；**如与实测不一致须标注** `状态/已知偏差` 并在页内写明差异；
3. **代码块原样保留**（含缩进与注释）——不得重排或补全；
4. **不可得即写不可得**：站点存在但未抓到者，在 `_meta/sources.md` 逐条列出原因，**禁止留白**；
5. **落库后更新** `标签索引.md` 与 `<平台>/index.md`（分域 MOC）。

## 四、禁写（红线，违反即撤稿）

1. **改写／摘要化原文**——本库是**快照**，不是二次创作；
2. **把项目结论写进本库**——结论属 `knowledge/`／`review-kb/`；
3. **任何凭据**（token／密钥／账号明文）；
4. **把平台文档当契约**——**不得**据本库直接下"接口就是如此"的结论；契约须以**运行实测**为准；
5. **入库到公开仓**——本库**只随私有 VIP 仓分发**（见 `README.md` 分发红线）；
6. **擅自改 `README.md`／`harness/`**（须走沿革 ＋ 用户确认）。

## 五、长度上限

| 类型 | 上限 |
| --- | --- |
| 单页正文 | 与原文一致（**不因长度截断**）；超长页按原页结构原样保存 |
| `<平台>/index.md` | ≤ 300 行（分域清单，不搬正文） |
| `_meta/sources.md` | 无上限（逐页对照表） |

## 六、与状态快照／台账的分工

| 平台文档事实 | **本库** |
| 项目结论与复盘 | `knowledge/`／`review-kb/` |
